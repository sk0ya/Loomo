# §39 ターミナルサポート（ターミナルの中身を、別の見せ方で）

> 作成日: 2026-10-19 / 状態: **第1段実装済み**（Claude Code の会話を読み物に・TUI の操作キー・シェルのコマンド一覧）。
> 関連する正本: 袖の活動（タイトルの印・承認待ち）は §24.1.1、タブの様子の表（前面のコマンド・場所）は §24.53、
> コマンドの出力の置き場は §24.21、Claude Code の記録・フック・セッションは §38、記録の読み方は §37.2.1、
> Markdown のページ（テーマ・mermaid・アウトライン・本文差し替え）は EditorSupport のもの（§24.8・メモリの
> markdown-preview-incremental）。

## §39.1 目的と位置——情報を足すのではなく、見せ方を変える

エディタには EditorSupport がある。その価値は**新しい情報ではない**——中身はエディタにあるテキストそのもので、
.md をプレビューに、.csv を表に、.html をページに、**同じ中身を別の形で見せる**。

ターミナルにはそれが無かった。ターミナルの見せ方は「1本の文字列が時系列に流れていく」だけで、表は崩れ、
コードは素の文字、図は描かれず、過去は遡るしかない。ターミナルサポートは EditorSupport と同じ型で、
**前に出ているターミナルのタブに追従し、そこで流れた中身を、ターミナルにはできない形で見せ直す**。
拡張子の代わりに**前面のプログラム**で見せ方（提供者）を選ぶ。

> **やり直しの記録（2026-10-19）。** 第1版の Claude の面は、記録から取れるもの（頼みごと・書き換えたファイル・
> 最近の操作・操作キー・状態）を並べた。並べ方を「ターン単位・知りたい順」に組み直しても良くならなかった。
> 理由は二つ：(1)「何が嬉しいか」を決めずに「何が取れるか」から作った。(2) 調べると、状態・実行中の操作・
> 変更の差分（`/diff`）・離れていた間の要約（`/recap`）・並行セッションの一覧（エージェント一覧）・コンテキスト量
> （ステータスライン）は **Claude Code 自身がもっと良い形で出している**——横に並べ直しても劣化コピーにしかならない。
> 残る価値は「同じ中身の見せ方を変える」ことだけで、それが EditorSupport の価値でもあった。

`PaneKind.TerminalSupport`（末尾に追加）。ドックの既定は**右**（EditorSupport と同じ、本文の脇に添える面）。
既定キーは無い（`pane.terminalSupport`「ターミナルサポートを開く」）——脇に出しておく面で、呼びに行く起点ではない。

## §39.2 追従元と見せ方の決め方

追従元は `_activeTerminalTab`。その様子を `TerminalSupportSubject`（タブ・場所・前面のコマンドと開始時刻・
Claude の状態）に組み立てて渡す。**新しく見張るものは無い**——材料はすべて既存の表から読む。

- 前面のコマンド・場所：タブの様子の表（§24.53 `TerminalStatusOf`。OSC 133 の C〜D／A）
- Claude の状態：袖の活動（§24.1.1 `PaneActivityTracker.AgentTabs`。タイトルの印＋フック）
- 実行し終えたコマンド：出力の置き場（§24.21 `TerminalCommandOutputs`）

見せ方（`TerminalSupportMode`）は次の順に決める。

1. **Claude Code**：Claude の印が出ている、または前面のコマンドが `claude`。**Claude を先に見る**——Claude は
   C を出したまま居座るので「動いているプログラム」でもあるが、見たいのはコマンド行ではなく会話の中身。
   常駐の復元直後のように C が来ないまま印だけ分かる場合（§38.7）もこれで拾える。
2. **プログラム**：シェル以外が前面に居る（C を見て D 未着）。TUI もそうでないものも。
3. **シェル**：プロンプトで待っている。

引き直しは合図をまとめて 1 回（`RequestTerminalSupportRefresh`、Background 優先度）。合図はタブの切り替え・
袖のバッジの更新（Claude の状態・コマンドの始まりと終わり）・SessionStart・出力の切り出し・タブの様子の変化。
**ペインが見えていないときは何もしない**——見えた瞬間（`IsVisibleChanged`）に追いつく。

## §39.3 プログラム（TUI）

コマンド行・経過時間（§24.53 の 1 秒時計に乗る）・そして**知っているプログラムなら操作キー**を出す。
表は `TerminalProgramCatalog`（EditorSupport の拡張子→提供者の表にあたる）。

- 引き方：先頭の語の実行ファイル名（拡張子・パスを外す。pwsh の呼び出し演算子 `& '…\claude.exe'` も外す）。
  `dotnet watch` は 2 語で見る。**REPL（python・node）は引数なしのときだけ**——`python build.py` はスクリプトの実行で、
  REPL の案内は的外れ。
- **載せるキーは確かめたものだけ**。TUI のキーは版で変わり、間違った案内は案内が無いより悪い（押して別のことが
  起きる）。知らないプログラムはコマンド行と経過時間だけ。
- 第1段の顔ぶれ：Vim 系・less・lazygit・htop・ssh・Python／Node.js の REPL・dotnet watch。Claude Code の行も表に
  あるが（見分けに使う）、Claude の面には出さない——キーの案内は Claude Code 自身が出している。

## §39.4 Claude Code——会話を読み物として

ターミナルの Claude の返事は流れていく文字で、表は罫線の文字に崩れ、コードは素の文字、mermaid は描かれず、
前の返事は遡って探すしかない。同じ会話を **Markdown として描き直した1本の文書**にする。

- **頼みごとを見出し（h2）に**、その下に Claude の**返事を Markdown として描画**する。表は表に、コードは色付きに、
  mermaid は図になる。返事の中の見出しは**2 段下げる**（`#`→`###`、`ClaudeConversationDocument.DemoteHeadings`。
  コードブロックの中は触らない）ので、ページの**アウトライン欄が「頼みごと → 返事の節」の会話の目次**になる——
  ターミナルには無い「前のあの説明」へ一押しで戻る道。
- ターンの最後の本文が返事。**それより前の本文（作業の途中のメモ）は「途中のメモ N 件」に畳む**。作業中は最後の
  本文も途中なので「Claude · 作業中」と添える。
- 見出しの下に1行だけ、そのターンで**変えたファイル**（押すとエディタで開くリンク）・ワークスペースの外の数・
  コマンド回数・失敗数。ここは読み物の脇注で、主役は返事。
- 頭の帯は1行：自分の番か（承認待ち・あなたの番は強調色）・題（Claude がタイトルに出している具体的な題、無ければ
  記録の `ai-title`）・コンテキスト量とターン数・「記録」（jsonl を開く）。セッションを確かめられないときはその理由。
- **開いたときは最新のターンの頭**を出す。最新のターンを読んでいる最中に新しいターンが始まったら、その頭へ付いていく
  ——古いターンを読み返しているときは動かさない（ページの本文差し替えの「末尾に居れば末尾に付いていく」とは別に、
  ターンの頭で止める）。
- 本文のリンクは EditorSupport のプレビューと同じ振り分け（URL＝ブラウザ、ファイル＝エディタ）。相対パスは
  **Claude が動いている場所（タブの cwd）**から解く。

### §39.4.1 描き方

- ページは EditorSupport と同じ `MarkdownPage`（テーマは Markdown プレビューの設定・mermaid・アウトライン）、
  WebView2 と一時ページの道具も同じもの（`IEditorSupportViewFactory`・`EditorSupportNavigationService`、ページは
  `preview-claude-<pid>.html`）。Diff の Markdown 描画（§24.10）と同じく、XAML から生えて DI が届かないペインなので
  ShellWindow が道具を渡す。
- **ページを組むのはテーマが変わったときだけ**。会話が書き足されるたびの更新は**本文の差し替え**（`setBody`）。
  ターンごとに1つの `section` にしてあるので、ページの差し替えは変わったターンだけを入れ替える——読み返している
  古いターンの DOM もスクロール位置も触らない。
- 本文（全ターンの Markdown 描画）は**裏のスレッドで組む**。作業中は数秒おきに来るので、世代番号で古い結果を捨てる。
- **見えていないうちは WebView を作らない**（Claude の居ないタブ・隠れたペインで Chromium を起こさない）。

### §39.4.2 記録の決め方と読み方

- **タブのセッションは確かめてから出す。推量はしない。** 記録は SessionStart のフック（§38.4）で結び付いたものを
  使う（タブ ID 付きで届くので確定）。フックの無いタブ（未設定・設定前に起動した claude・常駐の繋ぎ直し）は、
  **動いている claude のプロセスから確かめる**（`ClaudeLiveSessions`）。Claude Code は起動中のプロセスごとに
  `~/.claude/sessions/<pid>.json`（いまのセッション ID・場所・開始時刻。`/clear` で書き換わる）を書くので、そのうち
  1. **この Loomo の端末の中**で動いている——親をたどると Pty.Host（常駐の端末）か Loomo 自身（常駐でない端末）に
     行き着く（Toolhelp のプロセス一覧。PID の再利用に備えて深さの上限と輪の検出つき）、
  2. 場所（cwd）がタブと同じ、
  3. ほかのタブにフックで結び付いていない、
  ものだけを候補にする。1つなら確定、複数ならタブで `claude` を打った時刻（OSC 133 の C）とセッションの開始時刻が
  15 秒以内のもの。**それでも決まらなければ何も描かず理由を出す**——別の会話を出すより、出さないほうがよい。
  記録は `projects/<slug(cwd)>/<sessionId>.jsonl`。
  - 第1版は「タブの場所の記録フォルダーでいちばん新しい記録」を当て推量していた。同じフォルダーで Loomo の外
    （Windows Terminal など）でも claude を回していると、**そちらの会話を Loomo のタブのものとして出していた**
    （2026-10-19 に実機で発生。指摘を受けて撤去）。
  - タブのシェルの PID が分かれば一段確実になるが、Terminal ライブラリは ConPTY の子の PID を外へ出していない
    （`ConPtySession.ProcessId` は internal）。出すには Terminal と Pty.Host の通信の改修が要る——§39.8。
- 読み方は**ハーネスペインと同じもの**（`ClaudeTranscriptParser`＝ツール呼び出し・頼みごと・料金、
  `ClaudeSessionCatalog.Summarize`＝題・コンテキスト量）。読み方を二つ持つと、片方だけ記録の形の変化に追従して
  食い違う。ここで足すのは返事の本文（assistant の text ブロック。思考とツール呼び出しは含めない）だけ。
- **ターンの区切り**は頼みごとの記録の位置（`HarnessRun.PromptMarks`）。本体の操作は行番号で、サブエージェントの
  操作（別ファイル）は時刻で振り分ける。**作業の途中に足した指示**は user の行にならず `queued_command` の添付
  （`attachment.type = "queued_command"`）として残るので、パーサーはこれも頼みごとに数える（ハーネスの頼みごとの
  数も正しくなる）。ターンは新しい 20 個まで（`MaxTurns`）。
- **変えたファイル**は Edit・MultiEdit・Write・NotebookEdit が成功したもの（`Read`・拒否・失敗は入れない）。
  ワークスペースの外（Claude の一時ファイル・作業メモ）は数だけ（`workspace.Contains`、マルチルート）。
- **いつ読むか**：追従元・状態が変わったとき（ターンの終わり・承認待ち・SessionStart・タブの切り替え）と、
  **作業中だけ 4 秒おき**（`TerminalSupportClaudeInterval`。ペインが見えている間だけ回る）。長さと更新時刻が前回と
  同じなら開きもしない。読むのは裏のスレッドで、読んでいる間にタブが替わったら結果を捨てる（世代番号）。

## §39.5 シェル

前面に何も居ないときは、**このタブで実行し終えたコマンド**（§24.21 の置き場のうち、このタブのもの）を
✓／✗ 終了コード・経過つきで並べる。押すと出力をエディタで開き、右クリックで「前回の出力と比べる」
（前回を持っているときだけ）・「プロンプトへ入れる」（Enter は送らない、§24.3。複数行はコンポーザへ）。
出力は永続化しない（§24.21 の注記のまま。再起動で消える）。

WebView2 で描いて画面から撮って確かめた。

## §39.7 実測

記録 9MB（ツール 245 回）の `ClaudeSessionDigest.Read` が 120〜150ms（初回 335ms、Release、Ryzen 5 3500）。
作業中 4 秒おきなら 1 コアの数 % で、読むのは裏のスレッド。ただし**記録の長さに比例**し、1 回あたり ~20MB を
確保して捨てる——長いセッションでは効いてくる。§39.8 の 1 つめ。

## §39.8 既知の穴と次の段

- **差分読み**：いまは変わるたびに全体を読み直し、全ターンを描き直す。前回の読み終わり位置から追記分だけ読む形に
  すれば、記録の長さに依らなくなる（ツール呼び出しと結果の対応・usage の重複除去を跨いで持ち越す必要がある）。
- **サブエージェント**の記録（`<session>/subagents/*.jsonl`）はまだ読んでいない（振り分けの仕組みはある）。
- **タブのシェルの PID**：Terminal ライブラリが ConPTY の子の PID を公開し、Pty.Host がタブごとに返せば、
  「そのタブのシェルの子孫の claude」で確定でき、同じ場所で複数動いていても打った時刻に頼らずに済む（§39.4.2）。
- 返事の見出しの id はターンをまたいで重なりうる（同じ題の節が二つのターンにあると、アウトラインの飛び先が先の方になる）。
- アウトライン欄は狭いペインでは幅を取る。
- **同じ原理をほかの出力へ**：表形式の出力（`Get-Process`・CSV）→ 表のグリッド（VGrid）、JSON → 折りたためるツリー、
  `git log --graph` → 枝の図、テスト／ビルドの出力 → 成否のツリーと file:line の一覧（§31.17 の problem matcher）。
  提供者を前面のプログラム・出力の形で選ぶ骨組み（§39.2）はそのまま使える。
- コマンドの出力の置き場はコマンド行ごとに 2 回分なので、別のタブで同じコマンドを打つと、こちらのタブの一覧からは
  消える（§24.21 の置き場の形のまま）。
