## §39.1 目的と位置——情報を足すのではなく、見せ方を変える

エディタには EditorSupport がある。その価値は**新しい情報ではない**——中身はエディタにあるテキストそのもので、
.md をプレビューに、.csv を表に、.html をページに、**同じ中身を別の形で見せる**。

ターミナルにはそれが無かった。ターミナルの見せ方は「1本の文字列が時系列に流れていく」だけで、表は崩れ、
コードは素の文字、図は描かれず、過去は遡るしかない。ターミナルサポートは EditorSupport と同じ型で、
**前に出ているターミナルのタブに追従し、そこで流れた中身を、ターミナルにはできない形で見せ直す**。
拡張子の代わりに**前面のプログラム**で見せ方（提供者）を選ぶ。

> **やり直しの記録（2026-10-19）。** 第1版の Claude の面は、記録から取れるもの（頼みごと・書き換えたファイル・
> 最近の操作・操作キー・状態）を並べた。並べ方を「ターン単位・知りたい順」に組み直しても良くならなかった。
> 理由は二つ：(1)「何が嬉しいか」を決めずに「何が取れるか」から作った。(2) 調べると、状態・実行中の操作・
> 変更の差分（`/diff`）・離れていた間の要約（`/recap`）・並行セッションの一覧（エージェント一覧）・コンテキスト量
> （ステータスライン）は **Claude Code 自身がもっと良い形で出している**——横に並べ直しても劣化コピーにしかならない。
> 残る価値は「同じ中身の見せ方を変える」ことだけで、それが EditorSupport の価値でもあった。

`PaneKind.TerminalSupport`（末尾に追加）。ドックの既定は**右**（EditorSupport と同じ、本文の脇に添える面）。
既定キーは無い（`pane.terminalSupport`「ターミナルサポートを開く」）——脇に出しておく面で、呼びに行く起点ではない。

## §39.2 追従元と見せ方の決め方

追従元は `_activeTerminalTab`。その様子を `TerminalSupportSubject`（タブ・場所・前面のコマンドと開始時刻・
Claude の状態）に組み立てて渡す。**新しく見張るものは無い**——材料はすべて既存の表から読む。

- 前面のコマンド・場所：タブの様子の表（§24.53 `TerminalStatusOf`。OSC 133 の C〜D／A）
- Claude の状態：袖の活動（§24.1.1 `PaneActivityTracker.AgentTabs`。タイトルの印＋フック）
- 実行し終えたコマンド：出力の置き場（§24.21 `TerminalCommandOutputs`）

見せ方（`TerminalSupportMode`）は次の順に決める。

1. **Claude Code**：Claude の印が出ている、または前面のコマンドが `claude`。**Claude を先に見る**——Claude は
   C を出したまま居座るので「動いているプログラム」でもあるが、見たいのはコマンド行ではなく会話の中身。
   常駐の復元直後のように C が来ないまま印だけ分かる場合（§38.7）もこれで拾える。
2. **プログラム**：シェル以外が前面に居る（C を見て D 未着）。TUI もそうでないものも。
3. **シェル**：プロンプトで待っている。

引き直しは合図をまとめて 1 回（`RequestTerminalSupportRefresh`、Background 優先度）。合図はタブの切り替え・
袖のバッジの更新（Claude の状態・コマンドの始まりと終わり）・SessionStart・出力の切り出し・タブの様子の変化。
**ペインが見えていないときは何もしない**——見えた瞬間（`IsVisibleChanged`）に追いつく。

## §39.3 プログラム（TUI）

コマンド行・経過時間（§24.53 の 1 秒時計に乗る）・そして**知っているプログラムなら操作キー**を出す。
表は `TerminalProgramCatalog`（EditorSupport の拡張子→提供者の表にあたる）。

- 引き方：先頭の語の実行ファイル名（拡張子・パスを外す。pwsh の呼び出し演算子 `& '…\claude.exe'` も外す）。
  `dotnet watch` は 2 語で見る。**REPL（python・node）は引数なしのときだけ**——`python build.py` はスクリプトの実行で、
  REPL の案内は的外れ。
- **載せるキーは確かめたものだけ**。TUI のキーは版で変わり、間違った案内は案内が無いより悪い（押して別のことが
  起きる）。知らないプログラムはコマンド行と経過時間だけ。
- 第1段の顔ぶれ：Vim 系・less・lazygit・htop・ssh・Python／Node.js の REPL・dotnet watch。Claude Code の行も表に
  あるが（見分けに使う）、Claude の面には出さない——キーの案内は Claude Code 自身が出している。

## §39.4 Claude Code——会話を読み物として

ターミナルの Claude の返事は流れていく文字で、表は罫線の文字に崩れ、コードは素の文字、mermaid は描かれず、
前の返事は遡って探すしかない。同じ会話を **Markdown として描き直した1本の文書**にする。

- **頼みごとを見出し（h2）に**、その下に Claude の**返事を Markdown として描画**する。表は表に、コードは色付きに、
  mermaid は図になる。返事の中の見出しは**2 段下げる**（`#`→`###`、`ClaudeConversationDocument.DemoteHeadings`。
  コードブロックの中は触らない）ので、ページの**アウトライン欄が「頼みごと → 返事の節」の会話の目次**になる——
  ターミナルには無い「前のあの説明」へ一押しで戻る道。
- ターンの最後の本文が返事。**それより前の本文（作業の途中のメモ）は「途中のメモ N 件」に畳む**。作業中は最後の
  本文も途中なので「Claude · 作業中」と添える。
- 見出しの下に1行だけ、そのターンで**変えたファイル**（押すとエディタで開くリンク）・ワークスペースの外の数・
  コマンド回数・サブエージェントの数・失敗数。ここは読み物の脇注で、主役は返事。サブエージェントが書き換えたファイルも
  入る（記録を読んでいる、§39.4.2）。
- 頭の帯は1行：自分の番か（承認待ち・あなたの番は強調色）・題（Claude がタイトルに出している具体的な題、無ければ
  記録の `ai-title`）・コンテキスト量とターン数・「記録」（jsonl を開く）。セッションを確かめられないときはその理由。
- **開いたときは最新のターンの頭**を出す。最新のターンを読んでいる最中に新しいターンが始まったら、その頭へ付いていく
  ——古いターンを読み返しているときは動かさない（ページの本文差し替えの「末尾に居れば末尾に付いていく」とは別に、
  ターンの頭で止める）。ページが記録より先にできた（開いた直後は本文が空）ときは、初めて会話が届いた時点で最新の
  ターンの頭へ寄せる——第1段はここで先頭のターンに留まっていた（2026-10-20 に実際の WebView2 で見つけて直した）。
- ターンの見出しの id は**記録の行番号**（`cc-turn-<行>`）。古いターンが `MaxTurns` から落ちても id が変わらない。
  返事の中の見出し・脚注の id と、それを指す同じ文書内のリンクには**ターンごとの頭**（`t<行>-`）を付ける
  （`ClaudeConversationDocument.ScopeIds`）。同じ題の節が二つのターンにあると、`#まとめ` へのリンクやパーマリンクが
  先のターンへ飛んでいた。
- 本文のリンクは EditorSupport のプレビューと同じ振り分け（URL＝ブラウザ、ファイル＝エディタ）。相対パスは
  **Claude が動いている場所（タブの cwd）**から解く。

### §39.4.1 描き方

- ページは EditorSupport と同じ `MarkdownPage`（テーマは Markdown プレビューの設定・mermaid・アウトライン）、
  WebView2 と一時ページの道具も同じもの（`IEditorSupportViewFactory`・`EditorSupportNavigationService`）。包みは
  `TerminalSupportWebPage` で、会話（`preview-claude-<pid>.html`、ターンに付いていく）と出力の見せ直し
  （`preview-output-<pid>.html`、§39.5.1）の2枚が同じ包みを使う。Diff の Markdown 描画（§24.10）と同じく、XAML から生えて DI が届かないペインなので
  ShellWindow が道具を渡す。
- **ページを組むのはテーマが変わったときだけ**。会話が書き足されるたびの更新は**本文の差し替え**（`setBody`）。
  ターンごとに1つの `section` にしてあるので、ページの差し替えは変わったターンだけを入れ替える——読み返している
  古いターンの DOM もスクロール位置も触らない。
- 本文は**裏のスレッドで組む**。作業中は数秒おきに来るので、世代番号で古い結果を捨てる。組むのも**変わったターンだけ**：
  ターンの HTML は中身の指紋（`ClaudeConversationDocument.TurnKey`＝頼みごとの行・本文の数と最後の長さ・操作の数と
  結果の届いた数・失敗・ファイル・作業中か）ごとに `RenderCache` に控え、書き足された最新のターンだけを Markdown から描く。
  直近の組み立てで使われなかった控えは捨てる。
- **見えていないうちは WebView を作らない**（Claude の居ないタブ・隠れたペインで Chromium を起こさない）。

### §39.4.2 記録の決め方と読み方

- **タブのセッションは確かめてから出す。推量はしない。** 記録は SessionStart のフック（§38.4）で結び付いたものを
  使う（タブ ID 付きで届くので確定）。フックの無いタブ（未設定・設定前に起動した claude・常駐の繋ぎ直し）は、
  **動いている claude のプロセスから確かめる**（`ClaudeLiveSessions`）。Claude Code は起動中のプロセスごとに
  `~/.claude/sessions/<pid>.json`（いまのセッション ID・場所・開始時刻。`/clear` で書き換わる）を書く。
  - **タブのシェルの PID が分かるときはそれが一番強い**：そのシェルの子孫の claude だけを候補にする
    （`ClaudeLiveSessions.IsDescendantOf`）。場所も時刻も見ないので、同じ場所で複数動いていても、claude の中で場所が
    変わっても決まる。PID は自前の ConPTY なら `ConPtySession.ProcessId`（Terminal 1.0.47 で公開）、常駐なら Pty.Host が
    Open の応答で返す `PtyProtocol.Response.ShellProcessId`（足しただけの欄なので `PtyProtocol.Version` は上げない——
    古いホストは 0 を返し、そのときは下の確かめ方に戻る）。ShellWindow はタブ ID → シェルの接続を `_terminalShells` に
    持ち、タブを閉じたら外す。シェルがもう居ない（PID は再利用されうる）ときも下へ戻る。
  - シェルの PID が分からなければ、sessions のうち
    1. **この Loomo の端末の中**で動いている——親をたどると Pty.Host（常駐の端末）か Loomo 自身（常駐でない端末）に
       行き着く（Toolhelp のプロセス一覧。PID の再利用に備えて深さの上限と輪の検出つき）、
    2. 場所（cwd）がタブと同じ、
    3. ほかのタブにフックで結び付いていない、

    ものだけを候補にする。1つなら確定、複数ならタブで `claude` を打った時刻（OSC 133 の C）とセッションの開始時刻が
    15 秒以内のもの。**それでも決まらなければ何も描かず理由を出す**——別の会話を出すより、出さないほうがよい。
  - 記録は `projects/<slug(cwd)>/<sessionId>.jsonl`。
  - 第1版は「タブの場所の記録フォルダーでいちばん新しい記録」を当て推量していた。同じフォルダーで Loomo の外
    （Windows Terminal など）でも claude を回していると、**そちらの会話を Loomo のタブのものとして出していた**
    （2026-10-19 に実機で発生。指摘を受けて撤去）。
- 読み方は**ハーネスペインと同じもの**（`ClaudeTranscriptParser`＝ツール呼び出し・頼みごと・料金、
  `ClaudeSessionCatalog`＝題・コンテキスト量）。読み方を二つ持つと、片方だけ記録の形の変化に追従して
  食い違う。ここで足すのは返事の本文（assistant の text ブロック。思考とツール呼び出しは含めない）だけ。
- **ターンの区切り**は頼みごとの記録の位置（`HarnessRun.PromptMarks`）。本体の操作は行番号で、サブエージェントの
  操作（別ファイル）は時刻で振り分ける。**作業の途中に足した指示**は user の行にならず `queued_command` の添付
  （`attachment.type = "queued_command"`）として残るので、パーサーはこれも頼みごとに数える（ハーネスの頼みごとの
  数も正しくなる）。逆に、**バックグラウンドの作業の終了通知**（`<task-notification>`）は Claude Code が user の文字列の
  行として差し込むが、人間の頼みごとではないので数えない（第1段はこれを見出しにしていた。実記録で 1 セッション数十件）。
  ターンは新しい 20 個まで（`MaxTurns`）。
- **サブエージェントの記録**（`<session>/subagents/*.jsonl`）も読む。現れた順に足し、操作は時刻でターンへ振り分ける。
- **変えたファイル**は Edit・MultiEdit・Write・NotebookEdit が成功したもの（`Read`・拒否・失敗は入れない）。
  ワークスペースの外（Claude の一時ファイル・作業メモ）は数だけ（`workspace.Contains`、マルチルート）。
- **いつ読むか**：追従元・状態が変わったとき（ターンの終わり・承認待ち・SessionStart・タブの切り替え）と、
  **作業中だけ 4 秒おき**（`TerminalSupportClaudeInterval`。ペインが見えている間だけ回る）。読むのは裏のスレッドで、
  読んでいる間にタブが替わったら結果を捨てる（世代番号）。
- **どう読むか——追記分だけ**（`ClaudeSessionFollower`）。前回の読み終わりのバイト位置から先だけを読み、改行で終わった行
  まで食わせる（書きかけの最終行は次の回）。追記を跨いで持ち越すのは、パーサーの状態（`ClaudeTranscriptReader`：結果を
  待っているツール呼び出しをファイルごと・usage の `message.id` ごとの重複除去・行番号）・要約
  （`ClaudeSessionCatalog.SummaryAccumulator`：題・コンテキスト量はどれも「最後に見たもの」）・本文。まとめて読んだ
  `ClaudeTranscriptParser.Parse` と同じ結果になる（`Parse` 自身が読み手に食わせて写すだけの形）。どれかのファイルが
  **縮んだ**ら最初から読み直す。長さ・更新時刻・サブエージェントのフォルダーの中身が前回と同じなら開きもしない。
- 読み直しは重なりうるので、読み手は**版**（中身が変わるたびに増える数）を返し、ViewModel は自分が最後に描いた版と比べる。
  重なった読み直しの片方が世代番号で捨てられても、次の読み直しが「描いた版と違う」ので取りこぼさない。

## §39.5 シェル

前面に何も居ないときは、**このタブで実行し終えたコマンド**（§24.21 の置き場のうち、このタブのもの、
`TerminalCommandOutputs.ForTab`）を ✓／✗ 終了コード・経過つきで並べる。押すとその回の出力を下に見せ直す（§39.5.1）。
頭の「エディタで開く」「前回と比べる」（同じコマンドの1つ前の回、`PreviousOf`）と、右クリックの「プロンプトへ入れる」
（Enter は送らない、§24.3。複数行はコンポーザへ）。出力は永続化しない（§24.21 の注記のまま。再起動で消える）。

- 置き場はコマンド行ごとに全タブで2回分なので、別のタブで同じコマンドを打つと、こちらのタブの回は「今回」から
  「前回」へ繰り下がる。第1段は「今回」だけを見ていて、こちらの一覧から消えていた。`ForTab` は今回と前回の両方から
  このタブのものを拾う（繰り下がった回には比べる相手がいない）。
- **選んだ回**は、最新を見ていれば新しい回に付いていき、古い回を選んで読んでいる間は動かさない（行は値なので、選んだ印
  `IsSelected` も行に入れる）。

### §39.5.1 出力の見せ直し——同じ原理をほかの出力へ

Claude の会話を読み物にしたのと同じ原理（情報を足さず、同じ中身の見せ方を変える）を、実行し終えたコマンドの出力へ広げる。
提供者は**出力の形**で選ぶ（`TerminalOutputPresenter`、EditorSupport の拡張子→提供者の表にあたる）。上から順に、
**確かめてから**そう見せる——取り違えて崩すより、素の文字のほうがよい。

| 形 | 見分け方 | 見せ方 |
|---|---|---|
| 枝の図 | コマンドが `git log … --graph` で、`*` の行がコミットとして読める | 枝の桁ごとに色分け（2桁で1本）、節は ●、ハッシュと参照（`HEAD -> main`）を印に。罫線は罫線素片（`│ ╱ ╲`）——日本語の等幅フォントはバックスラッシュを `¥` で描く |
| テストの結果 | `dotnet test`（VSTest・MTP）・pytest・jest・vitest の集計行（§39.8） | 成否の一言・アセンブリごとの表・失敗したテストごとに（メッセージ・スタックトレースの file:line のリンク）。ビルドの診断も混ざっていれば下に |
| ビルドの診断 | tasks.json のタスクの matcher（その回がタスクなら）と組み込みの problem matcher（msCompile・tsc・gcc・eslint）が1件でも拾う | エラー／警告の数・ファイルごとの見出し（アウトライン欄がファイルの目次になる）・行:桁のリンク・コード |
| JSON | 全体が1つの値として読める（`{`/`[` で始まり閉じる） | 畳めるツリー（2段目まで開く・型ごとの色・4000 節まで） |
| 表 | PowerShell の Format-Table（見出しの下の `---- ----`）、またはコマンドが CSV を出すもの | 表（数だけの列は右寄せ・見出しを押すと並べ替え・`Directory:` の行は見出しに） |
| 素の文字 | どれでもない | 描かれたときの色で（30 万字を超えたら末尾を残す） |

- **表の列の切り方**：罫線の区切りだけでは切れない。PowerShell は数の列を右寄せにし、見出しより長い値は罫線より左へ
  はみ出す（`812.21` が `-----` の1桁前から始まる）。「どの行でも空白の桁」を隙間とみなして塊に分け、各塊をいちばん
  重なる罫線の列へ寄せる（`ColumnRanges`）。中に空白を持つ値（`2026/10/19    10:00`）は2つの塊になるが同じ罫線に
  重なるので1列にまとまる。罫線の区切りだけで切っていた最初の版は、実機の `Get-Process` で列がずれた。
- CSV はコマンドが CSV を出すもの（`ConvertTo-Csv`・`.csv`）のときだけ見る——カンマを含む普通の文章を表と取り違えない。
- 並べ替えはページの共通の仕掛け（`MarkdownPage` の `table.loomo-sortable`、document で受けるので本文差し替えを跨いでも効く）。
- リンクは `file:///…:行:桁`。振り分けは EditorSupport のプレビューと同じ口（`FileLinkResolver` が末尾の行:桁を読む）。
  診断の相対パスは、その回を実行した場所と、そこを持つワークスペースのフォルダーから解く（`FolderForOrPrimary`）。
- 見せ直しは裏のスレッドで組む（出力は最大 1MB）。ページの本文が替わるのは別の回を選んだときだけなので、いつも先頭から見せる。
- **VGrid を使わない理由**：第1段では「表 → VGrid」と書いたが、診断・テスト・JSON と同じ1枚のページに載せたほうが、
  リンクの振り分け・テーマ・アウトライン・WebView の世話が1つで済む。表に要るのは並べ替えまでで、編集は要らない。

## §39.7 実測

Release、Ryzen 5 3500。記録 15.8MB の実セッションで：

| | 1 回 | 確保 |
|---|---|---|
| 全体を読み直す（第1段、`ClaudeSessionDigest.Read`） | 120ms（初回 260ms） | ~20MB |
| 追記分だけ（20 行書き足し、`ClaudeSessionFollower.Refresh`） | 9〜12ms | ~250KB |
| 　うち digest の組み立て（`Compose`） | 0.2〜0.3ms | |
| 　うち書き足された直後のファイルを開く | 7〜10ms | |
| 変わっていない（開かない） | 0.03〜0.14ms | |

残る ~10ms のほとんどは**書き足された直後のファイルを開くこと**そのもので、Loomo の外（OS 側。リアルタイムの
ウイルス対策の検査と見ている）にかかる。6MB でも 15MB でも同じで、記録の長さには比例しない。書き足しが 1 行でも同じ。
第2段の最初の版はこれを「digest の組み立てが記録の長さに比例する」と書いていたが、測り分けると組み立ては 0.3ms で、
誤りだった（2026-10-20 に訂正）。読むのは作業中 4 秒おき・裏のスレッドなので、開く費用は 0.25% にとどまる。
追記分を足したあとの digest は、全体を読み直したものと一致した（ターン・操作数・返事・コンテキスト量）。

## §39.8 既知の穴と次の段

第1段の §39.8 に挙げた穴（差分読み・サブエージェント・タブのシェルの PID・返事の見出しの id の重なり・狭いペインの
アウトライン・ほかの出力への広げ・別のタブで同じコマンドを打つと一覧から消える）は第2段で、第2段の初版に残した穴
（テストの道具・tasks.json の matcher・出力の色・狭いペインで目次を出したままにする手段）は第2段の続きで埋めた：

- **テストの道具**：VSTest に加えて Microsoft.Testing.Platform（`Test run summary:` と `failed … (…)`）・pytest
  （締めの `=== 1 failed, 3 passed in … ===` と `FAILED …`、トレースバックの `file.py:12:`）・jest（`Tests:` と `●`、
  `at … (file:line:col)`）・vitest（`Tests  1 failed | 4 passed (5)` と `FAIL … > …`、`❯ file:line:col`）。読み手ごとに
  同じ形（`TestReport`）へ読み、描き方は1つ。**集計の行があるときだけ**テストの結果とみなす（`● ` は systemctl status に、
  `ERROR`・`FAILED` はログにもある）。相対パスはその回を実行した場所から解く。jest の抜粋のコード（`4 | …`）は位置の
  リンクで足りるのでメッセージに入れない。
- **tasks.json の matcher**：タスクの実行（§31.17）が1段終わるたびに、打ち込んだ1行（`TaskInvocation.TerminalLine`）
  → そのタスクの matcher と基準（タスクのフォルダー・実行した場所）を覚える（`ShellWindow._taskOutputMatching`）。
  出力の置き場もコマンド行で引くので同じ鍵で結べる。タスクの matcher を先に、組み込みを後に当てる。タスクの終わりは
  出力の切り出しより遅れて届くので、覚えたら見せている回を読み直す（`RepresentOutput`）。
- **出力の色**：Terminal 1.0.47 の `ShellCommandOutputEventArgs.StyledLines`（`Output` の1行に1つ、同じ書式の文字の連なり
  `TerminalOutputRun`：前景・背景・太字・薄字・斜体・下線・取り消し線・反転・OSC 8 のリンク）。行の切り出し
  （エコー・前後の空行）は素の文字と同じ範囲（`ExtractRange`）。Loomo は色か書式が1つでもあるときだけ持ち
  （`TerminalCommandOutput.StyledOrNull`）、上限で頭を落とすときは同じ行数だけ落とす。見せ直しの「素の文字」は
  描かれたときの色で描く（行の数が文字と揃わなければ素の文字に戻る）。色はターミナルが描いた RGB のまま。
- **狭いペインの目次**：畳んだ帯の上端（`≡`、開くと「アウトライン」の題）を押すと**開いたまま**になり、本文の上に
  重ねずに横に並べる（幅 `min(200px, 42vw)`）。もう一度押すと畳む。帯の途中は、触れて開いたあとは目次の項目なので
  押すと飛び先へ行く——押す場所は上端だけ。実際の WebView2 で、押したあとの並びは確かめた。ただし実マウスの押下は
  検証用の窓が前面に出られず（前面ロック）届かなかったので、押下は本文のスクリプトから起こして確かめた。

残るもの：

- 古い Pty.Host（版は同じ）が動き続けていると PID は 0 で、場所と時刻の確かめ方に戻る（ホストが入れ替われば解ける）。
- 色は Terminal の配色の RGB のままで、ページのテーマ（明るい配色）では読みにくい色がありうる。
- ビルドの診断の matcher は、tasks.json のタスクとして走らせた回だけ（手で同じコマンドを打っても、打った行が同じなら
  同じ読み方になる——鍵がコマンド行なので）。

## §39.9 会話をツリーとトグルで引く（第3段）

§39.4 の読み物は1本の文書で、目次（アウトライン）から辿れるのは頼みごとと返事の見出しだけだった。「前のあの説明」
「あのファイルはどう変わったか」「サブエージェントは何を報告したか」「どのコマンドが落ちたか」を探すには、長い文書を
スクロールするしかない。**見たいものを一発で特定し、それだけを描く**ために、会話を**ツリー**にし、出す種類を
**トグル**で選ぶ。ツリーと呼ぶのは、サブエージェントが自分の操作を子に持つから（ターン → エージェント → 操作）。

```
[§ 返事][✎ 変更][◇ サブ] $ コマンド  ✗ 失敗  … メモ      ← 点いている種類だけがツリーに出る
[絞り込み（本文・ファイル・コマンド）          ]
 ≡ 会話をすべて                         7 ターン    ← §39.4 の読み物（ターンに付いていく）
 ▸ 一つ目の頼みごと                     10:00      ← ターン（会話と同じ順、新しいものが下へ）。選ぶとそのターン
 ▾ 二つ目の頼みごと                     10:01 ✗1
     § まとめ                                      ← 返事の節（いちばん上の段の見出しで切る）
     ✎ b.cs                                        ← 書き換え。選ぶと差分
   ▾ ◇ 直す                           3 操作 ✗1   ← サブエージェント。選ぶと頼みごとと報告
       ✎ sub.cs
       $ dotnet test                          ✗    ← 選ぶと出力の見せ直し（§39.5.1 と同じ道具）
──────────────────────────（分割線）
 選んだ節だけを描くページ
```

- **軸はターン**（2026-10-20 にユーザーが選んだ）。ターンは会話と同じ順で、新しいものが下へつながる（最初の版は新しい順に上へ積んでいたが、会話の流れと逆で読みにくいと指摘を受けて直した）。追従中は選んだ最新のターンが見える位置へツリーを送る。ファイル軸（ファイル → それを変えたターン）は
  候補にしたが採らなかった。
- **葉はどれも、押すと「ターミナルでは見られない形に描き直した中身」が出る**（§39.1 のやり直しの記録と同じ物差し）。
  要約 1 行で終わるものはツリーに置かない。
  | 節 | 描くもの |
  |---|---|
  | 会話をすべて | §39.4 の読み物そのもの（ターンに付いていく） |
  | ターン | そのターンだけ（頼みごと・脇注・メモ・返事） |
  | § 返事の節 | 返事を、コードブロックの外のいちばん上の段の見出しで切った1節（見出しより前の本文も1節。見出しが無ければ返事全体） |
  | ✎ ファイル | そのターン（エージェント）での書き換えを順に。Edit／MultiEdit は差分（`DiffUtil`→```diff```）、Write は書いた中身 |
  | $ コマンド | コマンド行と、**出力を形に合わせて見せ直したもの**——Claude が走らせた `dotnet test` はテストの表に、`git log --graph` は枝の図に（`TerminalOutputPresenter`）。Bash の結果の頭の `Exit code N` は外して終了コードにする |
  | ◇ サブエージェント | 頼みごと（畳む）と報告（Markdown）。操作はツリーの子 |
  | ✗ 失敗 | 失敗した操作（コマンド以外も）の結果の全文 |
  | … メモ | 作業の途中の本文 |
- **トグルの既定**は返事・変更・サブ。コマンド・失敗・メモは見たいときに点ける。コマンドを点けていれば、失敗したコマンドは
  そちらに ✗ 付きで出るので、失敗には二重に出さない。選んだ種類の葉が1つも無い古いターンは出さない（最新のターンは出す）。
  トグルは永続化しない（ペインの ViewModel が持つ。タブを替えても残る）。
- **サブを出しているとき、エージェントの操作はエージェントの下へ**（ターンの直下は本体の操作だけ）。消せばターンの直下に並ぶ。
- **絞り込み**は題に加えて中身（返事の本文・コマンド全文・ファイルの表示パス・エージェントへの頼みごとと報告）に当て、
  当たった節とその親だけを残して開く。頼みごとに当たったターンは中身をそのまま残す。
- **選んだ節だけを描く**。ページ（`TerminalSupportWebPage`）は会話のものを使い回し、別の節を選んだら先頭から、同じ節の
  書き足し（作業中のターン）は読んでいる位置のまま。ターンに付いていく動き（§39.4）は「会話をすべて」のときだけ。
- **追従**：開いたときは最新のターンを選ぶ。最新のターン（の中の節）を選んでいれば、新しいターンが始まったらその頭へ
  付いていく。古いターンを読み返している間は動かさない（§39.4・§39.5 と同じ約束）。
- **見た目**（2026-10-20 に整えた）：種類のチップはキー設定の観点チップと同じ丸い形で、色の付いた印と**セッション全体の件数**を
  添える（どの種類がどれだけあるかが、点ける前に分かる）。印の色はコードのアウトラインの記号の色を借りる（返事＝Interface、
  変更＝Type、サブ＝Method、コマンド＝Enum、失敗＝Error）——どのテーマでも馴染む。ツリーの行は同じ色の印を固定幅で置き、
  コマンドは等幅。選んだ行は角丸の淡い面＋左端のアクセントの線、子は細いガイド線で字下げ（コードのアウトラインと同じ作法）。
  ターン・エージェントは題を赤くせず、中の失敗の数（✗N）だけを赤く、作業中は小さな点で示す。絞り込みは虫眼鏡と ✕ 付き。
  ツリーとページの分割線は見た目 1px・掴める幅 5px。
- **行は使い回す**。節の id は記録の位置から作る（ターン＝`t<頼みごとの行>`、操作＝tool_use の id、エージェント＝agentId、
  ファイル＝親＋パス）ので、記録が書き足されても・トグルを替えても同じ行は同じインスタンス——開閉と選択が残る。
  最新のターンだけ開いて生やし、ほかの開閉は人に任せる。選んだ節がトグルで隠れても、見せている中身はそのまま。

### §39.9.1 サブエージェントを結ぶ

サブエージェントの記録は `<session>/subagents/agent-<id>.jsonl`（名前は横の `agent-<id>.meta.json` の description）。
本体のどの Agent／Task 呼び出しが起動したものかは、
1. 呼び出しの結果の `toolUseResult.agentId`（同期・非同期どちらにも載る。非同期は起動した時点で返る）、
2. まだ結果が無い（動いている同期のエージェント）なら、**渡した頼みごと（`input.prompt`）と記録の最初の user の行が同じ**こと、

で結ぶ（`ClaudeSessionDigest.Subagents`）。結べたエージェントは起動した呼び出しのターンへ、結べないもの（フォークした
スキル——`/code-review` は Agent を経ずに subagents に記録を書く）は動き始めた時刻でターンへ振り分ける。報告は、同期なら
呼び出しの結果（全文）、非同期（結果は「起動した」だけ）なら記録の最後の本文。

### §39.9.2 全文はその時だけ記録から引き直す

digest は数 MB の記録を追いかけ続けるので、コマンドの出力・Write の中身・同期エージェントの報告の全文までは抱えない。
パーサーが操作ごとに **tool_use の id と結果の行番号**（`RunToolCall.ToolUseId`・`ResultLineNumber`）を持ち、ツリーで
選ばれたときにその行だけを読む（`ClaudeTranscriptLookup`、裏のスレッド）。描いた本文は節の指紋（`ClaudeTreeNode.Key`）
ごとに1つ控え、作業中の 4 秒おきの読み直しで指紋が変わらなければ描き直さない（記録も開かない）。

返事の本文を持つ上限（`MaxReplyChars`）は 2000 字から 2 万字に上げた。2000 字で切っていた頃は、長い返事の後ろの節が
ツリーにも読み物にも出なかった。

### §39.9.3 確かめたこと

`ClaudeSessionTreeTests`：サブエージェントを agentId と頼みごとで結ぶ・エージェントの操作をその下へ（サブを消せば
ターンの直下）・既定の種類・トグルで出し分け（失敗の二重出し無し・葉の無い古いターンを隠す）・絞り込み（本文・
エージェントの中の操作・頼みごと）・書き足しで id が変わらない・選んだ節の描き方（コマンドの出力を記録から引いて
見せ直す・Write の中身・差分・エージェントの報告）・最新のターンへの追従と読み返し中は動かさない・行の使い回し。
見た目は、実記録（サブエージェント4つ・14MB）を流し込んだペインを描いて撮り、選んだ節のページ（エージェントの報告・
Claude が走らせた `dotnet test` がテストの表になる）を Edge で描いて確かめた。実機の Loomo の中で Claude を動かしながらの
確認（追従・WebView の差し替え）はまだ。
