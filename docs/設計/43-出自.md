## §43.2 出すもの（第1段）

- **コミットしていない行の blame に、その行を書いた頼みごと。** カーソル行の行末（§24.42 の設定が ON のとき）は
  `頼みごと, 2026-11-14 20:31 · 〈頼みごとの 1 行目〉`、`:Gblame` の欄は `Claude (頼みごと, 日時)`。サブエージェントが
  書いた行は「サブエージェント」と出し、頼みごとは本体のターンのもの。git が答えられる行（コミット済み）は
  これまでどおり。**人間が書いた行には何も出さない**——どの書き込みにも無い行は結ばない。
- **まだ git に載っていないファイル**（blame が失敗する）は、全行をコミットしていない行として結ぶ。
- **blame の欄で Claude の行を押す** → 頼みごとの本文を通知欄へ（コミットの行なら差分が開く場所）。
- **右クリック**（blame の欄）:
  - 「この頼みごとで変わった場所…」——出自の逆向き。同じ頼みごと（同じターン）が書いたファイルを 1 行ずつ
    （足した行数つき）。選ぶと、その書き込みが**いまある行**へ行く。
  - 「頼みごとの全文をコピー」
  - 「この会話を再開」——新しいタブで `claude --resume`（§38.4 と同じ）。セッション ID は記録のファイル名から
    来るので、打つ前に形を確かめる。
- 設定は足さない。blame を出しているときに、git が黙る行を埋めるだけ。

### §43.2.1 コミットした行（A2a）

- **最近コミットした行**（コミットの時刻が索引の期間＝14 日以内）は git の blame の行のまま、**頼みごとを添える**。
  ハッシュ・作者・日付・元の行番号は変えない——欄を押せばコミットの差分、右クリックの差分・履歴・リンクもこれまでどおり。
- 添える場所は件名の**前**：`頼みごと「〈1 行目〉」 · 〈コミットの件名〉`。計画は「件名の後ろ」だったが、行末の注記
  （§24.42）は件名を先頭 60 字で切るので、後ろでは長い件名のコミットで頼みごとが見えない。件名は残り、blame の欄の
  ツールチップで全部読める。
- 右クリックは、コミットの項目の後ろに「この行を書いた頼みごと：…」（押すと本文を通知欄へ）と、コミットしていない行と
  同じ 3 項目（変わった場所・全文のコピー・会話の再開）。
- **結び方**はコミットごと：そのコミットの行だけを `Attribute` に通し、書き込みは**そのコミットより前のもの**に絞る
  （あとから同じ中身を書き直した頼みごとに取られない。Write の穴＝§43.5 の 1 つ目がコミット済みの行へ広がらない）。
  続いている行を辿るのも同じコミットの中だけ。Loomo の git 操作には手を入れていないので、Claude がターミナルで
  コミットしても効く。
- エディタの blame の行に取っ手を載せる欄が無いので、索引が（ファイル・短いハッシュ・そのコミットでの行番号）→
  書き込みの表を持つ（blame を引くたびにファイルごと差し替え）。Editor パッケージは変えていない。
- 実測（Loomo 自身、第1段のコミット直後）：`ClaudeProvenance.cs` の 209 行すべてに元の頼みごとが付く。
  2 回目以降は git の blame 込みで 50〜140ms（第1段と変わらない）。

### §43.2.4 記録が消えても残す（A2b）

- 置き場所は **`%APPDATA%/Loomo/provenance.db`（SQLite）** に決めた（2026-11-14）。git notes は採らない——人のリポジトリに
  頼まれずに ref を増やすことになる。
- **覚えるとき**：blame を引いて、コミット済みの行を記録から結べたとき（A2a）。覚えるのは頼みごと（本文・セッション ID・
  記録の場所・頼みごとの行）と、行の鍵（ファイル・短いハッシュ・そのコミットでの行番号）→ 頼みごと、だけ。足した行の中身は
  持たない。すでに覚えている行は書き直さない。
- **使うとき**：記録からは結べなかったコミット済みの行（14 日より前・記録が消えた）に、覚えていた頼みごとを同じ形で添える。
- **元の記録が消えていたら**、右クリックは「（元の記録は消えています…）」と全文のコピーだけ。差分・変わった場所・会話・再開は
  記録が要るので並べない。記録が残っていれば（15〜30 日）会話と再開は効く。
- 読み書きは blame を引くスレッド（背景、§31.15）。400 日より前に覚えた行は、開いたついでに刈る。
- **穴**：覚えるのは blame を引いたファイルだけ。コミットから 14 日のあいだ一度も blame を出さなかったファイルの行は
  結ばれないまま期間を過ぎる（行末の注記＝§24.42 を ON にしていれば、開いたファイルは自然に覚える）。

### §43.2.2 頼みごと単位の差分（A3）

- **入口**は 2 つ：blame の欄の右クリック「この頼みごとの差分を開く」（コミットしていない行・最近コミットした行）と、
  ターミナルサポート（§39）の会話のツリーでターン（とその中の行）を右クリック「この頼みごとの差分を開く」。
- **出るもの**：その頼みごとが書き換えたファイルを 1 件ずつ、左＝頼みごとの前・右＝頼みごとの後で Diff ペインに積む
  （`DiffOpenTarget.Request`。中身は素材の比較＝フォルダー比較と同じ積み方なので、通しで読む・次の差分へ・別窓、は
  そのまま効く）。作ったファイルは印「追加」。
- **「見た」印**（§24.107）が付けられる。見方は頼みごとごと（`request:<セッション>:<頼みごとの行>`）——同じ頼みごとを
  開き直せば、読んだところが残っている。素材の比較で印を付けられるのは、見方を名乗るこの比較だけ。
- **前の中身**は次の順で探す（`ClaudeRequestDiffBuilder`）：
  1. Claude Code のファイル履歴（`~/.claude/file-history/<セッション>/`）。記録の `file-history-snapshot`／
     `file-history-delta` のうち、頼みごとのメッセージ（`uuid`）に結ばれたバックアップ＝その頼みごとで最初に触る前の中身。
     バックアップ無しと記録されていれば「無かった」。
  2. 最初の書き込みの結果に残る元の中身（`toolUseResult.originalFile`）・新規作成の印（`type: create`）。
  3. どれも無ければ**抜粋**：操作ごとの置換前と置換後だけを並べる（行番号はファイルのものではない）。
- **後の中身**は、前の中身に操作（Edit の置換・Write の全体）を記録の順に**当て直して**作る。いまのファイルは使わない
  ——あとの頼みごとや人間の変更が混じるため。当たらない操作が 1 つでもあれば（ツールを通さない変更が間に入った）抜粋に落とす。
- **あとから変わっていたら、そう言う**：いまのファイルが「後」と違えば、一覧の見出しに「※このあと変わった」、右の題に
  「足した N 行のうち M 行がいまも残る」。無くなっていれば「※いまは無い」、抜粋なら「※抜粋」。そのまま読んでよい
  ファイルには何も付けない。
- 記録とバックアップを読むのは背景（押したときに 1 回）。ファイル履歴と結果の形は Claude Code の私的な形式なので、
  読めなければ黙って次の手へ落ちる。

### §43.2.3 会話のその場所へ（A4）

- blame の欄の右クリック「この頼みごとの会話を読む（ターミナルサポート）」→ ターミナルサポート（§39）がその記録を
  **留めて**、頼みごとのターンを開く（ツリーでそのターンを選び、本文にそのときの返事と操作）。再開（`--resume`）と
  違って何も動かさない——読むだけ。
- ターミナルサポートは前面のタブの動いているセッションに付いていく面なので、留めている間だけその追従を止める
  （`TerminalSupportViewModel.ShowRecordAsync`・`IsPinnedRecord`）。頭の 1 行は「記録」、右に「タブへ戻る」。
  **離れ方は 2 つ**：「タブへ戻る」を押す／ターミナルのタブを替える（替えた先のタブへ付いていく）。
- 終わったセッションでも、いま動いているセッションでも同じ入口。読むのは留めたときの 1 回だけで、動いているセッションの
  書き足しには付いていかない（付いていきたければタブへ戻る）。
- 留めた記録のツリーからも「この頼みごとの差分を開く」（§43.2.2）が使える——行 → 頼みごと → 返事 → 差分が部屋の中でつながる。

## §43.3 行の結び方

記録に残るのは行番号ではなく**書いた中身**（Edit の `new_string`・Write の `content`・MultiEdit の各 `new_string`・
NotebookEdit の `new_source`）。行は中身で合わせる——あとから人間や別の編集が行をずらしていても当たる。

1. **足した行**: 書き込みごとに、置換後にあって置換前（`old_string`）に無い行。Edit は一意にするための前後の文脈を
   `old_string` にも `new_string` にも入れるので、それを足した行に数えると他人の行まで自分のものになる。
   同じ行が置換前に n 回あれば、置換後の最初の n 回は「元からあった」。
2. **適用された書き込みだけ**: 結果が返っていて、失敗（`is_error`）でも人間の拒否でもないもの。
3. **結ぶ**（`ClaudeProvenance.Attribute`）:
   - 中身のある行で、足した書き込みが 1 つだけ → それで決まり。
   - 複数の書き込みにある行（`return result;`）→ 続いている行の持ち主がその行も足していればそこへ。
     手がかりが無ければ、いちばん新しい書き込み。
   - `}`・空行・`try` のようにどこにでもある行 → 中身では決めず、続いている行の持ち主に寄せるだけ
     （寄せ先が無ければ結ばない）。
   - 辿るのは続いているコミットしていない行だけ（40 行まで）。**人間の行**（どの書き込みにも無い、中身のある行）で止まる。
4. **頼みごと**: 本体の操作は記録の行番号で、サブエージェントの操作（別ファイル）は時刻で、直前の頼みごとへ
   （§39.4 のターンの区切りと同じ。作業の途中に足した指示＝`queued_command` も頼みごと）。

## §43.4 記録の読み方と重さ

- `ClaudeProvenanceIndex`（Services）がワークスペースの記録フォルダー（§37.2.1 の探し方）から、**直近 14 日・
  新しい順に 24 件まで**を読む。コミットしていない行は長く残らないので、古い記録までは見ない。
- 記録 1 つは、長さ・更新時刻（サブエージェントの記録の印も）が変わらない限り 1 回しか読まない。読み方は
  `ClaudeTranscriptParser` のまま（頼みごとの見分け・拒否と失敗の除外を二重に持たない）。足すのは、書き込みの行だけを
  もう一度読んで中身を取り出すこと——記録の全行を抱えない。1 回の書き込みから持つのは 5,000 行まで。
- 読むのは **blame を引くスレッド**（エディタは背景から呼ぶ。開いたとき・保存したときに 1 回）。UI スレッドでは、
  すでに読んだものを引くだけ（押した行・変わった場所の一覧）。打鍵の経路には何も足さない（§31.15）。
- 実測（Loomo 自身のワークスペース、記録 24 件）: 最初の 1 回が約 0.8 秒、以降は git の blame 込みで 60〜90ms。
- エディタの `EditorBlameLine` は文字列と整数 1 つしか運べないので、ハッシュの欄に印 `Claude`（16 進ではないので
  コミットのリンク・差分の経路には乗らない）、元の行番号の欄に索引の取っ手（`HandleOf`／`FromHandle`）を入れる。
  エディタのパッケージは変えていない。

## §43.5 既知の穴

- **Write で丸ごと書き直したファイル**は、前の書き込みが足した行も新しい Write のものになる（Write には置換前が無い）。
- **ツールを通さない変更**（`sed`・整形・生成スクリプト・`git checkout`）は記録に中身が無いので結べない。
- **人間が Claude と同じ行を打った**場合は Claude のものになる（中身で合わせる以上、見分けられない）。
- **コミットして 14 日のあいだ blame を出さなかったファイル**の行は、その後は結ばれない（§43.2.4 の穴）。
  記録が消えたあとは、頼みごとの本文は出るが差分・会話は出せない。
- **コミットの時刻より後に記録された書き込み**は、そのコミットの行に結ばない。コミットを作り直して（amend・rebase）
  時刻が新しくなるぶんには効くが、時計のずれた別の PC の記録とは合わないことがある。
- 未保存の編集がある間はカーソル行の blame 自体が出ない（§24.42。行番号は保存してある版のもの）。
- 14 日より前・25 件目より古い記録の書き込みは結ばない。
- **頼みごと単位の差分**（A3）：NotebookEdit は当て直せないので抜粋。サブエージェントの書き込みはファイル履歴に
  載らないことがあり、そのときも抜粋。作業の途中に足した指示（`queued_command`）で始まるターンは、結ばれた
  バックアップが無いので結果の行か抜粋に落ちる。「あとから変わった」は**誰が**変えたかまでは言わない。
  抜粋・あとから変わったファイルでは、差分の行からエディタへ飛ぶと行がずれる。
- 画面は未確認（テストと、このセッション自身の記録を実データにした索引の確認まで）。

### C. 軌跡の二声化（第1段実装済み・2026-11-15）

**決めたこと**（「先に決めること」への答え）：
- **軌跡の点は人間のまま。** `trail.db` に Claude の出来事は書かない・`TrailEntryKind` も足さない。§27.1 の非目的
  （軌跡は人間のナビゲーション）は書き直さずに済ませる——バーのドット列・デデュープ・現在地・スクラブには何も混ぜない。
- **Claude の声は展開ビュー（§27.14）の段として重ねる。** コマンドの段が `command_runs` を重ねているのと同じ作りで、
  正本は Claude Code の記録（`~/.claude/projects`）。§27.14 が「まだ無いもの」に挙げていた「AI の操作との重ね合わせ」がこれ。
- **数え方は 1 つ**：ターンの区切りはターミナルサポート（§39.4）・出自（§43.3）と同じ頼みごとの印
  （`ClaudeTranscriptParser`）。留守中のまとめ（§24.22）・この日のまとめ（§24.23）のカードは今回は触らない——
  まとめを同じターンから引く形に寄せるのは、段が使われると分かってから。

**入ったもの**：
- 展開ビューに 4 段目「Claude」。頼みごと 1 つ＝頼んだ時刻から最後の操作までの帯。ファイルを書き換えたターンは塗り、
  書き換えていないターン（調べただけ・答えただけ）は枠だけ。ツールチップに時刻・頼みごとの 1 行目・書き換えたファイルの数。
- **押すと**：書き換えたターンは頼みごと単位の差分（§43.2.2）、そうでないターンは会話のその場所（§43.2.3）。
  上の「移動」の段（人間の点）と同じ時刻の軸なので、「頼んだ → Claude が書いた → 自分が見に行った」が縦に読める。
- 読むのは裏（`ClaudeDayActivity`。記録 1 つは変わらない限り 1 回・その日に近い 40 件まで）。段を描くときは読んである
  ものを引くだけで、20 秒より古ければ裏で読み直し、変わっていたら描き直す。
- 記録が消えた日（既定 30 日より前）は段が空になる。承認待ちは記録に残らないので段に出ない。
- 実装: `Loomo.Services/ClaudeCode/ClaudeDayActivity.cs`・`Views/Activity/TrailTimelineView.cs`（`ClaudeTurnsProvider`・
  `ClaudeTurnClicked`）・`ShellWindow.ClaudeProvenance.cs`（読み込みと押したとき）。テスト: `ClaudeDayActivityTests`。
  段の描画は View を単体で描いて確認した（11/14 の実記録で帯が時刻どおりに出る）。記録点は `trail.diff`・`trail.read`。
- あわせて、会話を詰め直したときの要約（`isCompactSummary`）が頼みごとに数えられていたのを直した（段に
  「This session is being continued…」のターンが出て気づいた。ターミナルサポートのターンにも効く）。

以下は当初の計画（残り＝まとめのカードとの一本化）。

- **何を**: 軌跡に「自分がいない間に部屋で起きたこと」の段を足す——ターンの終わり・書き込んだファイル・承認待ち。
  人間の点（§27.1）とは**段を分け**、混ぜない（デデュープ・現在地・スクラブは人間の点だけのもの）。

### D. 部屋を Claude から使う（第1段実装済み・2026-11-15）

**決めた線引き**（「先に合意する」への答え。主役は人間＝§38.1）：
- 道具は**置くだけ**の 3 つ：`show_file`（ワークスペースのファイルをこの行で）・`show_url`（http(s) をブラウザの
  **新しいタブ**で——見ているページを置き換えない）・`show_changes`（いちばん新しい「書き換えた頼みごと」の差分＝§43.2.2）。
- **出さない道具**：見えるターミナルに打つ・タブを閉じる・配置を変える・ファイルを書く。
- **フォーカスを奪わない**：人間は Claude に向かって打っている最中かもしれないので、置いたあとフォーカスを元のペインへ戻す。
  隠れているペインを出すための並べ替えもしない（出ていなければ通知にそう書く）。置いたことは通知で知らせる。
- **開けるもの**：ワークスペースの中にあるファイル（`workspace.Contains`）と http(s) の URL だけ。
- 2 つを並べる道具（計画にあった「この 2 つを並べる」）は入れていない——配置を変えることになるため。

**作り**：
- `LoomoMcpServer`（Services）：標準の MCP（Streamable HTTP・JSON 応答だけ）を 127.0.0.1 で待つ。Bearer トークンの無い要求と
  `Origin` 付きの要求（ブラウザのページから）は断る。IDE 連携（§38.2）と同じく TCP の上で HTTP を最小限だけ話す。
- **ポートとトークンは前回と同じ**（`%LOCALAPPDATA%/Loomo/mcp-endpoint.json`）。端末のシェルは Loomo より長生きする（§34）ので、
  再起動後も古いシェルの環境変数が通じる。取られていれば別のポートへ（2 つ目の Loomo）。
- ターミナルの環境変数に `LOOMO_MCP_URL`・`LOOMO_MCP_TOKEN`（`TerminalEnvironmentFor`）。**環境変数だけで MCP サーバーを足す
  方法は Claude Code に無い**ので、定義を 1 回だけユーザーが登録する：パレット「Loomo の道具（MCP）を Claude Code に登録する
  コマンドをコピー」→ ターミナルで実行。定義は環境変数を参照するだけ（ポートもトークンも `~/.claude.json` に書かれない）。
  Loomo は黙ってユーザーの設定を書かない。Loomo の外で起動した claude では、既定値の閉じたポートへつなぎに行って失敗するだけ。
- 設定は IDE 連携と同じ（`ClaudeCodeIdeIntegration`）。記録点は足していない（道具を呼ぶのは Claude なので、使われたかは記録で数えられる）。
- 実装: `Loomo.Services/ClaudeCode/LoomoMcpServer.cs`（サーバーと `LoomoMcpTools`）・`ShellWindow.LoomoMcp.cs`（ホスト・線引き）。
  テスト: `LoomoMcpServerTests`。
- **確かめたこと**：本物の `claude -p`（`--mcp-config` で同じ定義＝環境変数の参照）からこのサーバーの `show_file` を呼べた
  （localhost の http・独自名の環境変数の展開・こちらのプロトコル実装）。
- **未確認**：`claude mcp add --scope user` に `${…}` を渡したとき展開されずに保存されるか（`claude mcp get loomo` で見る）・
  Loomo の画面の側（フォーカスが戻る・通知・ペインが隠れているとき）・許可の聞かれ方（`permissions.allow` に
  `mcp__loomo__*` を足すかはユーザー次第で、Loomo は足さない）。

以下は当初の計画。

- **何を**: Loomo が MCP サーバーとして、Claude が**人間の前に物を置く**道具を出す——「このファイルのここを開く」
  「この 2 つを並べる」「この差分を開く」「この URL をブラウザペインで」（§19.5 の「AI への開く指示」）。
- **線引き（先に合意する）**: 主役は人間（§38.1）。Claude は置くだけで、見えるターミナルには打たない・タブを閉じない・
  配置を壊さない（開く先は既定の振り分けに従う）・フォーカスを奪わない（袖のバッジと通知で知らせる）。
- **作り方の当たり**: IDE 連携（§38.2）の口はモデルに見えるツールが限られる（§38.7）ので、別の MCP サーバーとして
  立て、Loomo のターミナルの環境変数で渡す。`loomo://`（§24.59）のリンクを開く口と中身を共有する。
- **閉じる条件**: Claude の返事の「ここを見てください」が、返事を読む前に部屋に出ている。
