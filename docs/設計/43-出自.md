## §43.1 なぜ（2026-11-14 の実測）

AI ペインを外した（§25 冒頭）あと、「次の部屋は何のための部屋か」を軌跡（`trail.db`）と Claude Code の記録
（`~/.claude/projects`）で測った。期間は 10/15〜11/14。

| 測ったもの | 値 |
|---|---|
| 人間がエディタで編集した地点（軌跡の Edit） | **10** |
| Claude Code の書き込み（Edit／Write の呼び出し） | **約 1,850**（1 日あたり延べ 20〜170 ファイル） |
| 人間の頼みごと | 約 600 |
| Diff ペインへ切り替えた回数（軌跡の Pane） | 8（Git ペインは 43） |
| 同時に動いていたセッション | ほぼ 1〜2、最大 3 |

書いているのはほぼ Claude で、人間の仕事は**頼む・戻ってきて読む・判定する**に移っている。部屋はまだ「自分で読み、
書き、移動する人」の作りで、軌跡も人間の移動しか知らない（§27.1 の非目的）。足りないのは機能の数ではなく、
**いま見ている行と、それを生んだ頼みごとを結ぶ線**。git の blame が答えるのはコミットした後だけで、いちばん
読まなければならない「まだコミットしていない行」には何も言わない。

- Diff ペインの 8 回は、切り離した窓のぶんを数え落としているかもしれない（軌跡はメイン領域のペイン切替を数える）。
- 並行は少ない。課題×ワークツリー×セッション×配置を 1 つに束ねる案（§43.6 の B）は、この数字では後回し。

## §43.2 出すもの（第1段）

- **コミットしていない行の blame に、その行を書いた頼みごと。** カーソル行の行末（§24.42 の設定が ON のとき）は
  `頼みごと, 2026-11-14 20:31 · 〈頼みごとの 1 行目〉`、`:Gblame` の欄は `Claude (頼みごと, 日時)`。サブエージェントが
  書いた行は「サブエージェント」と出し、頼みごとは本体のターンのもの。git が答えられる行（コミット済み）は
  これまでどおり。**人間が書いた行には何も出さない**——どの書き込みにも無い行は結ばない。
- **まだ git に載っていないファイル**（blame が失敗する）は、全行をコミットしていない行として結ぶ。
- **blame の欄で Claude の行を押す** → 頼みごとの本文を通知欄へ（コミットの行なら差分が開く場所）。
- **右クリック**（blame の欄）:
  - 「この頼みごとで変わった場所…」——出自の逆向き。同じ頼みごと（同じターン）が書いたファイルを 1 行ずつ
    （足した行数つき）。選ぶと、その書き込みが**いまある行**へ行く。
  - 「頼みごとの全文をコピー」
  - 「この会話を再開」——新しいタブで `claude --resume`（§38.4 と同じ）。セッション ID は記録のファイル名から
    来るので、打つ前に形を確かめる。
- 設定は足さない。blame を出しているときに、git が黙る行を埋めるだけ。

## §43.3 行の結び方

記録に残るのは行番号ではなく**書いた中身**（Edit の `new_string`・Write の `content`・MultiEdit の各 `new_string`・
NotebookEdit の `new_source`）。行は中身で合わせる——あとから人間や別の編集が行をずらしていても当たる。

1. **足した行**: 書き込みごとに、置換後にあって置換前（`old_string`）に無い行。Edit は一意にするための前後の文脈を
   `old_string` にも `new_string` にも入れるので、それを足した行に数えると他人の行まで自分のものになる。
   同じ行が置換前に n 回あれば、置換後の最初の n 回は「元からあった」。
2. **適用された書き込みだけ**: 結果が返っていて、失敗（`is_error`）でも人間の拒否でもないもの。
3. **結ぶ**（`ClaudeProvenance.Attribute`）:
   - 中身のある行で、足した書き込みが 1 つだけ → それで決まり。
   - 複数の書き込みにある行（`return result;`）→ 続いている行の持ち主がその行も足していればそこへ。
     手がかりが無ければ、いちばん新しい書き込み。
   - `}`・空行・`try` のようにどこにでもある行 → 中身では決めず、続いている行の持ち主に寄せるだけ
     （寄せ先が無ければ結ばない）。
   - 辿るのは続いているコミットしていない行だけ（40 行まで）。**人間の行**（どの書き込みにも無い、中身のある行）で止まる。
4. **頼みごと**: 本体の操作は記録の行番号で、サブエージェントの操作（別ファイル）は時刻で、直前の頼みごとへ
   （§39.4 のターンの区切りと同じ。作業の途中に足した指示＝`queued_command` も頼みごと）。

## §43.4 記録の読み方と重さ

- `ClaudeProvenanceIndex`（Services）がワークスペースの記録フォルダー（§37.2.1 の探し方）から、**直近 14 日・
  新しい順に 24 件まで**を読む。コミットしていない行は長く残らないので、古い記録までは見ない。
- 記録 1 つは、長さ・更新時刻（サブエージェントの記録の印も）が変わらない限り 1 回しか読まない。読み方は
  `ClaudeTranscriptParser` のまま（頼みごとの見分け・拒否と失敗の除外を二重に持たない）。足すのは、書き込みの行だけを
  もう一度読んで中身を取り出すこと——記録の全行を抱えない。1 回の書き込みから持つのは 5,000 行まで。
- 読むのは **blame を引くスレッド**（エディタは背景から呼ぶ。開いたとき・保存したときに 1 回）。UI スレッドでは、
  すでに読んだものを引くだけ（押した行・変わった場所の一覧）。打鍵の経路には何も足さない（§31.15）。
- 実測（Loomo 自身のワークスペース、記録 24 件）: 最初の 1 回が約 0.8 秒、以降は git の blame 込みで 60〜90ms。
- エディタの `EditorBlameLine` は文字列と整数 1 つしか運べないので、ハッシュの欄に印 `Claude`（16 進ではないので
  コミットのリンク・差分の経路には乗らない）、元の行番号の欄に索引の取っ手（`HandleOf`／`FromHandle`）を入れる。
  エディタのパッケージは変えていない。

## §43.5 既知の穴

- **Write で丸ごと書き直したファイル**は、前の書き込みが足した行も新しい Write のものになる（Write には置換前が無い）。
- **ツールを通さない変更**（`sed`・整形・生成スクリプト・`git checkout`）は記録に中身が無いので結べない。
- **人間が Claude と同じ行を打った**場合は Claude のものになる（中身で合わせる以上、見分けられない）。
- **コミットすると消える**。コミット済みの行は git の blame のまま——次の段（§43.6 の A2a）で塞ぐ。
- 未保存の編集がある間はカーソル行の blame 自体が出ない（§24.42。行番号は保存してある版のもの）。
- 14 日より前・25 件目より古い記録の書き込みは結ばない。
- 画面は未確認（テストと、このセッション自身の記録を実データにした索引の確認まで）。

## §43.6 計画（「次の部屋」の 4 本）

2026-11-14 に「全部やってみる」と決めた 4 本。並びは §43.1 の数字が強く支えている順で、**上から 1 段ずつ**進める。
各段は「テスト → 実データ（Loomo 自身の記録）で確認 → 目視 → コミット」で閉じてから次へ行く。

### 次にすること（ここから再開する）

1. **第1段の目視とコミット**（人間の番）。`:Gblame` の欄・カーソル行の行末・右クリックの 3 項目・
   「変わった場所」の一覧から行へ飛ぶ、を実機で見る。直しが無ければ main にコミット。
2. **A2a に着手**（下記）。入口は `EditorGitService.GetBlameLines`——コミット済みの行のうち、最近のコミットの行を
   出自の入力に足すだけで、新しい保存先は要らない。
3. A2a が閉じたら A3（頼みごと単位の差分）。ここまでで「読む」動線が 1 本つながる。

### A. 出自（この章の続き）

| 段 | 何を | どう作る | 閉じる条件 |
|---|---|---|---|
| **A2a** | **コミットしても線を切らない**（第1段のいちばん大きい穴） | 行は中身で合わせているので、コミット済みでも同じやり方で結べる。blame の結果のうち**コミットの日時が索引の期間内（14 日）**の行を、コミットしていない行と同じく `Attribute` に通す。git の blame の行（作者・件名）は残し、頼みごとは**足す**（件名の後ろ、または右クリックの項目）——コミットの情報を上書きしない。Loomo の git 操作に手を入れないので、Claude がターミナルでコミットしても効く。 | コミット直後の行から「この頼みごとで変わった場所」へ行ける。コミットの差分・履歴の項目はこれまでどおり出る。`EditorBlameLine` に載せ切れなければ Editor パッケージに欄を足す。 |
| **A2b** | **記録が消えても残す** | Claude Code は古い記録を消す（既定 30 日）。結んだ結果（コミット → 頼みごとの本文・セッション ID・ターンの位置）を小さく保存する。置き場所は未決：`%APPDATA%/Loomo` の SQLite（**推し**。人のリポジトリに書かない）か git notes（リポジトリと一緒に動くが、頼まれずに ref を増やす）。 | 30 日より前のコミットの行でも頼みごとが出る。保存は背景（§31.15）。 |

### C. 軌跡の二声化

- **何を**: 軌跡に「自分がいない間に部屋で起きたこと」の段を足す——ターンの終わり・書き込んだファイル・承認待ち。
  人間の点（§27.1）とは**段を分け**、混ぜない（デデュープ・現在地・スクラブは人間の点だけのもの）。
- **材料**: 記録（`ClaudeSessionFollower`）とフック（§38.4）。新しい `TrailEntryKind` は末尾に足す（数値で保存）。
  戻り先は A3 の差分（頼みごと単位）——だから **A3 の後**。
- **先に決めること**: 留守中のまとめ（§24.22）・この日のまとめ（§24.23）・展開ビュー（§27.14）との重なり。
  まとめのカードの中身を軌跡の段から引く形にして、数え方を 1 つにする。§27.1 の非目的の書き直しも要る。
- **閉じる条件**: 戻ってきたとき、時間の軸で「頼んだ → Claude が書いた → 自分が見た」が 1 本で追える。

### D. 部屋を Claude から使う

- **何を**: Loomo が MCP サーバーとして、Claude が**人間の前に物を置く**道具を出す——「このファイルのここを開く」
  「この 2 つを並べる」「この差分を開く」「この URL をブラウザペインで」（§19.5 の「AI への開く指示」）。
- **線引き（先に合意する）**: 主役は人間（§38.1）。Claude は置くだけで、見えるターミナルには打たない・タブを閉じない・
  配置を壊さない（開く先は既定の振り分けに従う）・フォーカスを奪わない（袖のバッジと通知で知らせる）。
- **作り方の当たり**: IDE 連携（§38.2）の口はモデルに見えるツールが限られる（§38.7）ので、別の MCP サーバーとして
  立て、Loomo のターミナルの環境変数で渡す。`loomo://`（§24.59）のリンクを開く口と中身を共有する。
- **閉じる条件**: Claude の返事の「ここを見てください」が、返事を読む前に部屋に出ている。

### B. 作業を単位にする

課題×ワークツリー×セッション×配置を 1 つに束ねる。§43.1 の並行（ほぼ 1〜2）では効きが小さいので最後。
C・D が入って並行が増えたら測り直し、3 本以上が日常になっていたら着手する。それまでは個別の機能
（§24.17・§24.56・§38.8・§24.55）のまま。

### 測り直し

各段を閉じたら、§43.1 と同じ測り方で 2 週間後に見る——blame の右クリックの 3 項目・Diff ペインへの切替・
（C の後は）軌跡の Claude の段から戻った回数。使われていなければ外す（2026-11 の機能整理と同じ物差し）。
測るための記録点（パレットの履歴と同じく、出自の項目を押した回数）は A2a のときに足す。
