## §44.1 なぜ

§43 は「いまの使い方」を測って、足りない線を足す章だった。この章は測った使い方から逆算しない——**部屋が何に化けられるか**
から描く（2026-11-15 の合意。既存の機能・既存の使い方・この PC の実測に寄せて出した案は 4 回続けて外れた）。

書くのが Claude になったいま、変えられるのは 3 つ：

| 何が変わるか | いま | 次 |
|---|---|---|
| **道具の増え方** | 機能を 1 つずつ本体に作り込み、ビルドし、使われなければ刈る（§24 は 108 節・2026-11 に刈った） | 頼むとViewerが生える。再ビルドしない。使わなければ枯れる（§44.2） |
| **変更の読み方** | 行の赤と緑 | 前と後の**動き**——出力・テストの成否・画面の絵。行は潜ったときだけ（§44.3） |
| **仕事の始まり方** | その場で頼む | 常設の**言いつけ**。部屋が裏で進め、人間は採るか捨てるか（§44.4） |

3 つは独立に使えるが、作る順は **1 → 2 → 3**：2 の見せるViewerは 1 の上に生やし（API が足りるかの試金石）、3 は「テストが落ちたら」の
きっかけと、採る前に読む材料を 2 から借りる。

なお §43.1 の「同時に動いていたセッションはほぼ 1〜2」は**この PC の記録だけ**の数字で、使い手は別の PC で Claude Code を
複数起動して順繰りに回している。§43.6 B を後回しにした根拠は弱い（B 自体はこの章では扱わない）。

## §44.2 生えるViewer

### 何が起きるか

ターミナルの Claude に「ポートを握っているプロセスの一覧がほしい」と言う → Claude が小さな HTML を書く → 部屋に
そのViewerが出る。Loomo は再ビルドも再起動もしない。Viewerを書き直せば、開いているViewerがその場で読み直る。

`アイデア.md` の候補（Transform Tray・Encoding Inspector・Process Tree / Port Inspector）はどれも「小さい道具」で、
本体に 1 つずつ作り込むと §24 と同じ道をたどる。これらを**本体に入れず、生やす**のが最初の使い道。

### Viewerの実体

- 置き場所は `%APPDATA%/Loomo/viewers/<id>/`。中身は `viewer.json`（題・説明・使う API・決まったコマンド）と `index.html`
  （と、その隣の css／js）。**ワークスペースの中には置かない**——人のリポジトリに頼まれずにファイルを増やさない
  （§43.2.4 で git notes を採らなかったのと同じ理由）。リポジトリと一緒に持ち歩くViewer（`.loomo/viewers/`）は使われてから。
- Viewerは WebView2 で動く（`LoomoWebView2`）。オリジンはViewerごとに `https://<id>.viewer.loomo/`。`file.loomo`（ローカルの HTML は
  すべて同じオリジン）とは**別**にする——ブラウザペインで開いた手元の HTML や、ネットのページから部屋の API に届かせない。
- 出る場所は新しいペイン「Viewer」（`PaneKind.Viewer` を**末尾に**足す。数値で保存しているため）。Viewer 1 つ＝タブ 1 つ。
  ペインなのでドック・分割・切り離しはほかと同じに効く。サイドバーへ置くのは第 2 段。

### 部屋の API（`window.loomo`）

Viewerのオリジンにだけ差し込む（`AddScriptToExecuteOnDocumentCreatedAsync`）。中身は `postMessage` の往復で、答えは Dispatcher を通す。

| 口 | 中身 | 線引き |
|---|---|---|
| `workspace.folders()`・`workspace.activeFile()` | フォルダーの一覧・前に出ているファイルと行 | 読むだけ |
| `open(path, line)`・`openUrl(url)`・`openDiff(…)` | エディタ／ブラウザの新しいタブ／Diff に出す | MCP の `show_*`（§43.6 D）と同じ中身。ここは人間がViewerを押した結果なのでフォーカスは移してよい |
| `fs.read(path)`・`fs.list(dir)` | ワークスペースの中のファイルを読む | `workspace.Contains` の中だけ。**書く口は出さない**（第 1 段） |
| `git.status()`・`git.repositories()` | `GitWorkspaceStatus` を引くだけ | `git status` を新しく起こさない（§40） |
| `run(name, args)` | `viewer.json` に**名前つきで書いてあるコマンド**を裏で回し、出力を流す | 見えるターミナルには打たない（`RunCommandAsync`・`ChildProcessIo`）。書いていないコマンドは回せない |
| `state.get/set` | Viewerごとの小さな置き場（JSON） | Viewerのフォルダーの外へ書かない |
| `on(event)` | `fileSaved`・`activeFileChanged`・`gitChanged`・`commandFinished` | UI スレッドで重いことをしない（§31.15） |
| `toast(text)` | 通知欄へ | — |

**許すのは人間**：Viewerを初めて出すとき、`viewer.json` が挙げた API とコマンドの行をそのまま見せて 1 回だけ聞く。`viewer.json` が
変わったら（指紋が変わったら）聞き直す。`index.html` の書き直しでは聞かない——できることの上限は `viewer.json` が決める。

**聞くのは `run`・`net`・`motion`・`orders` を挙げたViewerだけ**（2026-11-15 に変えた）。`workspace`・`open`・`fs.read`・`git` だけの
Viewerは読むか人間の前に置くだけで、外へも出られない——書いたのは Claude Code 自身の Write でそちらの権限を通っており、Viewerの側で
増える力が無いので、聞かずに開く（「頼むと生える」の手触りを毎回の許しで削らない）。逆に `run` は残す：Claude Code の権限で
止められたコマンドでも `viewer.json` に書くだけで裏で回せてしまう（実際に 1d の確認で起きた）ので、ここが人間の唯一の関所になる。
`net` は `fs.read` で読んだ中身を外へ送れるので同じ側。許さずに使える口は `ViewerApi.WithoutApproval` に一覧で持ち、新しい口は
足した時点では聞く側に入る。

### 生やし方

- MCP に道具を 2 つ足す：`viewer_guide`（Viewerのフォルダーの場所・`viewer.json` の形・API の一覧を返す）と `show_viewer(id)`
  （そのViewerを「Viewer」ペインに出す。フォーカスは奪わない）。ファイルを書くのは Claude Code 自身の Write——Loomo は書く道具を出さない。
  - AGENTS.md の「人間の前に物を置く道具だけ」の一文は、この 2 つを足すときに書き直す（`show_viewer` は置く道具、
    `viewer_guide` は読むだけ）。
- 人間の側の入口はパレット「Viewerを開く…」（一覧から）と「Viewerを生やす…」（Claude への頼みごとの下書きをクリップボードへ）。
- 開いているViewerのフォルダーは見張り、保存されたら読み直す（`LocalPageWatcher` と同じ作り＝読んだファイルの親を非再帰で）。

### 枯れ方

Viewerを開いた回数を日別に数える（`ProvenanceUsageLog` と同じ形）。30 日開かなかったViewerは一覧の「枯れたViewer」へ下げる
（消さない。開けば戻る）。捨てるのは人間が一覧から。**本体の機能を刈った物差しを、Viewerには最初から組み込む。**

### 段と閉じる条件

| 段 | 何を | 閉じる条件 |
|---|---|---|
| **1a** | Viewerのホスト：`viewers/` を読む・Viewerごとのオリジンで答える・「Viewer」ペイン・タブ・復元・保存で読み直す | 手で置いた `index.html` がViewerとして出て、再起動しても戻る |
| **1b** | `window.loomo` の読む口と開く口（`workspace`・`fs.read`・`git`・`open*`・`state`・`on`・`toast`）、許しのカード | テスト用のViewerから全部の口を呼べる。Viewerでない頁（`file.loomo`・ネット）からは 1 つも呼べない |
| **1c** | `run`（名前つきのコマンド）と出力の流し込み | `viewer.json` に無いコマンドは断られる。出力が流れる途中でViewerを閉じたら子を止める |
| **1d** | MCP の `viewer_guide`・`show_viewer`、パレットの入口、枯れ方の記録 | **本物の claude に頼んで、Loomo を再ビルドせずに「ポートとプロセス」のViewerが生える**（`アイデア.md` の 1 件目） |
| **2** | サイドバーに置けるViewer・切り離し・`fs.write`（要るなら）・リポジトリと一緒に持ち歩くViewer | 1d で生やしたViewerが 2 週間後も開かれていたら |

### 入ったもの（第 1 段・2026-11-15）

計画どおりに入ったもの：Viewerの置き場と定義（`viewer.json`）・Viewerごとのオリジン・「Viewer」ペイン（`PaneKind.Viewer`・ドックの既定は右）・
タブ・`window.loomo`・許しのカード・名前つきのコマンド・保存で読み直す・MCP の `viewer_guide`／`show_viewer`・パレット
（「Viewerを開く：〈題〉」「Viewerを生やす頼みごとの下書きをコピー」）・枯れたViewer（「＋」のメニューで下へ分ける）。

計画から変えた・足したこと：
- **口に `net` を足した。** 挙げていないViewerのページは、Viewerのフォルダーの外への要求を全部断られる（CDN のスクリプトも `fetch` も）。
  `fs.read` で読んだ中身をそのまま外へ送れてしまうので、ネットワークも人間が許す口にした。
- **Viewerから渡る値は `$env:LOOMO_ARG_n` と変数 `$LoomoInput`。** 標準入力を `$input` で読ませる形は、PowerShell がコンソールの
  コードページ（cp932）で読んで日本語が化けた（起動後に `InputEncoding` を変えても効かない）。先に UTF-8 で読み切って変数に入れる。
- **読み込むのは、ペインが見えていて前に出ているViewerだけ。** 隠れたペインの中では WebView2 の初期化が終わらず、待つと `show_viewer` が
  返らなかった（実機で 60 秒のタイムアウト）。許しが済んでいれば「出せる」とだけ答え、読み込みは見えたときに回す。
- **コマンドの出力の行は、答えと同じ優先度でまとめて流す。** 背景の優先度で流すと、最後の行が答え（`Promise` の解決）より後に届いた。
- 部屋の色は CSS 変数（`--loomo-bg`・`--loomo-panel`・`--loomo-fg`・`--loomo-fg-dim`・`--loomo-accent`・`--loomo-border`・
  `--loomo-font-size`）で渡す。読み込みのたびに、いまのテーマで作り直す（開いたままテーマを替えたら、次の読み込みから）。
- 開いているViewerと許した指紋は、部屋ごとではなく PC ごと（`%APPDATA%/Loomo/viewers-state.json`）。Viewerのフォルダーの中には置かない
  ——Viewerを書く Claude が自分で自分を許せてしまう。
- 出来事は `activeFileChanged` と `gitChanged` の 2 つだけ（`fileSaved`・`commandFinished` は使うViewerが出てから）。
- Claude がViewerを出すとき（`show_viewer`）は §43.6 D と同じ線：フォーカスを奪わない・隠れているペインを出すための並べ替えをしない
  （出ていなければ通知にそう書く）。人間がViewerの中で押した結果（`loomo.open`）はフォーカスが移ってよい。

実装: `Loomo.Core/Viewers/ViewerManifest.cs`（定義・指紋・`ViewerUrl`）、`Loomo.Services/Viewers/ViewerStore.cs`（置き場・`ViewerRoomState`）、
`Loomo.Services/Viewers/ViewerRoomApi.cs`（口の線引き・`ViewerCommandRunner`・`ViewerGuide`）、`Loomo.App/Services/Viewers/ViewerTabHost.cs`
（Viewer 1 つ＝WebView2 1 つ・橋のスクリプト）、`Loomo.App/Views/Viewers/ViewerPaneView.cs`（タブ・カード）、
`Loomo.App/Views/Shell/Activity/ShellWindow.Viewers.cs`（部屋の側の受け口）。テスト: `ViewerTests`。

確かめたこと（Release 構成の Loomo を試験用のワークスペースで起こして）：
- 手で置いたViewerが出る・再起動しても開いていたViewerとペインが戻る・許し待ちのViewerはカードが出てページは読み込まれない。
- 点検用のViewerから全部の口を呼べる（フォルダー・前に出ているファイル・読む・一覧・Git の状態・コマンド＋引数＋日本語の入力・置き場）。
  ワークスペースの外の読み出し・書いていないコマンド・ネットワーク・`file.loomo` は断られる。
- **本物の `claude -p` に「Loomo にViewerを生やして：いまポートを握っているプロセスの一覧…」と頼むと、再ビルドなしで「ポート」のViewerが生えた**
  （`viewer_guide` → Write → `show_viewer`。許しのカード → 許す → 一覧が出る）。このViewerは `%APPDATA%/Loomo/viewers/ports/` に残してある。

未確認：タブをマウスで押す・閉じる、「＋」のメニュー、保存での読み直し（見張りは入れたが実機では見ていない）、切り離した窓、
テーマを替えたあとの色、`activeFileChanged`／`gitChanged` がViewerに届くこと、パレットの項目。

### パスから開く（2026-11-21）

呼び名を「面」から **Viewer** に改めた（画面・コード・置き場 `viewers/`・定義 `viewer.json`・オリジン `*.viewer.loomo`・MCP の
`show_viewer`／`viewer_guide`。使っているデータが無いので互換は取らない。`PaneKind` は名前だけ変え、保存している数値は据え置き）。

**何が起きるか**：人は Viewer に**パスか URL を渡すだけ**。見せ方は Loomo が決める。`viewer.json` を人が書くことは無い。

| 渡したもの | 出方 | 部屋の API |
|---|---|---|
| `.html`・`index.html` のあるフォルダー | 頁のまま（フォルダーごとのオリジン `https://p<指紋>.page.loomo/`）。フォルダーが書き換わると読み直す | 無し。**ネットにも出さない**（頁は同じフォルダーのファイルを読めるので、外へ出られると隣の書類や `.git/config` を送れてしまう。外向きの要求・WebSocket・WebRTC・外への iframe を止める。2026-11-21 のレビューで直した） |
| EditorSupport が見せられる形式（PDF・画像・Markdown・CSV・Excel…） | EditorSupport と同じ表示（読むだけ。表の編集は書き戻さない）。ファイルが書き換わると描き直す | 無し |
| `.exe` | 起動して、出てきた窓をタブの場所に重ねる | 無し |
| URL（http/https） | ブラウザペインと同じプロファイルの WebView2 で、その頁をタブに出す | 無し |
| 見せ方の決まっていないテキスト | エディタ（Diff と同じ LSP なしの部品）に**読むだけ**で出す。上の帯に「エディタで開く」「Claude Code に見せ方を作ってもらう」 | — |
| 見せ方の決まっていないバイナリ | Hex（EditorSupport のバイナリの受け皿）。右クリックから「Claude Code に見せ方を作ってもらう」 | — |
| 上の 2 つで、その拡張子の Viewer を作ってあるとき | 作った Viewer（id は `file-<拡張子>`、フォルダーは `file-folder`）。`loomo.target.*` で渡したパス 1 つだけを読む | `target`（許し不要）＋作った Viewer が挙げたもの |

**作ってもらう**：裏の `claude -p`（作業フォルダー＝**その Viewer のフォルダーだけ**、自動で許す道具は Read・Glob・Grep、書き込みは
`acceptEdits` が作業フォルダーの中だけ受け入れる、シェル・ネットは渡さない）に、対象の
ファイルの頭（テキストは 6000 字・バイナリは 512 バイトの 16 進）と `viewer_guide` の中身を貼って頼む。対象のファイルは道具で
読ませない——読める範囲（`--add-dir`）を広げると、受け入れ済みの書き込みも人のリポジトリへ届いてしまう。作業フォルダーを置き場
全体にすると、ファイルの中身に仕込まれた頼みで許し済みの別の Viewer（動き・言いつけ）の頁を書き換えられる（頁の書き直しでは許しを
聞き直さない）ので、そのフォルダーだけにした（実機の `claude -p` で、隣の Viewer への書き込みが断られることを確かめた）。成功は
「終了コード 0・定義と頁が読める・フォルダーの中身が書き換わった」の 3 つで判断する（作り直しでは古い定義が残っているため）。拡張子ごとに 1 つ作り、
同じ種類のファイルは次から待たずにそれで開く。タブの右クリック「Viewer を作り直す…」で一言を添えて直させられる。`run`・`net` を
挙げた Viewer ができたときだけ、これまでどおり許しのカードで聞く（関所は残る）。**勝手には作らない**——テキストはまずエディタで
出し、作るのは人が頼んだとき（フォルダーも、作るかを聞くカードを出すだけ）。

**プログラムの窓の重ね方**：子にしない（`SetParent`）・持ち主にもしない。別プロセスの窓と親子／持ち主の関係を結ぶと入力のキューが
つながり、相手が固まると Loomo も固まるため。枠（タイトルバー・リサイズ枠）を外して、ペインの位置と大きさに合わせ続ける
（100ms ごとに見て、変わったときだけ動かす）。タブが隠れたら隠し、Loomo が最小化されたら隠す。重なり順は**Loomo が前に出ている間
だけ最前面**にし、Loomo が裏へ回ったら最前面を外して Loomo のすぐ上へ戻す（他のアプリより前には残さない）——Windows は前面の窓
より上へよそのプロセスの窓を並べ替えさせず、`HWND_TOP` は成功を返しても上がらなかった（実機で確認）。PowerToys の Always On Top
と同じ手。相手が固まっているとき（`IsHungAppWindow`）は位置合わせも並べ替えも相手のスレッドに預ける。Loomo が起動したものは
タブを閉じる・Loomo を終えると `CloseMainWindow` で終わらせる（保存の確認は相手に任せる）。復元したタブは勝手に起動しない
（「起動する」のカード）。

**入口**（手順）：
1. Viewer ペインの「＋」→「パスを指定して開く…」／TABS の「＋」→「新しい Viewer…（パスを指定して開く）」／パレット
   「パスを指定して Viewer で開く…」／ファイルツリー・ファイル一覧・エディタのタブの右クリック「ペインへ送る ▸ Viewer」／
   エディタ・ターミナルで選んだ文字がいまあるパスなら「ペインへ送る ▸ Viewer（名前）」／Viewer ペインへのドロップ。
2. 入力欄にパスか URL。下の 1 行に、どう出すつもりかが出る（例「テキストとしてエディタに出します（読むだけ…）」）。Enter で開く、
   Esc でやめる。「ファイルを選ぶ…」「フォルダーを選ぶ…」でも渡せる。
3. タブが増え、TABS の「Viewer」にも同じ行が並ぶ（題はファイル名、ツールチップはパスと見せ方）。
4. 再起動すると並びが戻る（鍵は `path:<フルパス>`・`url:<URL>`・置き場の Viewer は id）。
5. タブの右クリック：閉じる・他のタブを閉じる・別ウィンドウで開く・作り直す／作ってもらう・パス（URL）をコピー・エクスプローラーで表示。

**別ウィンドウ**：Viewer のタブはそのまま切り出せる（ペインから外して窓へ移す。戻すのは窓のタブを Viewer ペインの見出しへ落とす）。
WebView2 は窓をまたいで載せ替えると空表示になるので、移るたびに中身を作り直す（`IViewerTab.Rehost`）。切り出した窓も部屋の
スナップショットに乗り、起動時に戻る（`DetachKind.ViewerMove`、プログラムは起動しない）。

実装: `Loomo.App/Services/Viewers/`（`ViewerTargets`＝見せ方の決め方・`ViewerTabFactory`・タブ `ViewerPageTab`／`ViewerPreviewTab`／

## §44.3 動きで読む

### 何が起きるか

頼みごとの差分（§43.2.2）を開くと、行の前に**動きの前後**が出る：「テスト 2 件が通る → 落ちる」「`--help` の出力に 1 行増えた」
「この画面のここが変わった（前後の絵を重ねて）」。行の差分はその下。動きが変わっていない変更は「動きは同じ」と 1 行で済む。

### 見どころ（何の動きを見るか）

ワークスペースごとに決める（`%APPDATA%/Loomo/workspaces/` の側。リポジトリには書かない）。種類は 3 つ：

- **コマンド**：決まったコマンドの出力と終了コード。
- **テスト**：成否の一覧（`dotnet test` の TRX は §28 の読み方をそのまま。ほかのランナーは `アイデア.md` の「多言語化」と一緒に）。
- **絵**：URL（隠れた WebView2 で開いて `CapturePreviewAsync`）か、PNG を出すコマンド（WPF は View を単体で描く手法がある）。

見どころを足すのも Claude に頼める（「この画面を見どころにして」）——定義はViewerの API 越し。

### 前の動きはどこから来るか

**組み直さず、録っておく。** 頼みごとの前の状態を別のワークツリーに組んでビルドし直す手は、Loomo 自身で数分かかる。
代わりに Claude のターンが終わるたび（フックの Stop・§38.4）に、作業ツリーで見どころを裏で回して**その時点の動き**を録る。
「前」は 1 つ前に録ったもの。

- 回すのは裏（`ChildProcessIo`）。回している間に作業ツリーが変わったら、その回は捨てる（混ざった動きを録らない）。
- 重い見どころ（全テスト）は「手で」か「言いつけ（§44.4）で」に回せる。ターンごとに回すのは軽いものだけ。
- 録ったものは `%APPDATA%/Loomo/motion.db`（SQLite）と絵のフォルダー。鍵は頼みごと（セッション・頼みごとの行＝§43 と同じ）。
- 録り始める前の頼みごとには動きが無い——無いものは無いと言う（空の欄を見せない）。

### 見せ方

- **記録は本体、見せるViewerは §44.2 で生やす**（API に `motion.of(request)` を足す）。足りなければ本体へ戻す——その判断が
  1 の API の試金石になる。
- 絵の比べ方は 3 つ：並べる・重ねて透かす・違う所だけ塗る。
- 入口は頼みごとの差分を開く所ぜんぶ（blame の右クリック・ターミナルサポートのターン・軌跡の Claude の段・MCP の `show_changes`）。

### 段と閉じる条件

| 段 | 何を | 閉じる条件 |
|---|---|---|
| **2a** | 見どころの定義・ターンの終わりに録る・`motion.db`（コマンドとテスト） | Loomo 自身で、テストを 1 件落とす頼みごとのあとに「通る → 落ちる」が出る |
| **2b** | 絵の見どころ（URL・PNG を出すコマンド）と 3 つの比べ方 | View を 1 つ変える頼みごとの前後の絵が重なって出る |
| **2c** | 動きから行へ潜る（入れ替わったテスト → その頼みごとの、そのテストに近い書き込み） | 落ちたテストから 2 手以内で犯人の行に着く |

### 入ったもの（第 1 段・2026-11-15）

計画から変えた・足したこと：
- **置き場は SQLite ではなくフォルダー**：`%APPDATA%/Loomo/motion/<鍵>/`（`probes.json`・`snapshots/<時刻>/snapshot.json` と絵）。
  絵を隣に置くため。鍵は主フォルダーのパスから作る（部屋の ID ではない）。200 件を超えたら古いものから刈る。
- **見どころの定義もリポジトリの外**（上の `probes.json`）。行を人間が 1 回許す（パレット「動き：見どころを許す」で行をそのまま見せる。
  許しの指紋は `motion/approved.json`——Viewerと同じく、定義を書く Claude が自分で許せないように）。行が変わったら聞き直す。
  書くのはパレット「動き：見どころを編集」（ひな形を置いてエディタで開く）か、Claude（MCP の `motion_guide` が置き場所と形を返す）。
- **見どころの種類**：`command`（出力と終了コード）・`tests`（`$env:LOOMO_OUT` に書かれた TRX／JUnit の成否）・`image`（同じく PNG）。
  `ignore` の正規表現に当たる行は比べる前に落とす（所要時間・日時）。`when` は `turn`（既定）か `manual`。
- **ターンの終わりに録り直さない場合**：前に録ってから作業ツリーの印（HEAD と `git status --no-optional-locks`）が同じ。
  回している間に印が変わったら、その回は捨てる。録るのは同時に 1 つで、録っている間に終わったターンは、終わってから 1 回だけ録り直す。
- **頼みごとの結び方**：ターンが終わったタブのセッションと、出自の索引（§43）のいちばん新しい書き込みが同じセッションなら、その頼みごと。
  ファイルを書き換えないターン・Bash だけで変えたターンには頼みごとが付かない（動きは録る）。
- **見せ方は本体に作らず、本体が置くViewer「動き」として生やした**（`BuiltInViewers`。§44.2 の口に `motion` を足しただけで足りた＝試金石は通った）。
  一覧（時刻・頼みごと・1 行のまとめ）→ 押すと詳細（出力の前後の差分・テストの入れ替わり・絵の 並べる／重ねる（透かしのつまみ）／違う所を塗る）。
  頼みごとが結ばれていれば「この頼みごとの差分を開く」（§43.2.2）。
- **知らせ**：ターンの終わりに録った動きが変わっていたら通知（「動きが変わりました：テスト：1 件が落ちるようになった」）。
- 「動きから行へ潜る」（2c）は、詳細の「この頼みごとの差分を開く」まで。落ちたテストに近い書き込みを選んで開くところは入れていない。

実装: `Loomo.Core/Motion/Motion.cs`（見どころ・テスト結果の読み方・比べ方）、`Loomo.Services/Motion/MotionStore.cs`（置き場・許し・
`MotionRecorder`・`MotionGuide`）、`MotionService.cs`（同時に 1 つ・ターンの終わりの取りまとめ）、`Loomo.Services/Viewers/BuiltInViewers.cs`（Viewer）、
`Loomo.App/Views/Shell/Activity/ShellWindow.Motion.cs`（ターンの終わり・パレット・Viewerの口）。テスト: `MotionAndOrderTests`。

確かめたこと（Release 構成の Loomo を試験用のリポジトリで起こし、Viewerから口を呼んで）：手で録る → ファイルを変える → 録ると
「数える：出力が変わった／テスト：1 件が落ちるようになった」が一覧に出て、行を実際のマウスで押すと出力の差分（− 0 ＋ 2）と
「passed → failed small」が出る。**未確認**：ターンの終わりに録る経路（本物の Claude をそのタブで動かしていない）・通知・絵の見どころ・
パレットの項目。

## §44.4 言いつけ

### 何が起きるか

部屋に常設の言いつけを置く：「テストが落ちたら、直す案を作っておく」「上流が動いたら、取り込んで試しておく」
「毎朝、依存の更新を試しておく」。部屋は裏のワークツリーで Claude を動かし、仕上がりを**盆**に並べる。
人間は盆の 1 件を開いて、動き（§44.3）と差分を読み、**採る**か**捨てる**。

### 作り

- 言いつけ＝名前・きっかけ・頼みごとの本文・対象のリポジトリ・上限（時間・1 日の回数）。置き場所は `%APPDATA%/Loomo/orders.json`。
- **きっかけ**：手で／時刻・間隔／見どころの入れ替わり（§44.3 の「通る → 落ちる」）／裏の fetch で上流が動いた（§24.92）。
- **走らせ方**：`git worktree add`（置き場所は `%LOCALAPPDATA%/Loomo/orders/`）→ そこで Claude Code を対話なしで起こす
  （見えるターミナルではなく裏のプロセス。許す道具は言いつけごとに絞る）→ 終わったらブランチ `loomo/order/<名前>/<日時>` に
  コミットを残し、要約と動きを録る。Claude Code の対話なしの起こし方・許可の渡し方は版で変わるので、着手時に CHANGELOG と
  ドキュメントで確かめてから決める（§38 と同じ進め方）。
- **盆**：仕上がりの一覧（言いつけ・いつ・要約・動きが変わったか）。1 件ごとに「開く（動きと差分）」「採る（いまのブランチへ
  取り込む。衝突の予告＝§24.88 を先に出す）」「捨てる（ワークツリーとブランチを消す）」「ワークツリーを部屋として開く」。
  盆も §44.2 のViewerとして生やせるかを先に試す。

### 線引き

- **人間の作業ツリーには書かない。** 採るまでは裏のワークツリーの中だけ。push もしない。
- 同時に走るのは 1 本（既定）。Loomo が動いている間だけ（常駐ホスト＝§34 に持たせるのは使われてから）。
- 使用量（§38 のコンテキスト量・`ClaudeUsageSource`）が決めた線を越えていたら走らせない。走った回数と使った量は盆に出す。
- 走っていること・終わったことは袖と「動いているもの」Viewer（§24.54）に出す——頼んでいない物音を立てない。

### 段と閉じる条件

| 段 | 何を | 閉じる条件 |
|---|---|---|
| **3a** | 言いつけの定義・手のきっかけ・裏のワークツリーで走らせる・盆（開く／捨てる） | 手で起こした言いつけの仕上がりが盆に出て、作業ツリーは 1 バイトも変わっていない |
| **3b** | 採る（衝突の予告つき）・時刻と間隔・使用量の線 | 一晩置いた言いつけの案を、朝に 1 件採れる |
| **3c** | 見どころの入れ替わり・上流の動きをきっかけに | テストを落とすコミットのあと、頼まずに直す案が盆に出る |

### 入ったもの（第 1 段・2026-11-15）

- 言いつけ＝名前・頼みごと・きっかけ（手で／毎日この時刻に／動きが悪い方へ変わったら）・許す道具・1 日の回数（既定 3）・期限（既定 30 分）。
  置き場は `%APPDATA%/Loomo/orders/<鍵>/orders.json`、盆は同じ場所の `results.json`（50 件まで）。
- **走らせ方**：`git worktree add -b loomo/order/<名前>/<時刻>`（置き場所は `%LOCALAPPDATA%/Loomo/orders/<鍵>/`）→ そこで
  `claude -p --output-format text --permission-mode acceptEdits --allowedTools <許す道具> --disallowedTools "Bash(git push:*)"`
  （頼みごとは標準入力で渡す。`LOOMO_TERMINAL_TAB` などの印は外す＝裏の Claude は人間の画面に物を置けない）→ 終わったら
  Loomo が `git add -A` と commit（名前は Loomo）→ 変わったファイルの数と、Claude の返事（まとめ）を盆に。
  **許す道具の既定は Read・Edit・Write・Glob・Grep**（シェルは渡さない）。広げるのは `orders.json` の `Tools` を手で。
- 変更なしで終わったらワークツリーとブランチを消して「変更なし」とだけ残す。git の外のワークスペースでは「失敗」。
- 仕上がりのワークツリーで、許された見どころを全部回して動きを録り、いまの作業ツリーの最新の動きと比べた 1 行を添える。
  **比べる相手は作業ツリーの最新**なので、人間の未コミットの変更が混じる（試験では、仕上がり側に無い未追跡のファイルのぶん
  「1 件が通るようになった」と出た）。
- **採る**：まず従来形式の `git merge-tree <元> HEAD <仕上がり>` で衝突を予告し、ぶつかるならファイルを挙げて何もしない。
  ぶつからなければ `git cherry-pick --no-commit`（作業ツリーとインデックスに当てる・コミットはしない）→ ワークツリーとブランチを消す。
  この PC の git は 2.35 で `merge-tree --write-tree` が無いため、§24.88 と同じ従来形式の読み方（`GitMergeTreeParser.ParseLegacyConflicts`）。
- **捨てる**：ワークツリーとブランチを消し、盆から外す。
- **きっかけ**：毎分、時刻の来た「毎日」の言いつけを 1 つ進める。ターンの終わり・手で録った動きが悪い方へ変わったら（テストが落ちるように
  なった・終了コードが 0 から外れた）、きっかけが「動き」の言いつけを、変化の 1 行と落ちたテスト名を頼みごとに添えて進める。
  自動のきっかけは、1 日の回数と 5 時間の使用量の線（80%。`claude-usage.json` の保存値を読むだけ）の内側でだけ。
  同時に走るのは 1 本・Loomo が動いている間だけ。起動したとき、前の Loomo が途中で終わった言いつけは「失敗」にする。
- 見せ方は本体が置くViewer「言いつけ」（盆：まとめ・動き・差分を開く・採る・捨てる／言いつけ：足す・いま進める・外す）。
  差分は Diff ペインのコミット範囲（元 → 仕上がり）。
- 上流の動き（裏の fetch）をきっかけにするのは入れていない。

実装: `Loomo.Core/Orders/StandingOrder.cs`、`Loomo.Services/Orders/OrderService.cs`（走らせる・採る・捨てる・`RunClaudeAsync`）、
`ShellWindow.Motion.cs`（きっかけ・使用量の線・Viewerの口）。テスト: `MotionAndOrderTests`（裏の Claude は差し替え。本物の git で、
人間の作業ツリーが変わらない・採ると当たる・ぶつかるなら断る・捨てる・変更なしは片付ける・同時に 1 本）。

確かめたこと：試験用の Loomo のViewerから言いつけを置いて「いま進める」→ **本物の `claude -p` が裏のワークツリーで readme.txt に 1 行足し、
盆に「1 ファイル」とまとめが出て、人間の作業ツリーは変わっていなかった**（2 本目は「進めている最中です」で断られた）。Viewerから採ると
作業ツリーに当たり（コミットはしない）、ワークツリーとブランチが消えた。**未確認**：時刻と動きのきっかけ・使用量の線・衝突の予告の画面・
差分を開く。
