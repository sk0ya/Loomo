> 作成日: 2026-11-15 / 状態: **§44.2 生える面の第 1 段（1a〜1d）実装済み**・§44.3／§44.4 は計画。

> ローカルの HTML を開く口（`https://file.loomo/…`）は §21.5.1／§24.45、裏でコマンドを回す口は `TerminalService.RunCommandAsync`、

## §44.1 なぜ

§43 は「いまの使い方」を測って、足りない線を足す章だった。この章は測った使い方から逆算しない——**部屋が何に化けられるか**
から描く（2026-11-15 の合意。既存の機能・既存の使い方・この PC の実測に寄せて出した案は 4 回続けて外れた）。

書くのが Claude になったいま、変えられるのは 3 つ：

| 何が変わるか | いま | 次 |
|---|---|---|
| **道具の増え方** | 機能を 1 つずつ本体に作り込み、ビルドし、使われなければ刈る（§24 は 108 節・2026-11 に刈った） | 頼むと面が生える。再ビルドしない。使わなければ枯れる（§44.2） |
| **変更の読み方** | 行の赤と緑 | 前と後の**動き**——出力・テストの成否・画面の絵。行は潜ったときだけ（§44.3） |
| **仕事の始まり方** | その場で頼む | 常設の**言いつけ**。部屋が裏で進め、人間は採るか捨てるか（§44.4） |

3 つは独立に使えるが、作る順は **1 → 2 → 3**：2 の見せる面は 1 の上に生やし（API が足りるかの試金石）、3 は「テストが落ちたら」の
きっかけと、採る前に読む材料を 2 から借りる。

なお §43.1 の「同時に動いていたセッションはほぼ 1〜2」は**この PC の記録だけ**の数字で、使い手は別の PC で Claude Code を
複数起動して順繰りに回している。§43.6 B を後回しにした根拠は弱い（B 自体はこの章では扱わない）。

## §44.2 生える面

### 何が起きるか

ターミナルの Claude に「ポートを握っているプロセスの一覧がほしい」と言う → Claude が小さな HTML を書く → 部屋に
その面が出る。Loomo は再ビルドも再起動もしない。面を書き直せば、開いている面がその場で読み直る。

`アイデア.md` の候補（Transform Tray・Encoding Inspector・Process Tree / Port Inspector）はどれも「小さい道具」で、
本体に 1 つずつ作り込むと §24 と同じ道をたどる。これらを**本体に入れず、生やす**のが最初の使い道。

### 面の実体

- 置き場所は `%APPDATA%/Loomo/faces/<id>/`。中身は `face.json`（題・説明・使う API・決まったコマンド）と `index.html`
  （と、その隣の css／js）。**ワークスペースの中には置かない**——人のリポジトリに頼まれずにファイルを増やさない
  （§43.2.4 で git notes を採らなかったのと同じ理由）。リポジトリと一緒に持ち歩く面（`.loomo/faces/`）は使われてから。
- 面は WebView2 で動く（`LoomoWebView2`）。オリジンは面ごとに `https://<id>.face.loomo/`。`file.loomo`（ローカルの HTML は
  すべて同じオリジン）とは**別**にする——ブラウザペインで開いた手元の HTML や、ネットのページから部屋の API に届かせない。
- 出る場所は新しいペイン「面」（`PaneKind.Face` を**末尾に**足す。数値で保存しているため）。面 1 つ＝タブ 1 つ。
  ペインなのでドック・分割・切り離しはほかと同じに効く。サイドバーへ置くのは第 2 段。

### 部屋の API（`window.loomo`）

面のオリジンにだけ差し込む（`AddScriptToExecuteOnDocumentCreatedAsync`）。中身は `postMessage` の往復で、答えは Dispatcher を通す。

| 口 | 中身 | 線引き |
|---|---|---|
| `workspace.folders()`・`workspace.activeFile()` | フォルダーの一覧・前に出ているファイルと行 | 読むだけ |
| `open(path, line)`・`openUrl(url)`・`openDiff(…)` | エディタ／ブラウザの新しいタブ／Diff に出す | MCP の `show_*`（§43.6 D）と同じ中身。ここは人間が面を押した結果なのでフォーカスは移してよい |
| `fs.read(path)`・`fs.list(dir)` | ワークスペースの中のファイルを読む | `workspace.Contains` の中だけ。**書く口は出さない**（第 1 段） |
| `git.status()`・`git.repositories()` | `GitWorkspaceStatus` を引くだけ | `git status` を新しく起こさない（§40） |
| `run(name, args)` | `face.json` に**名前つきで書いてあるコマンド**を裏で回し、出力を流す | 見えるターミナルには打たない（`RunCommandAsync`・`ChildProcessIo`）。書いていないコマンドは回せない |
| `state.get/set` | 面ごとの小さな置き場（JSON） | 面のフォルダーの外へ書かない |
| `on(event)` | `fileSaved`・`activeFileChanged`・`gitChanged`・`commandFinished` | UI スレッドで重いことをしない（§31.15） |
| `toast(text)` | 通知欄へ | — |

**許すのは人間**：面を初めて出すとき、`face.json` が挙げた API とコマンドの行をそのまま見せて 1 回だけ聞く。`face.json` が
変わったら（指紋が変わったら）聞き直す。`index.html` の書き直しでは聞かない——できることの上限は `face.json` が決める。

### 生やし方

- MCP に道具を 2 つ足す：`face_guide`（面のフォルダーの場所・`face.json` の形・API の一覧を返す）と `show_face(id)`
  （その面を「面」ペインに出す。フォーカスは奪わない）。ファイルを書くのは Claude Code 自身の Write——Loomo は書く道具を出さない。
  - AGENTS.md の「人間の前に物を置く道具だけ」の一文は、この 2 つを足すときに書き直す（`show_face` は置く道具、
    `face_guide` は読むだけ）。
- 人間の側の入口はパレット「面を開く…」（一覧から）と「面を生やす…」（Claude への頼みごとの下書きをクリップボードへ）。
- 開いている面のフォルダーは見張り、保存されたら読み直す（`LocalPageWatcher` と同じ作り＝読んだファイルの親を非再帰で）。

### 枯れ方

面を開いた回数を日別に数える（`ProvenanceUsageLog` と同じ形）。30 日開かなかった面は一覧の「枯れた面」へ下げる
（消さない。開けば戻る）。捨てるのは人間が一覧から。**本体の機能を刈った物差しを、面には最初から組み込む。**

### 段と閉じる条件

| 段 | 何を | 閉じる条件 |
|---|---|---|
| **1a** | 面のホスト：`faces/` を読む・面ごとのオリジンで答える・「面」ペイン・タブ・復元・保存で読み直す | 手で置いた `index.html` が面として出て、再起動しても戻る |
| **1b** | `window.loomo` の読む口と開く口（`workspace`・`fs.read`・`git`・`open*`・`state`・`on`・`toast`）、許しのカード | テスト用の面から全部の口を呼べる。面でない頁（`file.loomo`・ネット）からは 1 つも呼べない |
| **1c** | `run`（名前つきのコマンド）と出力の流し込み | `face.json` に無いコマンドは断られる。出力が流れる途中で面を閉じたら子を止める |

### 入ったもの（第 1 段・2026-11-15）

計画どおりに入ったもの：面の置き場と定義（`face.json`）・面ごとのオリジン・「面」ペイン（`PaneKind.Face`・ドックの既定は右）・
タブ・`window.loomo`・許しのカード・名前つきのコマンド・保存で読み直す・MCP の `face_guide`／`show_face`・パレット
（「面を開く：〈題〉」「面を生やす頼みごとの下書きをコピー」）・枯れた面（「＋」のメニューで下へ分ける）。

計画から変えた・足したこと：
- **口に `net` を足した。** 挙げていない面のページは、面のフォルダーの外への要求を全部断られる（CDN のスクリプトも `fetch` も）。
  `fs.read` で読んだ中身をそのまま外へ送れてしまうので、ネットワークも人間が許す口にした。
- **面から渡る値は `$env:LOOMO_ARG_n` と変数 `$LoomoInput`。** 標準入力を `$input` で読ませる形は、PowerShell がコンソールの
  コードページ（cp932）で読んで日本語が化けた（起動後に `InputEncoding` を変えても効かない）。先に UTF-8 で読み切って変数に入れる。
- **読み込むのは、ペインが見えていて前に出ている面だけ。** 隠れたペインの中では WebView2 の初期化が終わらず、待つと `show_face` が
  返らなかった（実機で 60 秒のタイムアウト）。許しが済んでいれば「出せる」とだけ答え、読み込みは見えたときに回す。
- **コマンドの出力の行は、答えと同じ優先度でまとめて流す。** 背景の優先度で流すと、最後の行が答え（`Promise` の解決）より後に届いた。
- 部屋の色は CSS 変数（`--loomo-bg`・`--loomo-panel`・`--loomo-fg`・`--loomo-fg-dim`・`--loomo-accent`・`--loomo-border`・
  `--loomo-font-size`）で渡す。読み込みのたびに、いまのテーマで作り直す（開いたままテーマを替えたら、次の読み込みから）。
- 開いている面と許した指紋は、部屋ごとではなく PC ごと（`%APPDATA%/Loomo/faces-state.json`）。面のフォルダーの中には置かない
  ——面を書く Claude が自分で自分を許せてしまう。
- 出来事は `activeFileChanged` と `gitChanged` の 2 つだけ（`fileSaved`・`commandFinished` は使う面が出てから）。
- Claude が面を出すとき（`show_face`）は §43.6 D と同じ線：フォーカスを奪わない・隠れているペインを出すための並べ替えをしない
  （出ていなければ通知にそう書く）。人間が面の中で押した結果（`loomo.open`）はフォーカスが移ってよい。

実装: `Loomo.Core/Faces/FaceManifest.cs`（定義・指紋・`FaceUrl`）、`Loomo.Services/Faces/FaceStore.cs`（置き場・`FaceRoomState`）、
`Loomo.Services/Faces/FaceRoomApi.cs`（口の線引き・`FaceCommandRunner`・`FaceGuide`）、`Loomo.App/Services/Faces/FaceTabHost.cs`
（面 1 つ＝WebView2 1 つ・橋のスクリプト）、`Loomo.App/Views/Faces/FacePaneView.cs`（タブ・カード）、
`Loomo.App/Views/Shell/Activity/ShellWindow.Faces.cs`（部屋の側の受け口）。テスト: `FaceTests`。

確かめたこと（Release 構成の Loomo を試験用のワークスペースで起こして）：
- 手で置いた面が出る・再起動しても開いていた面とペインが戻る・許し待ちの面はカードが出てページは読み込まれない。
- 点検用の面から全部の口を呼べる（フォルダー・前に出ているファイル・読む・一覧・Git の状態・コマンド＋引数＋日本語の入力・置き場）。
  ワークスペースの外の読み出し・書いていないコマンド・ネットワーク・`file.loomo` は断られる。
- **本物の `claude -p` に「Loomo に面を生やして：いまポートを握っているプロセスの一覧…」と頼むと、再ビルドなしで「ポート」の面が生えた**
  （`face_guide` → Write → `show_face`。許しのカード → 許す → 一覧が出る）。この面は `%APPDATA%/Loomo/faces/ports/` に残してある。

テーマを替えたあとの色、`activeFileChanged`／`gitChanged` が面に届くこと、パレットの項目。

## §44.3 動きで読む

### 何が起きるか

頼みごとの差分（§43.2.2）を開くと、行の前に**動きの前後**が出る：「テスト 2 件が通る → 落ちる」「`--help` の出力に 1 行増えた」
「この画面のここが変わった（前後の絵を重ねて）」。行の差分はその下。動きが変わっていない変更は「動きは同じ」と 1 行で済む。

### 見どころ（何の動きを見るか）

ワークスペースごとに決める（`%APPDATA%/Loomo/workspaces/` の側。リポジトリには書かない）。種類は 3 つ：

- **コマンド**：決まったコマンドの出力と終了コード。
- **テスト**：成否の一覧（`dotnet test` の TRX は §28 の読み方をそのまま。ほかのランナーは `アイデア.md` の「多言語化」と一緒に）。
- **絵**：URL（隠れた WebView2 で開いて `CapturePreviewAsync`）か、PNG を出すコマンド（WPF は View を単体で描く手法がある）。

見どころを足すのも Claude に頼める（「この画面を見どころにして」）——定義は面の API 越し。

### 前の動きはどこから来るか

**組み直さず、録っておく。** 頼みごとの前の状態を別のワークツリーに組んでビルドし直す手は、Loomo 自身で数分かかる。
代わりに Claude のターンが終わるたび（フックの Stop・§38.4）に、作業ツリーで見どころを裏で回して**その時点の動き**を録る。
「前」は 1 つ前に録ったもの。

- 回すのは裏（`ChildProcessIo`）。回している間に作業ツリーが変わったら、その回は捨てる（混ざった動きを録らない）。
- 重い見どころ（全テスト）は「手で」か「言いつけ（§44.4）で」に回せる。ターンごとに回すのは軽いものだけ。
- 録ったものは `%APPDATA%/Loomo/motion.db`（SQLite）と絵のフォルダー。鍵は頼みごと（セッション・頼みごとの行＝§43 と同じ）。
- 録り始める前の頼みごとには動きが無い——無いものは無いと言う（空の欄を見せない）。

### 見せ方

- **記録は本体、見せる面は §44.2 で生やす**（API に `motion.of(request)` を足す）。足りなければ本体へ戻す——その判断が
  1 の API の試金石になる。
- 絵の比べ方は 3 つ：並べる・重ねて透かす・違う所だけ塗る。
- 入口は頼みごとの差分を開く所ぜんぶ（blame の右クリック・ターミナルサポートのターン・軌跡の Claude の段・MCP の `show_changes`）。

### 段と閉じる条件

| 段 | 何を | 閉じる条件 |
|---|---|---|
| **2a** | 見どころの定義・ターンの終わりに録る・`motion.db`（コマンドとテスト） | Loomo 自身で、テストを 1 件落とす頼みごとのあとに「通る → 落ちる」が出る |
| **2b** | 絵の見どころ（URL・PNG を出すコマンド）と 3 つの比べ方 | View を 1 つ変える頼みごとの前後の絵が重なって出る |
| **2c** | 動きから行へ潜る（入れ替わったテスト → その頼みごとの、そのテストに近い書き込み） | 落ちたテストから 2 手以内で犯人の行に着く |

## §44.4 言いつけ

### 何が起きるか

部屋に常設の言いつけを置く：「テストが落ちたら、直す案を作っておく」「上流が動いたら、取り込んで試しておく」
「毎朝、依存の更新を試しておく」。部屋は裏のワークツリーで Claude を動かし、仕上がりを**盆**に並べる。
人間は盆の 1 件を開いて、動き（§44.3）と差分を読み、**採る**か**捨てる**。

### 作り

- 言いつけ＝名前・きっかけ・頼みごとの本文・対象のリポジトリ・上限（時間・1 日の回数）。置き場所は `%APPDATA%/Loomo/orders.json`。
- **きっかけ**：手で／時刻・間隔／見どころの入れ替わり（§44.3 の「通る → 落ちる」）／裏の fetch で上流が動いた（§24.92）。
- **走らせ方**：`git worktree add`（置き場所は `%LOCALAPPDATA%/Loomo/orders/`）→ そこで Claude Code を対話なしで起こす
  （見えるターミナルではなく裏のプロセス。許す道具は言いつけごとに絞る）→ 終わったらブランチ `loomo/order/<名前>/<日時>` に
  コミットを残し、要約と動きを録る。Claude Code の対話なしの起こし方・許可の渡し方は版で変わるので、着手時に CHANGELOG と
  ドキュメントで確かめてから決める（§38 と同じ進め方）。
- **盆**：仕上がりの一覧（言いつけ・いつ・要約・動きが変わったか）。1 件ごとに「開く（動きと差分）」「採る（いまのブランチへ
  取り込む。衝突の予告＝§24.88 を先に出す）」「捨てる（ワークツリーとブランチを消す）」「ワークツリーを部屋として開く」。
  盆も §44.2 の面として生やせるかを先に試す。

### 線引き

- **人間の作業ツリーには書かない。** 採るまでは裏のワークツリーの中だけ。push もしない。
- 同時に走るのは 1 本（既定）。Loomo が動いている間だけ（常駐ホスト＝§34 に持たせるのは使われてから）。
- 使用量（§38 のコンテキスト量・`ClaudeUsageSource`）が決めた線を越えていたら走らせない。走った回数と使った量は盆に出す。
- 走っていること・終わったことは袖と「動いているもの」面（§24.54）に出す——頼んでいない物音を立てない。

### 段と閉じる条件

| 段 | 何を | 閉じる条件 |
|---|---|---|
| **3a** | 言いつけの定義・手のきっかけ・裏のワークツリーで走らせる・盆（開く／捨てる） | 手で起こした言いつけの仕上がりが盆に出て、作業ツリーは 1 バイトも変わっていない |
| **3b** | 採る（衝突の予告つき）・時刻と間隔・使用量の線 | 一晩置いた言いつけの案を、朝に 1 件採れる |
| **3c** | 見どころの入れ替わり・上流の動きをきっかけに | テストを落とすコミットのあと、頼まずに直す案が盆に出る |

## §44.5 先に決めたこと・まだ決めていないこと

決めたこと（この計画の前提）：
- 面はワークスペースの外（`%APPDATA%`）。リポジトリに何も書かない。
- 面のオリジンは `file.loomo` と分ける。API は面のオリジンにだけ出す。
- 面が回せるのは `face.json` に書いたコマンドだけ。許すのは人間、1 回。
- 動きは組み直さず録る。
- 言いつけは人間の作業ツリーに書かない・push しない。

まだ決めていないこと（その段に来たら決める）：
- 面の API に書く口（`fs.write`）を出すか（§44.2 の第 2 段）。
- ターンごとに回してよい見どころの重さの線（秒数で切るか、人間が印を付けるか）。
- 言いつけの Claude に許す道具の既定。
- 面を別の PC へ持っていく方法（使い手は 2 台で作業している）。
