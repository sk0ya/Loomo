## §41.1 目的と位置——見せ方ではなく、できることを足す

EditorSupport と TerminalSupport の価値は「同じ中身を別の形で見せる」ことだった（§39.1）。ブラウザはもともと描画の
道具なので、**見せ方を変えても仕方がない**。普通のブラウザは**拡張機能でできることを増やしている**——ブラウザサポートは
その方向で、**前に出ているタブのページ（サイト）ごとに道具を替える**。

ただし Loomo のブラウザでは本物の拡張機能が動く（§21.5.2）。JSON の整形・翻訳・ダークモード・広告ブロック・パスワード
管理のような**ブラウザの中で完結するもの**は本物を入れればよく、ここで作り直すと劣化コピーにしかならない。作るのは
**拡張機能には原理的にできないこと**——拡張機能はブラウザの外を知らないが、ブラウザサポートは部屋の中に居て、
エディタ・Diff・Git・ワークスペース・ターミナルに手が届く。**ページを部屋の中へつなぐ道具だけ**を載せる。

`PaneKind.BrowserSupport`（末尾に追加）。ドックの既定は**右**（EditorSupport・TerminalSupport と同じ、脇に添える面）。
既定キーは無い（`pane.browserSupport`「ブラウザサポートを開く」）。

## §41.2 追従元とサイトの決め方

追従元は前面のブラウザのタブのページ（`BrowserViewModel.CurrentUrl`）。タブの切替・遷移・同一ページ内の遷移
（History API）で `CurrentPageChanged` が来る（題だけの変化では来ない）。**ペインが見えていないときは何もしない**——
見えた瞬間（`IsVisibleChanged`）に追いつく（§39.2 と同じ）。

サイトの選び方は `BrowserSupportCatalog.Describe(url)`——EditorSupport の拡張子、TerminalSupport の前面のプログラムに
あたるもので、拡張機能の `matches` に相当する。**ページの中身（DOM）は読まず、URL だけから決める**：

- 組織・プロジェクト・リポジトリ・PR 番号・パス・行は URL に入っている。ページの作りが変わっても壊れない。
- ページから何も受け取らないので、ページに載った第三者の iframe に操られることがない（§21.5.2 の促しバーで踏んだ問題）。

例外はコードブロックの右クリック（§41.8）だけで、これはページの中身そのものが材料になる。それでも**ページから届く合図は
受けない**——こちらが走らせたスクリプトの戻り値をデータとして読むだけ（`ExecuteScriptAsync`）。

同じページ（URL から読んだ中身が同じ）なら作り直さない——同じ PR の副画面（`?_a=files`）や題の確定のたびに、
見つけた手元のクローンを捨てて探し直さない。どのサイトにも当たらない普通のページは URL そのもの（フラグメント抜き）で
比べる（同じホストの別の記事は別のページ。抜き書きへ戻る `#:~:text=` では作り直さない）。ワークスペースのフォルダーが
出入りしたときだけ、同じページでも作り直す。

ペインは上から、ページの見出し（サイト・題・手元のクローン）・**先に出す節**（調べ始めた場所・PR の未解決の指摘——そのページで
一番知りたいことを決まった道具の列の下に埋めない。`BrowserSupportSection.Leads`）・**道具**（ページ1つにつき決まったボタン）・
**節**（読んでみるまで数の分からない行：CI のエラー・パッケージを使っている場所・ポートを開いているもの）。節の件数は題と別に
持ち、見出しの横の印に出す。節はページが替わると空にし、読み終わった順に決まった位置へ差し込む。前のページへの答え
（読んでいる間に別のページへ移った）は捨てる。

## §41.3 Azure DevOps（Azure Repos）

URL の読み方は `AzureDevOpsWebUrl.TryParse`（純粋）。受ける形はリモートの照合（`AzureDevOpsPullRequestJson.RemoteMatches`）と
揃える：`dev.azure.com/組織/…`・`組織.visualstudio.com/…`（`DefaultCollection` 付きも）・Server の `/tfs/コレクション/…`、
プロジェクトを省いた形（`組織/_git/repo`＝リポジトリ名がプロジェクト名）。名前の `%20` はほどく。

| ページ | URL | 道具 |
|---|---|---|
| PR | `…/_git/repo/pullrequest/123` | 節 **未解決の指摘**（§41.3.3）・**差分を Diff ペインで見る**（分岐点から）・**この PR を Claude Code へ渡す** |
| ファイル | `…/_git/repo?path=/src/a.cs&version=GBmain&line=12` | **手元のファイルを開く（12 行目）** |
| コミット | `…/_git/repo/commit/<hash>` | （道具なし。差分はページが見せている §41.13） |
| リポジトリの他のページ | `…/_git/repo`・PR 一覧など | （道具なし。名札と手元のクローンだけ） |

`path=/`（トップのフォルダー）はファイルではない。

**「Git の対象にする」を単独の道具にしない。** 以前はどのページにも「このリポジトリを Git の対象にする」を添えていたが、
切り替えは目的（PR の差分を見る・コミットを見る）の手段で、先に人が手で済ませる段ではない。差分・コミットの道具は
押したときに自分でそのクローンを Git の対象にしてから開く（`SelectGitRepository`）ので、単独のボタンは要らなかった——
リポジトリが1つのワークスペースでは押しても何も変わらないボタンが、道具の無いページで一番目立つ所に出ていた。

### §41.3.1 手元のクローン

ページのプロジェクト／リポジトリを指すリモートを持つリポジトリを、**ワークスペースの全リポジトリ**（§40 のカタログ）から
探す（`FindAzureRepositoryAsync`。いま Git の対象にしているものを先に・リモートが複数当たれば origin）。カタログの初回は
フォルダーを歩くので UI スレッドでは作らない。リモートの URL はリポジトリごとの窓口（`GitService.For`）が覚えている。

- 見つかれば「手元のクローン: <場所>（<リモート>）」を出し、クローンが要る道具を並べる。
- 見つからなければ「ワークスペースに <プロジェクト> / <リポジトリ> のクローンがありません」と言い、クローンの要らない
  道具（会話を読む）だけを残す。**クローンはしない**——どこへ置くかは人が決めることで、頼まれていない。

### §41.3.2 道具の中身

- **差分**：パレットの「Azure DevOps: プルリクエスト」（§24.27.1）と同じ部品。PR の元と入れ先のブランチを REST で読み
  （GET のみ）、`refs/heads/…` を ref を作らずに取って Diff ペインの2点比較（分岐点から）で出す。今回あわせて、PR の
  差分は**いまの Git の対象に無くても全リポジトリからクローンを探し、それを Git の対象にしてから取る**ようにした
  （以前は選んでいるリポジトリのリモートしか見ず、二つ目のリポジトリの PR は「見つかりません」だった）。ワークツリーは
  Git パネルの読み込み済みの状態の上で作るので、従来どおり選んでいるリポジトリだけ。
- **Claude Code へ渡す**：PR の説明・レビュアーと投票・スレッドを `PR-<id>.md`（§24.27.1 と同じ Markdown）にして一時フォルダー
  （`%TEMP%/Loomo/handoff/<プロジェクト>-<リポジトリ>-PR-<id>.md`。リポジトリを名前に入れるのは、まだ Claude が読んでいない
  別のリポジトリの同じ番号の PR で上書きしないため）に書き、ターミナルの Claude Code のプロンプトへ `@参照` で入れる（送信はしない。エディタの
  「Claude Code（Foo.cs:10）」と同じ形 §24.3.1）。以前は同じ Markdown を**エディタへ写す**道具だったが、ページに出ているものを
  エディタで読み直しても嬉しくない——写す目的は頼む相手へ渡すことだった。Claude Code が動いているタブが無ければ道具を出さない（ページの引き直しのほか、タブのタイトルの印が変わったとき・
  タブを閉じたときにも見直す——`claude` を起動したのにページを移るまで出ない、終わったのに残る、にしない）。
  照会先の組織は**ページの URL のもの**——設定の組織とは別の組織の PR を見ていることもある。認証は Work Items と同じ接続
  （共有の PAT。**書き込む口は持たない**）。
- **ファイル**：クローンの同じパスをその行で開く（`AzureDevOpsWebUrl.LocalPath`。`..` でクローンの外を指すものは開かない）。
  手元に無ければ、ページのブランチ（`version=GB…`）を添えて「手元のブランチには無いのかもしれません」と言う。手元の版は
  ページの版と違うことがある——同じにはしない（チェックアウトは人の作業を動かす）。

失敗と結果はペインの「手元のクローン」の行に出す（ダイアログで作業を止めない）。PR の取得の失敗だけは §24.27.1 の部品の
まま警告を出す。

### §41.3.3 未解決の指摘 → 手元の行

PR のページで知りたいのは「どこを直せと言われているか」で、直すのは手元のエディタ。スレッドの一覧はページにもあるが、
ページからは手元のファイルのその行へ飛べない。節「未解決の指摘」は、コードの行に付いた**未解決**のスレッド
（active・pending）をファイル・行の順に並べ、行ごとに「開く」。行の題は `パス:行`（等幅）、添え書きは最初の発言者と本文の頭
（返信の数）。

- **どこで開くか**：§42.3 の右クリックと同じ——PR の元のブランチのワークツリー → `pr/<番号>`（`ReviewWorktreeChooser`）。そこで
  開いたファイルには §42 の吹き出しも出る。行は PR の版のその行の中身で合わせる（`ReviewLineAnchor`。`OpenReviewThreadLocallyAsync` を共有）。
- **ワークツリーが無いとき**：節の添え書きでそう言い、行のボタンは「本体で開く」（ツールチップにブランチ違いと書く）。見出しの
  「ワークツリーを作る」は PR の元のブランチを取って `pr/<番号>` を作り、ワークツリーに置く（パレットの「ワークツリーで開く」と
  同じ名前・置き場）。パレットのほうは部屋を移るが、ここは**移らない**——指摘の行を開くための置き場で、作り終わると節が
  そのワークツリーを指し直す。リポジトリは Git の対象とは限らないので、そのクローンの窓口（`GitService.For`）で動かす。
- 既にある（どこにも置かれていない）`pr/<番号>` は PR の先頭へ動かすが、**PR に無いコミットを持っていれば動かさない**
  （`merge-base --is-ancestor`。手元で直したコミットが reflog にしか残らなくなる）。パレットの「ワークツリーで開く」も同じ。
- 節を出すたびに PR を**読み直す**（§42.3 の 2 分の覚えは使わない——ページで解決したスレッドを残して見せない）。読み直したものは
  右クリックの「手元で開く」の覚えにもなる。
- GitHub の PR はまだ（§42 が Azure DevOps だけのため）。

## §41.4 CI のエラー → 手元のファイル（共通）

パイプライン（§41.5）と Actions（§41.6）の失敗は、**エラーの場所を手元のファイルのその行へ**つなぐのが本体。ログを
読むだけなら CI のページで足りる——部屋に持ち込む理由は、ログの `src\App\Main.cs(12,5)` を押せばエディタのその行に
立てること。

- 拾う形は `CiLogProblems`（純粋）。MSBuild／tsc の `path(12,5): error CS0103: …` と gcc 系の `path:12:5: error: …` の
  二つだけで、**どちらも error／warning の語を伴うものに限る**（語を求めないと `example.com:443` まで場所に見える）。
  行頭の時刻・`gh run view --log-failed` の「ジョブ⇥ステップ⇥」・`##[error]`・色の制御文字・MSBuild が末尾に付ける
  `[…\proj.csproj]` は外してから読む。
- 場所は**ビルドエージェントの上のパス**（`D:\a\1\s\src\…`・`/home/runner/work/repo/repo/src/…`）。作業フォルダーの
  深さは CI ごとに違うので、先頭の段を1つずつ落としながらクローンの下にあるファイルを探し、**後ろから一番長く一致する**
  ものを採る（`MapToClone`）。ページのリポジトリのクローンが分かればそこ、分からなければ（パイプラインのページは
  リポジトリを持たない）ワークスペースの全リポジトリで探す。見つからなければ「手元に見つかりません」と添え、開くボタンは出さない。
- 節「エラー」の行：手元のパス:行（等幅）・✗／⚠ と本文・「開く」。エラーを先に。ログの全文はページに出ているので、写しに
  する道具は持たない（§41.13）。

## §41.5 Azure Pipelines

`…/プロジェクト/_build/results?buildId=123`（`AzureDevOpsWebPageKind.Build`。リポジトリには属さない）。ページを開くと
`_apis/build/builds/{id}/timeline` を読み（`GetBuildFailuresAsync`、GET のみ・§24.27.1 と同じ接続）、失敗した段と、
エラー・警告の issue を拾う（`AzureDevOpsBuildJson.ParseTimeline`）。issue の場所は `data.sourcepath`／`linenumber` に
あればそれ、無ければ本文から読む。issue に出ないエラーのために、失敗したタスクのログ（先頭の 5 本まで）も読む
（`GetBuildLogAsync`、素のテキスト）。失敗した段の一覧はページにあるので節にしない（§41.13）。

## §41.6 GitHub

URL の読み方は `GitHubWebUrl.TryParse`（純粋。github.com だけ。`settings`・`notifications` 等の GitHub 自身のページは除く）。
手元のクローンは Azure DevOps と同じく全リポジトリからリモートで探す（`FindRepositoryByRemoteAsync`。リモートの URL を
`GitHostingUrl.TryGetGitHubRepositoryUrl` で直して比べる）。gh を使うものは `--repo owner/repo` で名指しするので、
**クローンが無くても読める**（PR・Issue の会話、Actions のログ）。gh が無ければ入れ方を出す。

| ページ | URL | 道具 |
|---|---|---|
| PR | `/pull/12`（`/files` 等も） | 差分を Diff ペインで見る（`refs/pull/12/head` と基準を取る。§24.27 と同じ部品）・この PR を Claude Code へ渡す |
| Issue | `/issues/34` | この Issue を Claude Code へ渡す（本文と会話） |
| ファイル | `/blob/<ref>/<path>#L12` | 手元のファイルを開く（12 行目） |
| コミット | `/commit/<sha>`・`/pull/12/commits/<sha>` | （道具なし §41.13） |
| Actions の実行 | `/actions/runs/123` | 節「エラー」（§41.4） |

`blob/` の後ろは ref とパスの境目が URL からは決まらない（ブランチ名に / を含められる）。先頭から 1 段ずつ ref の側へ
寄せながら、クローンの下にあるファイルで決める（`GitHubWebUrl.LocalPath`）。

## §41.7 npm／NuGet のパッケージ

`npmjs.com/package/<name>`（スコープ付き・`/v/<版>`）と `nuget.org/packages/<id>/<版>`。版は URL にあるときだけ。
**このワークスペースでの使われ方**を節に出す（`BrowserPackagePages.Scan`、背景で）：

- 拾う先：npm は `package.json` の dependencies／devDependencies／peerDependencies／optionalDependencies、NuGet は
  `*.csproj`／`*.fsproj`／`*.vbproj` の `PackageReference`（`Include`／`Update`、版は属性か子要素）と中央管理の
  `Directory.Packages.props` の `PackageVersion`。`node_modules`・`bin`・`obj`・隠しフォルダーには入らない
  （深さ 6・400 ファイルまで。打ち切ったらそう言う）。`dotnet list package` は使わない（restore 済みでないと読めず遅い）。
- 節「このワークスペースで使っている場所」：ファイル・版（節の種類）・「開く」（その行）・ページに版があり違う版なら
  「<版> にする」。中央管理の行と版を書いていない参照は、コマンドではなくファイルを開いて直す。
- 節「まだ入れていないプロジェクト」：「<版> を追加」（版が無ければ最新）。行を並べるのは **5 つまで**——それより多ければ
  節は件数と「多いので並べません」だけにする（何十行は選べない。節ごと消すと「全部に入っている」と見分けがつかない）。
- 追加・版の変更は**自分では書き換えず、見えるターミナルに打つ**（`dotnet add '<proj>' package <id> --version <v>`・
  `Push-Location …; npm install '<name>@<v>' [--save-dev]; Pop-Location`）——§30 の導入と同じく出力が人に見え、失敗も
  そこで分かる。名前と版は安全な文字だけのときに限る（範囲指定の `>=` は PowerShell のリダイレクトに化ける。スコープ付きの
  `@types/node` はスプラットに読まれるので引用する）。ターミナルが何か動かしていれば打たず、手で打つ1行を出す。
- パッケージのページは README の例がそのまま使えるので、コードブロックの右クリック（§41.8）も効く。

## §41.8 記事・ドキュメント：コードブロックの右クリック

どのサイトにも当たらないページ（とパッケージのページ。`ShowsCode`）で、コードブロック（`pre`）を右クリックすると、メニューの
先頭に行き先の項目が出る（`ShellWindow.BrowserPageCodeMenu.cs`）。右クリックした所の `pre` を自前のスクリプトで1つ読むだけ
（`BrowserPageCode.ExtractAtScript`。座標は**右クリックされたタブ**の拡大率で割り、調べ始めた場所もそのタブのもの——前面の
  タブとは限らない。ページからの合図は受けない §41.2）。1 秒で読めなければ出さない。メニューは読み終わるまで出ないので、
  コードの上でありえない右クリック（画像・動画・音声・リンク・入力欄）では読まない。

- 調べ始めた場所（§41.12）がファイルなら **このコードを <ファイル名> の <行> 行目の下へ貼る**。
- シェルの言語か1行なら **このコマンドをターミナル「<タブ>」へ入れる**（調べ始めたタブ。無ければ見えるターミナル。頭の
  プロンプトを外し、Enter は押さない。複数行はコンポーザへ回る）。
- **このコードをエディタの新しいタブへ**（`snippet.<拡張子>`）・**このコードをコンポーザへ**。

以前は脇のペインに節「このページのコード」としてページの `pre` を並べ直していたが、同じものがページにもう載っていて、
脇で探し直すのは手間が増えるだけだった。要るのは「このコードを、あそこへ」の1手で、それはコードの上で済ませるのが速い。
ページ全体がコードのページ（GitHub のファイル・PR）では出さない——手元のファイルを開く方が早い。

## §41.9 localhost：そのポートを動かしているターミナル

`localhost`・`*.localhost`・`127.0.0.1`・`[::1]` のページでは、そのポートで待ち受けているプロセスを
`GetExtendedTcpTable`（IPv4 と IPv6。Vite は既定で `::1` だけで待ち受ける）で引き、それが**どのターミナルのタブのシェルの
子孫か**を見る（§39.4.2 の Claude のセッション探しと同じ親たどり）。節の行に「このタブへ」。Loomo のターミナルの外で
動いていればそう言い、誰も待ち受けていなければ「サーバーが止まっている」。Loomo が見せているローカルの HTML
（§24.45）では、道具「元のファイルをエディタで開く」。

## §41.10 （外した）このページの抜き書き

ペグボードの抜き書きのうち出典がこのページのものを並べていたが、ペグボードの中身を出典で絞って並べ直しただけだった（§41.13）。
抜き書きからページへ戻るのはペグボードの側で足りる。

## §41.12 どのページでも：調べ始めた場所へ戻る・そこへ貼る

エディタ・ターミナルの右クリック「ブラウザへ送る」で調べると、できたタブに**調べ始めた場所**（`BrowserSearchOrigin`：
ファイル・行・列・選択の最後の行、またはターミナルのタブ）を付ける。そのタブでリンクを辿っても、`target=_blank` で開いた
子のタブにも引き継ぐ（`BrowserNewWindowController` の `opened`）。覚えるのはセッションの間だけで、復元はしない。

調べ物は元の作業へ戻ってくるためのもの。ところが「エディタへ」（§41.8）は `snippet.xx` の写しを作るだけで、写したものを
元のファイルへ運ぶのは人の手だった。ブラウザの拡張機能は調べ始めた場所を知らないので、これは部屋の中でしかできない。

- 節「調べ始めた場所」（一番上）：`src/App/Main.cs:42`・「<調べた語>」を調べています・**戻る**（エディタのその行／そのタブへ）。
  ファイルが消えた・タブを閉じたなら出さない。
- ページのコードブロックの右クリック（§41.8）の先頭に **<ファイル名> の <行> 行目の下へ貼る**：選んだ所の**下の行**へ差し込む（選んだ所は調べた語そのもの
  ——エラーの文や API 名——なので置き換えない）。字下げはその行に揃え（ブロックの共通の字下げは外す）、改行はファイルの
  ものに合わせる（`PasteBelow`、純粋）。1 回の取り消せる編集。続けて貼ると前に貼ったものの下へ並ぶ（タブの出所の
  「最後の行」を進める。戻る先は変えない）。
- 出所がターミナルなら、コマンドの「ターミナルへ入れる」は**そのタブ**へ（「<タブ名>」へ）。前面が埋まっているタブには
  打たない（Claude Code が居れば頼みごととして送られる。§38）。複数行は従来どおりコンポーザへ。

## §41.13 道具の見直し（2026-11-03）——何が嬉しいかを言えない道具は置かない

道具ごとに「押すと何が嬉しいか」「部屋の他の所と重なっていないか」を問い直した。物差しは §41.1 の「拡張機能にはできないこと」
で、**ページに出ているものを部屋のどこかへ写し直すだけ**のものは、写した先で何が良くなるのかを言えない限り置かない。

| 道具 | どうしたか | 理由 |
|---|---|---|
| このリポジトリを Git の対象にする | 外した | 切り替えは目的（PR・コミットの差分）の手段で、その道具が押されたときに自分で切り替える。リポジトリが1つだと押しても何も起きない |
| 概要と会話をエディタで読む（PR・Issue） | Claude Code へ渡すに替えた | ページに出ているものをエディタで読み直しても嬉しくない。写す目的は頼む相手へ渡すこと |
| 失敗したログをエディタで読む・節「失敗した段」 | 外した | ログも段もページにある。本体はエラーの行 → 手元のファイル（§41.4） |
| このコミットを Diff ペインで見る | 外した | ページがそのコミットの差分を見せている |
| 節「このページのコード」 | コードブロックの右クリックへ（§41.8） | 同じコードを脇に並べ直していた |
| 節「このページの抜き書き」 | 外した | ペグボードの並べ直し |
| 節「まだ入れていないプロジェクト」 | 行は 5 つまで（多ければ件数だけ） | 何十行は選べない |
| 未解決の指摘（Azure DevOps の PR） | 足した（§41.3.3） | PR のページで一番知りたいことで、手元の行へ飛ぶのは部屋の中でしかできない |

残したもの——CI のエラー → 手元の行、ファイル → 手元のファイル、パッケージ → このワークスペースでの使われ方、localhost →
動かしているターミナル、ローカルの HTML → 元のファイル、調べ始めた場所——はどれも**ページからは分からないこと**（手元の
パス・手元の使われ方・どのタブか）を足している。
