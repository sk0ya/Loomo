# §41 ブラウザサポート（ページを、部屋の中へつなぐ）

> 作成日: 2026-11-03 / 状態: **第2段実装済み**（2026-11-03）。第1段＝Azure DevOps の PR・ファイル・コミット。
> 第2段＝パイプラインの失敗 → 手元のファイル（§41.5）・GitHub の PR・Issue・ファイル・コミット・Actions（§41.6）・
> npm／NuGet のパッケージ → このワークスペースでの使われ方と追加・版の変更（§41.7）・記事のコード → エディタ／コンポーザ／
> ターミナル／ペグボード（§41.8）・localhost → そのポートを動かしているターミナルのタブ（§41.9）・どのページでも
> → このページの抜き書き（§41.10）。続き＝GitHub Enterprise・GitLab、パイプラインのエラーを問題パネルへ流す。
> 関連する正本: Azure DevOps の PR を部屋で読む部品は §24.27.1、Git の対象と全リポジトリのカタログは §40、
> 本物の拡張機能（ストアからの導入・ポップアップ）は §21.5.2、脇に添える面の型は EditorSupport（§24.8）・TerminalSupport（§39）。

## §41.1 目的と位置——見せ方ではなく、できることを足す

EditorSupport と TerminalSupport の価値は「同じ中身を別の形で見せる」ことだった（§39.1）。ブラウザはもともと描画の
道具なので、**見せ方を変えても仕方がない**。普通のブラウザは**拡張機能でできることを増やしている**——ブラウザサポートは
その方向で、**前に出ているタブのページ（サイト）ごとに道具を替える**。

ただし Loomo のブラウザでは本物の拡張機能が動く（§21.5.2）。JSON の整形・翻訳・ダークモード・広告ブロック・パスワード
管理のような**ブラウザの中で完結するもの**は本物を入れればよく、ここで作り直すと劣化コピーにしかならない。作るのは
**拡張機能には原理的にできないこと**——拡張機能はブラウザの外を知らないが、ブラウザサポートは部屋の中に居て、
エディタ・Diff・Git・ワークスペース・ターミナルに手が届く。**ページを部屋の中へつなぐ道具だけ**を載せる。

`PaneKind.BrowserSupport`（末尾に追加）。ドックの既定は**右**（EditorSupport・TerminalSupport と同じ、脇に添える面）。
既定キーは無い（`pane.browserSupport`「ブラウザサポートを開く」）。

## §41.2 追従元とサイトの決め方

追従元は前面のブラウザのタブのページ（`BrowserViewModel.CurrentUrl`）。タブの切替・遷移・同一ページ内の遷移
（History API）で `CurrentPageChanged` が来る（題だけの変化では来ない）。**ペインが見えていないときは何もしない**——
見えた瞬間（`IsVisibleChanged`）に追いつく（§39.2 と同じ）。

サイトの選び方は `BrowserSupportCatalog.Describe(url)`——EditorSupport の拡張子、TerminalSupport の前面のプログラムに
あたるもので、拡張機能の `matches` に相当する。**ページの中身（DOM）は読まず、URL だけから決める**：

- 組織・プロジェクト・リポジトリ・PR 番号・パス・行は URL に入っている。ページの作りが変わっても壊れない。
- ページから何も受け取らないので、ページに載った第三者の iframe に操られることがない（§21.5.2 の促しバーで踏んだ問題）。

例外はページのコードの一覧（§41.8）だけで、これはページの中身そのものが材料になる。それでも**ページから届く合図は
受けない**——こちらが走らせたスクリプトの戻り値をデータとして読むだけ（`ExecuteScriptAsync`）。

同じページ（URL から読んだ中身が同じ）なら作り直さない——同じ PR の副画面（`?_a=files`）や題の確定のたびに、
見つけた手元のクローンを捨てて探し直さない。どのサイトにも当たらない普通のページは URL そのもの（フラグメント抜き）で
比べる（同じホストの別の記事は別のページ。抜き書きへ戻る `#:~:text=` では作り直さない）。ワークスペースのフォルダーが
出入りしたときだけ、同じページでも作り直す。

ペインは上から、ページの見出し・**道具**（ページ1つにつき決まったボタン）・**節**（読んでみるまで数の分からない行：
CI のエラー・パッケージを使っている場所・コード・抜き書き）。節はページが替わると空にし、読み終わった順に決まった
位置へ差し込む。前のページへの答え（読んでいる間に別のページへ移った）は捨てる。

## §41.3 Azure DevOps（Azure Repos）

URL の読み方は `AzureDevOpsWebUrl.TryParse`（純粋）。受ける形はリモートの照合（`AzureDevOpsPullRequestJson.RemoteMatches`）と
揃える：`dev.azure.com/組織/…`・`組織.visualstudio.com/…`（`DefaultCollection` 付きも）・Server の `/tfs/コレクション/…`、
プロジェクトを省いた形（`組織/_git/repo`＝リポジトリ名がプロジェクト名）。名前の `%20` はほどく。

| ページ | URL | 道具 |
|---|---|---|
| PR | `…/_git/repo/pullrequest/123` | **差分を Diff ペインで見る**（分岐点から）・**概要と会話をエディタで読む** |
| ファイル | `…/_git/repo?path=/src/a.cs&version=GBmain&line=12` | **手元のファイルを開く（12 行目）** |
| コミット | `…/_git/repo/commit/<hash>` | **このコミットを Diff ペインで見る**（手元に無ければリモートから取る） |
| リポジトリの他のページ | `…/_git/repo`・PR 一覧など | このリポジトリを Git の対象にする |

どのページにも「このリポジトリを Git の対象にする」を添える。`path=/`（トップのフォルダー）はファイルではない。

### §41.3.1 手元のクローン

ページのプロジェクト／リポジトリを指すリモートを持つリポジトリを、**ワークスペースの全リポジトリ**（§40 のカタログ）から
探す（`FindAzureRepositoryAsync`。いま Git の対象にしているものを先に・リモートが複数当たれば origin）。カタログの初回は
フォルダーを歩くので UI スレッドでは作らない。リモートの URL はリポジトリごとの窓口（`GitService.For`）が覚えている。

- 見つかれば「手元のクローン: <場所>（<リモート>）」を出し、クローンが要る道具を並べる。
- 見つからなければ「ワークスペースに <プロジェクト> / <リポジトリ> のクローンがありません」と言い、クローンの要らない
  道具（会話を読む）だけを残す。**クローンはしない**——どこへ置くかは人が決めることで、頼まれていない。

### §41.3.2 道具の中身

- **差分**：パレットの「Azure DevOps: プルリクエスト」（§24.27.1）と同じ部品。PR の元と入れ先のブランチを REST で読み
  （GET のみ）、`refs/heads/…` を ref を作らずに取って Diff ペインの2点比較（分岐点から）で出す。今回あわせて、PR の
  差分は**いまの Git の対象に無くても全リポジトリからクローンを探し、それを Git の対象にしてから取る**ようにした
  （以前は選んでいるリポジトリのリモートしか見ず、二つ目のリポジトリの PR は「見つかりません」だった）。ワークツリーは
  Git パネルの読み込み済みの状態の上で作るので、従来どおり選んでいるリポジトリだけ。
- **会話を読む**：`PR-<id>.md` の写し（§24.27.1 と同じ）。照会先の組織は**ページの URL のもの**——設定の組織とは別の
  組織の PR を見ていることもある。認証は Work Items と同じ接続（共有の PAT。**書き込む口は持たない**）。
- **ファイル**：クローンの同じパスをその行で開く（`AzureDevOpsWebUrl.LocalPath`。`..` でクローンの外を指すものは開かない）。
  手元に無ければ、ページのブランチ（`version=GB…`）を添えて「手元のブランチには無いのかもしれません」と言う。手元の版は
  ページの版と違うことがある——同じにはしない（チェックアウトは人の作業を動かす）。
- **コミット**：`rev-parse --verify` で手元にあるかを見て、無ければクローンのリモートを `fetch --no-tags` してからもう一度。

失敗と結果はペインの「手元のクローン」の行に出す（ダイアログで作業を止めない）。PR の取得の失敗だけは §24.27.1 の部品の
まま警告を出す。

## §41.4 CI のエラー → 手元のファイル（共通）

パイプライン（§41.5）と Actions（§41.6）の失敗は、**エラーの場所を手元のファイルのその行へ**つなぐのが本体。ログを
読むだけなら CI のページで足りる——部屋に持ち込む理由は、ログの `src\App\Main.cs(12,5)` を押せばエディタのその行に
立てること。

- 拾う形は `CiLogProblems`（純粋）。MSBuild／tsc の `path(12,5): error CS0103: …` と gcc 系の `path:12:5: error: …` の
  二つだけで、**どちらも error／warning の語を伴うものに限る**（語を求めないと `example.com:443` まで場所に見える）。
  行頭の時刻・`gh run view --log-failed` の「ジョブ⇥ステップ⇥」・`##[error]`・色の制御文字・MSBuild が末尾に付ける
  `[…\proj.csproj]` は外してから読む。
- 場所は**ビルドエージェントの上のパス**（`D:\a\1\s\src\…`・`/home/runner/work/repo/repo/src/…`）。作業フォルダーの
  深さは CI ごとに違うので、先頭の段を1つずつ落としながらクローンの下にあるファイルを探し、**後ろから一番長く一致する**
  ものを採る（`MapToClone`）。ページのリポジトリのクローンが分かればそこ、分からなければ（パイプラインのページは
  リポジトリを持たない）ワークスペースの全リポジトリで探す。見つからなければ「手元に見つかりません」と添え、開くボタンは出さない。
- 節「エラー」の行：手元のパス:行（等幅）・✗／⚠ と本文・「開く」。エラーを先に。道具「失敗したログをエディタで読む」は
  読み終わったログの全文を `build-<id>.log`／`run-<id>.log` の写しにする（読み直さない）。

## §41.5 Azure Pipelines

`…/プロジェクト/_build/results?buildId=123`（`AzureDevOpsWebPageKind.Build`。リポジトリには属さない）。ページを開くと
`_apis/build/builds/{id}/timeline` を読み（`GetBuildFailuresAsync`、GET のみ・§24.27.1 と同じ接続）、失敗した段と、
エラー・警告の issue を拾う（`AzureDevOpsBuildJson.ParseTimeline`）。issue の場所は `data.sourcepath`／`linenumber` に
あればそれ、無ければ本文から読む。issue に出ないエラーのために、失敗したタスクのログ（先頭の 5 本まで）も読む
（`GetBuildLogAsync`、素のテキスト）。節「失敗した段」には段ごとの「ログを読む」。

## §41.6 GitHub

URL の読み方は `GitHubWebUrl.TryParse`（純粋。github.com だけ。`settings`・`notifications` 等の GitHub 自身のページは除く）。
手元のクローンは Azure DevOps と同じく全リポジトリからリモートで探す（`FindRepositoryByRemoteAsync`。リモートの URL を
`GitHostingUrl.TryGetGitHubRepositoryUrl` で直して比べる）。gh を使うものは `--repo owner/repo` で名指しするので、
**クローンが無くても読める**（PR・Issue の会話、Actions のログ）。gh が無ければ入れ方を出す。

| ページ | URL | 道具 |
|---|---|---|
| PR | `/pull/12`（`/files` 等も） | 差分を Diff ペインで見る（`refs/pull/12/head` と基準を取る。§24.27 と同じ部品）・概要と会話をエディタで読む |
| Issue | `/issues/34` | 本文と会話をエディタで読む |
| ファイル | `/blob/<ref>/<path>#L12` | 手元のファイルを開く（12 行目） |
| コミット | `/commit/<sha>`・`/pull/12/commits/<sha>` | このコミットを Diff ペインで見る |
| Actions の実行 | `/actions/runs/123` | 失敗したログをエディタで読む・節「エラー」（§41.4） |

`blob/` の後ろは ref とパスの境目が URL からは決まらない（ブランチ名に / を含められる）。先頭から 1 段ずつ ref の側へ
寄せながら、クローンの下にあるファイルで決める（`GitHubWebUrl.LocalPath`）。

## §41.7 npm／NuGet のパッケージ

`npmjs.com/package/<name>`（スコープ付き・`/v/<版>`）と `nuget.org/packages/<id>/<版>`。版は URL にあるときだけ。
**このワークスペースでの使われ方**を節に出す（`BrowserPackagePages.Scan`、背景で）：

- 拾う先：npm は `package.json` の dependencies／devDependencies／peerDependencies／optionalDependencies、NuGet は
  `*.csproj`／`*.fsproj`／`*.vbproj` の `PackageReference`（`Include`／`Update`、版は属性か子要素）と中央管理の
  `Directory.Packages.props` の `PackageVersion`。`node_modules`・`bin`・`obj`・隠しフォルダーには入らない
  （深さ 6・400 ファイルまで。打ち切ったらそう言う）。`dotnet list package` は使わない（restore 済みでないと読めず遅い）。
- 節「このワークスペースで使っている場所」：ファイル・版（節の種類）・「開く」（その行）・ページに版があり違う版なら
  「<版> にする」。中央管理の行と版を書いていない参照は、コマンドではなくファイルを開いて直す。
- 節「まだ入れていないプロジェクト」：「<版> を追加」（版が無ければ最新）。
- 追加・版の変更は**自分では書き換えず、見えるターミナルに打つ**（`dotnet add '<proj>' package <id> --version <v>`・
  `Push-Location …; npm install '<name>@<v>' [--save-dev]; Pop-Location`）——§30 の導入と同じく出力が人に見え、失敗も
  そこで分かる。名前と版は安全な文字だけのときに限る（範囲指定の `>=` は PowerShell のリダイレクトに化ける。スコープ付きの
  `@types/node` はスプラットに読まれるので引用する）。ターミナルが何か動かしていれば打たず、手で打つ1行を出す。
- パッケージのページは README の例がそのまま使えるので、ページのコードの一覧（§41.8）も出す。

## §41.8 記事・ドキュメント：ページのコード

どのサイトにも当たらないページ（とパッケージのページ）では、ページの `pre` を順に拾って節「このページのコード」にする
（`BrowserPageCode.ExtractScript`。言語は `language-xx`／`lang-xx`／`highlight-source-xx` の class か `data-lang`、同じ中身は
1つ・60 個まで）。読み込みが終わった合図（`IsLoading` が下りた）で読み直し、見出しの「読み直す」で後から書き足された
コードも拾える。1 つも無ければ節ごと出さない。

行ごとに：**エディタへ**（`snippet.<拡張子>` の写し。保存先は人が決める）・**コンポーザへ**・**ターミナルへ**（シェルの
言語か1行のものだけ。頭のプロンプト `$ `・`> `・`PS C:\x> ` を外し、Enter は押さない。複数行はコンポーザへ回る——
`SendRecentCommandToTerminal` と同じ）・**ペグボードへ**（出典付き。§24.24）。

## §41.9 localhost：そのポートを動かしているターミナル

`localhost`・`*.localhost`・`127.0.0.1`・`[::1]` のページでは、そのポートで待ち受けているプロセスを
`GetExtendedTcpTable`（IPv4 と IPv6。Vite は既定で `::1` だけで待ち受ける）で引き、それが**どのターミナルのタブのシェルの
子孫か**を見る（§39.4.2 の Claude のセッション探しと同じ親たどり）。節の行に「このタブへ」。Loomo のターミナルの外で
動いていればそう言い、誰も待ち受けていなければ「サーバーが止まっている」。Loomo が見せているローカルの HTML
（§24.45）では、道具「元のファイルをエディタで開く」。

## §41.10 どのページでも：このページの抜き書き

ペグボードの出典付きの抜き書き（§24.24）のうち、出典がこのページ（`BrowserLibrary.SameUrl`）のもの。「この箇所へ」は
**このタブのまま** Text Fragment の URL へ移ってその一節を強調する（新しいタブを開かない——もうそのページに居る）。
抜き書きを取る・消すと読み直す。無ければ節ごと出さない。
