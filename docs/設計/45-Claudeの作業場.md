# §45 Claude の作業場（製品版への計画）

> 作成日: 2026-11-16 / 状態: **P0a〜P0c 実装済み**（2026-11-16、§45.3.1）。P0d から先は §45.8 の「先に決めること」と画面の台本の合意待ち
> 関連する正本: Claude Code 連携は §38、出自・部屋を Claude から使う口（MCP）は §43（§43.6 D）、生える面・動き・言いつけは §44、
> 画面の作り方と確かめ方はスキル `ui-usability`。

## §45.1 なぜ・ゴール

Loomo はエージェントではなく人間の部屋で、AI の作業はターミナルの Claude Code が担う（README の読み替え）。この章が扱うのは
「**Claude Code がこの部屋で働くとき、人間と Claude のあいだの線が細いところ**」で、2026-11-16 の棚卸しで次の 6 つが出た。

| # | 欠け | いまの作り（根拠） |
|---|---|---|
| 1 | **人間 → Claude へ位置つきの指摘を返す道が無い** | 読む方向（行 → 頼みごと → 差分 → 会話、§43）は厚い。返す方向は `openDiff` の受け入れ／却下の二択（§38.3）と、PR・Issue・分析プロンプトのコピー（§37・§41）だけ |
| 2 | **Claude から部屋の中が見えない** | MCP は置く道具（`show_*`）と案内（`face_guide`/`motion_guide`）だけ（§43.6 D）。ブラウザペインのページ・デバッガの停止状態・他のタブの出力・人間が見ている範囲は、人間が言葉で言い直している |
| 3 | **確かめた結果が Claude に戻らない** | 動き（§44.3）はターンの終わりに録って人間に知らせるだけ。言いつけ（§44.4）はシェルを持たない |
| 4 | **作業の単位が無い** | 課題×ワークツリー×セッション×配置が別々（§43.6 B）。後回しの根拠「並行はほぼ 1〜2」はこの PC だけの数字（§44.1） |
| 5 | **2 台の PC にまたがらない** | 面・見どころ・言いつけ・出自が PC ごと（§44.5 で未決） |
| 6 | **導入と接続の穴** | 既存のタブ・常駐で繋ぎ直したタブに環境変数が無い（§38.7）・常駐の復元直後に待機を検出しない・Loomo を 2 つ動かすと MCP の宛先が後勝ち（§43.6 D）・フックと MCP と許可の設定が別々のパレットに散っている |

**ゴール（製品レベル）**：別の PC に Loomo を入れた人が、**1 つの画面で接続を済ませ**、その日のうちに次の 3 つが
「説明し直し」なしで回ること。

1. Claude の変更を読みながら、行に指摘を書き、まとめて返せる（往復が部屋の中で閉じる）。
2. 「いま見ているこれ」を Claude が自分で読める（ブラウザのエラー・止まっている変数・前面のファイル）。
3. Claude が壊したことに、人間より先に Claude が気づく。

「製品レベル」は機能の数ではなく §45.7 の完了条件（導入・安全・失敗の仕方・性能・見た目・測り方）を全段で満たすこと。

## §45.2 変えない線

- **主役は人間**（§38.1）。Claude は**置く・読む**だけ。見えるターミナルに打つ・タブを閉じる・配置を変える・フォーカスを奪う・
  ファイルを書く道具は出さない。§45.4 で「読む」を足すので、AGENTS.md の MCP の線（"place things … and nothing else"）は
  「置く・読むだけ」に書き換える——**読む道具の範囲は §45.8 の 2 で人間が決める**。
- 人間が書いた指摘を Claude へ送るのは**人間の操作**だけ。見えるターミナルへは、人間が「送る」を押し、かつ Claude が入力待ちのときだけ
  貼る（Enter は押さない）。busy のタブには打たない（§24.3.1）。
- ユーザーのリポジトリに書かない。設定（`~/.claude/settings.json`・`~/.claude.json`）は人間が押したときだけ書き、外す口を必ず対にする。
- Loomo の外の claude では無害（フックも橋も即終了・空の道具一覧）。

### §45.3.1 入ったもの（P0a〜P0c・2026-11-16）

- **橋がフックも担う**：`sk0ya.Loomo.McpBridge.exe hook`（`HookRelay`）。フックの入力を Loomo の MCP サーバーの `/hook` へ渡し、
  答え（`ILoomoRoomHost.HookAsync` の JSON）をそのまま標準出力へ書く。いまの答えは前の版と同じ 2 つ（承認待ち・セッションの
  結び付け）を UI へ渡すだけで、何も返さない——返す中身は P1・P3 で足す。Loomo の外では即終了、どの Loomo も答えなければ
  前の版の名前付きパイプへ片道で送る（設定の Claude Code 連携を切って MCP サーバーが動いていない Loomo のため）。何があっても 0 で終わる。
- **ネイティブ版（AOT）**：橋の csproj の `PublishNativeBridge` が、ビルドのあとに別プロセスの `dotnet publish` で
  `bin/<構成>/native/` へ建て、本体の `CopyMcpBridge` が建っていればそちらの exe を運ぶ。C++ のビルドツールが無い PC では警告だけ出して
  フレームワーク依存の exe を運ぶ（印のファイルで、ソースが変わるまで試し直さない）。AOT は実行時を exe に焼くので、焼く版を
  `LoomoNativeRuntimeVersion`（10.0.15）で名指しする——SDK 10.0.302 の既定（10.0.10）は既知の脆弱性（GHSA-p3jp-9v83-76w9、10.0.14 未満）の範囲。
- **居場所の名乗り**（P0b）：橋は Toolhelp のスナップショットで親をたどり（子より後に生まれた親＝使い回された PID で止める）、
  祖先の PID を `X-Loomo-Pids`、環境変数のタブを `X-Loomo-Tab` で送る。Loomo（`LoomoRoomHost.Identify`）はタブが自分のものならそれ、
  無ければ祖先の中に自分のタブのシェル（`TerminalShellProcessId`）を探す。祖先に Loomo か常駐ホストが居れば「Loomo の中」なので、
  環境変数の無い常駐のシェルからも道具が見える。名乗らない橋（前の版）は今までどおり受け付ける。
- **Loomo が 2 つ**（P0c）：`mcp-endpoint.json` に `instances`（PID・ポート・トークン）を Loomo ごとに置き、閉じるときに外す。
  上の段の `port`・`token` は最後に起動したもの（前の版の橋はここだけ読む）。書くのは名前付きミューテックスの中で、居ない Loomo の
  項目はそのとき外す。橋は生きている Loomo の項目だけを新しい順に尋ね、自分のシェルを持たない Loomo は 421 で断る。
  居ない Loomo を尋ねないのは、閉じたポートへの接続を Windows が 2 秒ほど試し続けるため。
- **フックの設定**：パレット「Claude Code のフックを設定」が橋の exe を指す項目（`"…\mcp-bridge\sk0ya.Loomo.McpBridge.exe" hook`）を入れ、
  前の版のスクリプトの項目を外す（スクリプトのファイルは消さない——その前から動いている claude がまだ起こす）。「外す」は両方を外す。
  `ClaudeHookInstaller.IsLegacyInstalled` は P0d の画面で「古い版」を出すため。
- **測った数字**（2026-11-16）：橋の起動と終了はフレームワーク依存 ~70ms・AOT ~15ms。フックの往復（AOT・Loomo 2 つで 1 つが 421）は
  シェルから 26〜42ms（10 回）。**Claude Code 自身の計測**ではフック 1 回が exe 216ms・前のスクリプト 446ms——差の大半は Claude Code が
  フックを起こす側の重さで、橋では縮められない。§45.7 の「足す遅延 p95 < 50ms」は橋の往復の数字として読む。
- **確かめたこと**：テスト（`ClaudeRoomLinkTests` 8 件を足し、全 5426 件通過）。実機では、常駐ホストのタブの claude から環境変数を外して
  橋を起こし、道具の一覧と `motion_guide` が返った。Loomo を 2 つ動かし、このタブのシェルを持つ方が 200・持たない方が 421 と答えた。
  WMI で起こした（Loomo の外の）プロセスからは道具の一覧が空・フックは何も書かない。後から起動した Loomo を閉じると、その項目が外れた。
  本物の claude（`claude -p --settings` で exe のフックだけを足した一時の設定）で、SessionStart のフックが終了コード 0 で走った。
- **まだ**：ユーザーの `~/.claude/settings.json` は前の版のスクリプトのまま（入れ直しはパレットから人間が押す）。
  `UserPromptSubmit`・`Stop` はまだ登録していない（足すのは返す中身ができてから＝P1・P3）。P0d・P0e は未着手。
- **見つけた穴**：タブの中で `claude -p` を走らせると、その SessionStart でタブのセッションが `-p` のものに結び直される
  （見出しのコンテキスト量がそちらを指す）。前の版のスクリプトでも同じ。P0e と一緒に直す。

## §45.4 P1 返す道：レビューの往復（1 の解消）

**使う人の手順（台本・案）**：Claude の変更を Diff ペイン（頼みごと単位の差分＝§43.2.2）かエディタで読む → 気になる行で
キー（案：`Ctrl+Alt+M`。右クリック「Claude への指摘」も）→ 行の下に小さな入力欄、1〜2 行書いて Enter → 行に印が付き、
指摘の数がターミナルの見出しに出る（例「指摘 3」）→ 読み終えたら見出しの「指摘を送る」→ Claude が入力待ちなら、指摘をまとめた本文が
プロンプトに貼られる（Enter は人間）→ 送った指摘は「送った」に変わり、その行が次のターンで書き換えられたら「直った？」の印。

- **指摘の宛先**：指摘は Claude のセッション（タブ）に付く。行が出自（§43.3）で結べればその頼みごとのセッション、結べなければ
  前に出ている Claude のタブ。複数あれば入力欄に宛先を出して選べる。
- **本文の形**：`path:line`・その行の中身（行がずれても Claude が探せるように）・指摘の文。まとめて 1 つの Markdown。
- **busy のとき**：貼らない。代わりに「次に頼むとき添える」を選べ、P0a の `UserPromptSubmit` で文脈として足す（足したことは
  ターミナルの見出しに一瞬出す）。
- **却下に理由を**：`openDiff`（§38.3）で却下するとき、任意で一言書ける。返事（`DIFF_REJECTED`）は Claude Code のものなので変えず、
  一言は指摘として同じ経路で次のターンに添える。
- **置き場**：`%APPDATA%/Loomo/feedback/<セッション>.json`。保存は背景（§31.15）。送って 14 日で消す。
- **印**：エディタの注記の印（§42 の吹き出しの作り）を流用。Diff ペインで印が出せなければ Editor パッケージに足す。
- **測る**：`ProvenanceUsageLog` に `feedback.add`・`feedback.send`・`feedback.attach`・`feedback.resolved`。

閉じる条件：Claude の 3 ファイルにまたがる変更に 3 つ指摘を書き、1 回で送り、次のターンで 3 つとも「直った？」が付く——を実操作で。

## §45.5 P2 Claude の目：読むだけの道具（2 の解消）

MCP に**読むだけ**の道具を足す。どれも人間が見ているものに限り（見えていないペインの中身を探らない）、呼ばれたら袖に
「Claude が見た：ブラウザ」の通知を出す（何を見られたかが人間に分かること）。

| 道具 | 返すもの | 線 |
|---|---|---|
| `what_human_sees` | 前面のペインの種類・ファイルと表示中の行範囲・選択・未保存か・開いているタブの一覧（パスだけ） | 既定オン。IDE 連携の `getCurrentSelection` と重なる分は IDE 側に任せる |
| `browser_page` | 前面のブラウザタブの URL・題・直近のコンソールのエラー（件数上限）・失敗したリクエスト（URL と状態だけ）・スクリーンショット（縮小） | `localhost` とワークスペースのファイルは既定オン。**ほかのサイトは既定オフ**（サインインしたページの中身を出さない）。`BrowserService` の DevTools の口を使う |
| `debug_state` | 止まっている理由・場所・スタック（上限）・選んでいるフレームのローカル変数（深さと長さに上限） | 既定オン。止まっていなければそう言う |
| `terminal_output` | 指定したタブ（既定は Claude 自身以外で前面のもの）の直近の画面と、OSC133 で区切った直近のコマンドの出力 | **既定オフ**（秘密が流れやすい）。Claude 自身のタブは返さない |
| `motion_result` | ワークスペースの直近の動き（§44.3）と前回からの変化 | 既定オン。P3 の土台 |

- 道具ごとのオン／オフは P0d の画面に置く。オフの道具は一覧から外す（呼ばれて断るのではなく、見えない）。
- 返す量は上限を決め（例 1 回 16KB・スクショは 1 枚）、超えたら切った旨を書く。UI スレッドで読める状態だけを取り、重い取得は裏で。

閉じる条件：ブラウザペインで出ている JS のエラーを、人間が貼らずに Claude が直す。デバッガで止まっている変数を見て Claude が原因を言う。

## §45.6 P3 確かめた結果を戻す（3 の解消）

- **次の頼みごとに添える**：ターンの終わりに録った動き（§44.3）が「壊れた」（テストが落ちた・ビルドが通らない）に変わったら、
  次の `UserPromptSubmit` で要約（どの見どころが・前は何で今は何か・失敗の file:line）を文脈として足す。足したことは見出しに出す。
- **続けさせる（既定オフ）**：P0d の画面で「壊れたら Claude に直させる」をオンにすると、`Stop` フックで録り終わりを上限つき（例 90 秒）で
  待ち、壊れていたら理由を返してターンを続けさせる（1 つの頼みごとで 2 回まで）。待つ間は Claude の印が作業中のまま。
- **言いつけ**：仕上がりを盆へ置く前に、そのワークツリーで見どころを回して結果を添える（採る前の材料。§44.4 の 3 の続き）。
  シェルは今どおり渡さない——回すのは Loomo で、許した見どころの行だけ。

閉じる条件：わざとテストを壊す頼みごとをすると、人間が何も言わずに次のターン（または同じターン）で Claude が直しに行く。

## §45.7 製品の完了条件（全段に共通）

各段は以下を満たして閉じる（§43.6 の「テスト → 実データ → 目視 → コミット」を製品の条件に広げたもの）。

1. **導入**：P0d の画面から入れられ、外せる。外したら何も残らない（バックアップは初回だけ）。
2. **失敗の仕方**：Loomo が落ちている・古い版・外の claude・常駐の古いシェル・Loomo が 2 つ、のどれでも claude が止まらず、
   読める一言を返す。この 5 通りをテストに持つ。
3. **安全**：MCP は今どおり 127.0.0.1・Bearer・`Origin` 拒否。読む道具は既定と上限を守り、呼ばれたことが人間に見える。
   面・見どころと同じく、Claude が自分の許しを書けない（許しの置き場は Claude が書く場所の外）。
4. **性能**：プロンプト送信に足す遅延 p95 < 50ms（添えるものが無いとき）・読む道具 p95 < 200ms（スクショを除く）・
   UI スレッドで待たない・打鍵ごとの経路にディスク書き込みを置かない（§31.15）。数字は計測の記録を設計書に残す。
5. **見た目**：`ui-usability` の手順——台本の合意 → 決まり → `Test-XamlChanges.ps1` → ViewHarness（全テーマ × 16/22/28px） →
   `LoomoUi.psm1` で台本どおりに実操作（マウスだけ・キーボードだけ）。報告は「確かめたこと／見てほしいこと」。
6. **測る・刈る**：記録点を `ProvenanceUsageLog` に足し、2 週間後に測り直す。使われなければ外す（2026-11 の機能整理と同じ物差し）。
   測るのは**両方の PC**で（§44.1）。
7. **文書**：この章の「入ったもの」・AGENTS.md の線・README の表。

## §45.8 先に決めること（人間の答えが要る）

1. **指摘を送る経路**：(a) 入力待ちなら貼る（Enter は人間）＋busy なら次に添える（**推し**）／(b) 常に次の頼みごとに添えるだけ
   （見えるターミナルに一切触らない）。
2. **読む道具の範囲と既定**：§45.5 の表の既定（ブラウザは localhost だけ・ターミナルはオフ）でよいか。AGENTS.md の線を「置く・読む」に
   書き換えてよいか。
3. **「壊れたら直させる」**（`Stop` で続けさせる）を作るか。作るなら既定オフでよいか。
4. **MCP の登録**：P0d から Loomo が `claude mcp add` を裏で回してよいか（いまは「コマンドをコピー」で、Loomo はユーザーの設定を黙って
   書かない）。押したときだけ回すなら「黙って」ではない、という読みでよいか。
