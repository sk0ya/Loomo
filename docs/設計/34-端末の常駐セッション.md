# §34 端末の常駐セッション（tmux 相当の切り離しと再接続）

> 作成日: 2026-10-08 / 状態: **実装済み**（実機で「強制終了→再起動で同じ pwsh・同じ画面へ戻る」「タブを閉じたらシェルも終わる」を確認）
> 対象リポジトリ: `C:\Projects\Loomo` ＋ `C:\Projects\Terminal`
> 関連する正本: 復元の物差しは §24（部屋の復元）、子プロセスの I/O 規約は §31.16（ChildProcessIo）、
> 別プロセスの前例は §31.13（入力の先読み＝`Completion.Host`）。

## §34.1 目的

Loomo を閉じても、落ちても、**ターミナルのシェルは生きたまま残り**、次に開いたとき**同じ画面（スクロールバック・
カーソル・実行中のコマンド・vim などの代替画面）に戻る**。tmux の `detach` / `attach` と同じ体験を、部屋の
復元（§24）の一部として持つ。

着手前の実態：ターミナルは**一切永続化していなかった**（`RestoreTerminalTabs` の注記どおり、初回はワークスペースの
ルートに素のタブを1枚立てるだけ）。ワークスペース切替をまたいで生きていたのは、`TerminalWorkspaceTabs` が生きた
`TerminalTabView` をメモリ上で抱えていたからで、プロセスが終われば全部消えていた。

## §34.2 なぜ別プロセスか

ConPTY（`HPCON`）とその配下の conhost／シェルは、作ったプロセスがパイプとハンドルを握っている。さらに
`ConPtyProcessLauncher` はシェルを kill-on-close のジョブに入れる。Loomo の中で作る限り、Loomo の終了が
シェルの終了になる。だから tmux と同じく **PTY を持つ側（サーバー）と映す側（クライアント）を分ける**。

```
[Loomo]  RemotePtySession ──名前付きパイプ（セッションごとに1本）── [sk0ya.Loomo.Pty.Host]
                                                                       ├ ConPtySession ── pwsh
                                                                       └ HeadlessTerminal（画面モデル）
```

`Completion.Host`（§31.13）と形は同じだが**寿命の向きが逆**：あちらは Job Object で Loomo と一緒に死ぬように
してあり、こちらは **Loomo より長生きさせる**のが目的。

## §34.3 画面の復元は「ホストが画面モデルを持つ」（tmux 方式）

プロセスを生かすだけでは、再接続したクライアントの画面は真っ白になる。選択肢は2つあった。

| 方式 | 中身 | 判定 |
|------|------|------|
| 生出力の再生 | ホストが出力のリングバッファを持ち、再接続時に流し直す | **不採用**。途中のリサイズ・代替画面・頭を切ったときの絶対位置指定（ConPTY は `CUP` を多用する）で崩れる。上限を設けると壊れ方が読めない |
| 画面モデルの直列化 | ホストも同じエミュレータ（`AnsiTerminalBuffer`）を回し、再接続時に「今の状態」を VT 列に組み直して送る | **採用**。tmux と同じ。出力量に関係なく大きさはスクロールバック上限で決まる |

直列化した VT 列はクライアントから見ればただの出力なので、クライアント側は**新しいバッファに流し込むだけ**でよい。
VT は普遍の形式なので、ホストとクライアントの Terminal ライブラリの版が違っても（Loomo を更新したのに古い
ホストがセッションを抱えている、という状況は普通に起きる）壊れない。

### §34.3.1 直列化するもの（`TerminalVtSnapshotWriter`、Terminal ライブラリ）

- **行**：スクロールバック → 画面の順に、セル単位で SGR を差分出力。折り返された行（`IsWrapped`）は改行せず
  端まで書いて自動折り返しに任せる（クライアント側でも折り返し行として扱われ、リフローが効く）。末尾の
  既定色の空白は省く。全角の継続セルは飛ばす。OSC 8 のハイパーリンクは張り直す。
- **色**：バッファは SGR を書き込み時に RGB へ解決して持つ。ホストは既定テーマで解決するので、RGB のまま
  送るとクライアントのテーマ色にならない。**ホストのパレットと一致する RGB は索引（30–37/90–97/38;5;n）へ
  戻して送る**。それ以外は 38;2 の真色。
- **カーソルと状態**：カーソル位置・形・表示・点滅、現在の SGR、スクロール領域、モード（DECCKM、DECKPAM、
  DECAWM、DECOM、IRM、ブラケット貼り付け、フォーカス通知、マウス追跡と符号化、代替スクロール、
  modifyOtherKeys、kitty キーボード）、タイトル、cwd（OSC 7）、PSReadLine 履歴パス（OSC 633;P）。
- **代替画面**：主画面（スクロールバック＋退避した主画面）を先に書き、主画面のカーソルを置いてから
  `?1049h` で入り、代替画面を書く。抜けたときに主画面が正しく戻る。
- **シェル統合の印（OSC 133）**：ホストが受けた A/B/C/D を行の印として覚えておき、該当行の頭で出し直す。
  コマンド単位の移動・折りたたみ・スティッキースクロール・「直前の出力をコピー」が復元後も効く。
  ただし **再生中の印はクライアントで「過去の出来事」として扱う**（下の §34.3.2）。
- **持たないもの**：画像（sixel／kitty）、倍幅行、文字集合の G2/G3、kitty キーボードの積み重ね（今の値だけ戻す）。
  失っても画面の意味は崩れない。
- **確かめ方**：「戻したバッファのスナップショット＝元のスナップショット」という不動点（`TerminalVtSnapshotTests`）。
  セル・スタイル・折り返し・カーソル・モードのどれを落としても崩れるので、項目を足したらここに 1 行足す。

### §34.3.2 再生の印（replay ブラケット）

直列化した列には、Terminal ライブラリ専用の OSC で「ここから再生」「ここまで再生」の括弧を付ける。
括弧の中で受けた OSC 133 は、バッファの印（折りたたみ・移動の材料）としては記録するが、**今起きた出来事としては
通知しない**——そうしないと、Loomo の「最近のコマンド」（§24）や袖の活動バッジが、再接続のたびに過去の
コマンドを新規として拾い直す。

## §34.4 境界と役割

| 場所 | 置くもの |
|------|----------|
| Terminal（`Terminal.Controls`） | `TerminalTabView.SessionFactory`（セッション生成の差し替え口）、`HeadlessTerminal`（UI 無しの画面モデル＝公開ファサード）、`TerminalVtSnapshotWriter`、再生の括弧 |
| `Loomo.Core/Terminal/PtyProtocol.cs` | フレーム形式とメッセージ（ホストと本体の約束だけ。UI 依存なし） |
| `Loomo.Pty.Host` | 名前付きパイプのサーバー、セッション表、`ConPtySession`＋`HeadlessTerminal` の組 |
| `Loomo.Services/Terminal/` | `PtyHostClient`（ホストの起動・接続・影コピー）、`RemotePtySession : ITerminalSession` |
| `Loomo.App` | ターミナルタブのスナップショット保存と再接続、閉じる＝殺す／Loomo 終了＝切り離す、ワークスペース削除＝そのセッションを殺す |

## §34.5 プロトコル

- パイプ名：`loomo-pty-v{版}-{ログオンセッションID}-{ユーザー名のハッシュ}`。`PipeOptions.CurrentUserOnly`
  （作成側は現在ユーザーだけに ACL を絞り、接続側はサーバーの所有者が自分であることを確かめる）。
  版を名前に入れるのは、**互換の無いホストとは最初から出会わない**ようにするため。
- 接続1本＝セッション1つ（多重化しない）。最初の1フレームが要求で、`Create`（無ければ作る）か `Attach`
  （あれば繋ぐ）か、`Kill` / `List` / `KillWorkspace` の管理要求。
- フレーム：`[種別 1byte][長さ 4byte LE][本体]`。出力は UTF-16LE（ConPtySession は文字列で渡すので、
  サロゲートの切れ目で壊さないためにそのまま送る）。入力は生バイト。
- 1つのセッションに繋がるクライアントは1つ。後から `Attach` した方が勝ち、前の接続には `Detached` を送って閉じる。

## §34.6 寿命の規約

| 出来事 | セッションは |
|--------|--------------|
| タブを閉じる（`CloseAsync` → `Dispose`） | **殺す**（`RemotePtySession.Dispose` は Kill を送る） |
| 再起動・プロファイル変更でセッションを作り直す | 古い方は殺す（同じく `Dispose`） |
| Loomo の終了・クラッシュ | **生き残る**（パイプが切れるだけ。ホストは切断で殺さない） |
| ワークスペースの削除 | そのワークスペースのセッションを全部殺す |
| シェルが自分で終わる | ホストが表から外し、繋がっていれば `Exited` を送る |
| OS の再起動・ログオフ | 消える（tmux と同じ）。次回は保存した cwd で新しいシェルを立てる |

**`Dispose` を「殺す」側に倒した**のが要点。逆（Dispose＝切り離し）にすると、再起動やプロファイル変更で作り直す
たびに見えないシェルが溜まる。Loomo の終了ではタブを `Dispose` しない（今もしていない）ので、何もしなくても切り離しになる。

**スナップショットに載らなかったセッションも拾う**：保存の前に落ちると、ホストには生きているのにスナップショットに
タブが無いセッションが残る。ワークスペースの復元時、ホストの一覧にそのワークスペースの ID が付いた未知のセッションが
あればタブとして足す（失わない方に倒す）。

## §34.7 ホストの起動と影コピー

ホストを Loomo の `bin` から直接起こすと、常駐するホストが `bin` の DLL を掴み続け、**以後のビルドが全部落ちる**。
だからホスト一式（`ptyhost\`）を `%LOCALAPPDATA%\Loomo\ptyhost\<内容ハッシュ>\` へ写してから、そちらを起こす。
古い版のホストがセッションを抱えたまま新しい Loomo が来ても、パイプ名の版が同じならそのまま古いホストに繋ぐ。
セッションが0になってしばらく誰も繋がなければホストは自分で終わり、次に起きるのは新しい版になる。

起動は `CREATE_BREAKAWAY_FROM_JOB`（Loomo がジョブの中にいても抜ける。拒まれたら付けずに起こす）＋
`CREATE_NO_WINDOW`。ホスト自身は Loomo の Job Object に入れない（入れたら §34.2 の意味が無い）。

## §34.8 ホストの中のスレッド

- `AnsiTerminalBuffer` は WPF の型（`Color`／ブラシのキャッシュ）を使うので、**セッションごとに1本の専用スレッド**で
  画面モデルを触る（出力の取り込み・リサイズ・直列化を全部そこへ並べる）。
- クライアントへの書き出しも専用スレッド＋キュー。遅いクライアントが ConPTY の読み取りを止めない（§31.16）。
- 誰も繋がっていない間の問い合わせ（DSR・DA など）には**ホストの画面モデルが答える**。繋がっている間は
  クライアントが答えるので、ホストは黙る（二重に答えるとシェルに余計な入力が入る）。

## §34.9 設定

設定 → ターミナル「Loomo を閉じてもシェルを残す」（`LoomoSettings.PersistentTerminalSessions`、既定 ON）。
効くのは次に作るタブから。OFF でワークスペースを開くと、そのワークスペースで前に常駐させたシェルは殺す
（どのタブにも戻らないまま見えずに生き続けるのを防ぐ）。ワークスペースを開く前の仮のタブは常駐させない
（持ち主がいないので次回どこにも戻らない）。

## §34.10 踏んだ罠

- **名前付きパイプは両端とも `PipeOptions.Asynchronous`（overlapped）が必須**。同期ハンドルだと Windows は同じ
  ハンドルの I/O を直列にするので、読み取りスレッドが `ReadFile` で待っている間、別スレッドの `WriteFile` も
  止まる。ホスト（受信待ち＋出力の書き出し）と本体（出力の受信待ち＋入力の送信）の両方が同時に詰み、
  E2E テストが無言で固まった。`dotnet-stack` で両端の `ReadFile`／`WriteFile` が並んでいるのを見て判明。
- **ホストを `bin` から起こさない**（§34.7）。常駐するので、掴んだ DLL が以後のビルドを全部落とす。
- **実機検証の SendKeys**：テキストと `{ENTER}` を1回の `SendWait` で送ると、端末ビューの入力プロキシに
  テキストが残っている間に来た Enter が落ちる（生キャプチャ `TERMINAL_RAW_CAPTURE` で `` が出ていないのを確認。
  セッションの種類に関係ないビュー側の挙動）。Enter は別の `SendWait` で、少し間を空けて送る。

## §34.11 既知の限界

- 画像は戻らない。倍幅行は単幅になる。
- 同じセッションを2つのクライアントで同時に映すことはしない（後勝ち）。
- 切り離しウィンドウ（§24 の Terminal のスピンオフ）は今のところ常駐しない（切り離し自体が非永続のため）。
