## 推す

### 1. 差分のファイルに「見た」印を付け、見たあとに変わったら外す（元：GitLens v19.6.0・2026-11-10）
- 出典：https://github.com/gitkraken/vscode-gitlens/releases/tag/v19.6.0
- 元の機能：Commit Graph の Review Changes を、1 回 AI に書かせて終わりではなく「通して読む作業」にした。変更したファイルの一覧で
  どれを見たかを覚え、見たあとに変わったファイルは未読に戻す。差分エディタには「まだ見ていない次のファイルへ」の送りがある。
  amend・rebase しても、見た印と指摘は書き換え後のコミットへ付いていく。
- Loomo でやると：Diff ペインのファイル一覧（作業ツリー・比較基準 §24.11・コミット範囲のどれでも）の各行に「見た」チェックを置く。
  見たときのそのファイルのパッチのハッシュを覚えておき、パッチが変わったら印を外して「見たあとに変わった」の印にする。
  キー 1 つで「次の未読のファイルへ」移り、§24.50 の通し表示では見たファイルを畳む。覚える単位は（リポジトリ・比較の種類と対象・パス）→
  パッチのハッシュとし、ワークスペースごとに残す。パッチの中身で照合するので、amend・rebase してコミットが変わっても、中身が同じなら印は付いたまま。
  - 離れて戻ったときの復元：大きな変更を途中まで読んで席を立っても、戻ればどこまで読んだかが一覧に残っている。
  - 周辺視野：Claude Code が後ろで書き換えたファイルだけが未読に戻って浮かぶので、もう一度読むべきところが分かる。
    Claude Code がまとめて書き換えたものを読む、という Loomo でいちばん多い読み方にそのまま効く。
- いまの Loomo：**未実装**。`DiffFileItem`（`src/Loomo.App/ViewModels/Diff/DiffSessionModels.cs:83`）が持つのは
  リポジトリ・パス・バッジ・増減・ステージの段階・比較の出所だけで、見たかどうかは持たない。一覧のノード `DiffFileTreeNode`
  （`src/Loomo.App/ViewModels/Diff/DiffFileTreeNode.cs:15`）も、開閉と選択の状態しか持たない。
- 作業の置き場：Loomo のみ。
- 規模：M（パッチのハッシュの取り方（行単位の差分のキャッシュ §24.50 に相乗りする）、一覧の行のチェックと印、次の未読へ移るコマンド、
  通し表示で畳む処理、ワークスペースごとに残す処理、更新のたびに照合し直す処理）。
- 関連：§24.50、§24.11、§24.16、§24.4

### 2. ターミナルのタブを切り替えずに、画面の末尾を覗いて 1 行送る（元：zellij v0.46.0 の Session Previews・2026-11-11）
- 出典：https://zellij.dev/news/terminal-inbox-session-previews/ 、https://github.com/zellij-org/zellij/releases/tag/v0.46.0
- 元の機能：セッションマネージャーと Attention Inbox（OSC 7501 で「あなたが要る」ペインを並べる）の行から、ほかのセッション・ペインの
  画面をプレビューで覗ける。切り替えずに、そこへ短いコマンドを打ち込める。
- Loomo でやると：動いているもの面（§24.54）と TABS のターミナルの行（§24.53）にカーソルを載せると（または → キーで）、そのタブの画面の末尾
  十数行をポップアップに出し、下に 1 行の入力欄を置く。Enter で確定した文字列だけをそのタブへ送り、いま前に出ているペインもフォーカスも動かさない。
  「あなたの番」の行（承認待ち・入力待ちの Claude Code）に答えたり、別のタブで流しているビルドの最後の数行を確かめたりするのに、
  ペインを行き来しなくて済む。周辺視野が「見える」から「その場で片付けられる」まで広がる。
  ステージモードの袖のミニチュアは縮んでいて文字は読めないし、タイル配置では出ていないタブは見えないので、それを補う。
  §24.54 と同じく、押し間違いで頼みごとを捨てないよう Ctrl+C などの制御キーは送らず、送るのは入力欄で確定した文字列だけにする。
  AGENTS.md にある「前面が忙しいタブへ打ち込まない」はエージェントが打つ場合の規則で、人が自分で送るこの操作には当たらない。
- いまの Loomo：**部分的にある**。行に出るのは 1 行の要約と文字列のツールチップだけで（`src/Loomo.App/Views/Activity/RunningView.xaml:51`、
  要約は `src/Loomo.App/Services/Workspace/TerminalTabSummary.cs:11`）、押すとそのタブへ移る（`ActivateCommand`）。
  材料は揃っている：
  - 常駐ホストは、生きているセッションの画面を文字にして答える口を既に持っている（§24.67 の横断検索、`src/Loomo.Pty.Host/HostSession.cs:179` の `Search`。
    中で `CreatePlainTextSnapshot()` を呼んでいる）。
  - タブへ文字列を送る口もある（`TerminalTabView.SendTerminalInput`。ペグボードからターミナルへ送る処理が使っている、
    `src/Loomo.App/Views/Shell/Pegboard/ShellWindow.Pegboard.cs:34`）。
- 作業の置き場：Loomo のみ（Pty.Host のパイプの約束に「いまの画面の末尾 N 行」を頼むメッセージを足す。§24.67 の `Search` の隣に置く）。
  Terminal パッケージの改修も NuGet 公開も要らない。
- 規模：M（ホストのメッセージ 1 つ、ポップアップの View、送る処理、要約の行からの入口 2 か所、Claude Code の承認待ちに送るときの扱い）。
- 関連：§24.54、§24.53、§24.61、§24.67、§34

| 1. 差分のファイルに「見た」印 | §24.107 | `DiffViewedMarksTests`：指紋がコミットのハッシュと行番号に左右されない／状態の決まり方／見方の分かれ方／次の未読／見出しの数／置き場の往復と上限。実物のリポジトリでは、見た→書き換えると「変わった」→付け直し→別の VM でも見たまま、を確かめた。入口は行の右端の ✓／●／○・右クリック・見出しの「次の未読」・Alt+V。通しの表示では、見たファイルを見出しだけにする |
| 2. タブを切り替えずに覗いて 1 行送る | §24.108 | `TerminalPeekTests`：末尾の切り方／行の鍵からタブを引く／文字列と Enter を分けて送る／取れないときの説明。実物のホストと cmd では、繋いだままのセッションの末尾が返り、無いセッションでは null になることを確かめた。入口は動いているもの面の行の「覗く」・右クリック、TABS のターミナル行の右クリック。画面は常駐ホストの新しい約束 `Tail` で取る。**いま動いている常駐ホストは古いので、Loomo をすべて閉じて開き直すまでは「画面を取れませんでした」と出る** |
