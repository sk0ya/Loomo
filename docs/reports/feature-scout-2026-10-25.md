## 推す（効き目の大きい順）

### 1. コミットから変更を外して作業ツリーへ戻す（元：GitButler 0.20.1・2026-06-19）
- 出典：https://github.com/gitbutlerapp/gitbutler/releases （release/0.20.1「Uncommit changes」をコミット済みハンクの右クリックに追加。
  0.21.1・2026-07-21 で複数コミットにまたがって外せるようになった）
- 元の機能：コミット済みの差分（ファイル／ハンク）を選んで「コミットから外す」と、そのコミットからその変更だけが抜け、変更は作業ツリーに戻る。
- Loomo でやると：Git ペインのコミット詳細の変更ファイル一覧と、Diff ペインでコミットを見ているときの右クリックに「このコミットから外す（作業ツリーへ戻す）」。
  HEAD なら `git restore --source=HEAD~ --staged <path>` → `commit --amend --no-edit`、過去のコミットなら既存の fixup の経路（一時コミット＋autosquash・
  未ステージの退避と復元）を逆向きに使う——打ち消しのパッチを fixup として当て、外した内容は作業ツリーへ戻す。
  「コミットを分けたい」「混ぜてしまった 1 ファイルを次のコミットへ回したい」が、interactive rebase の edit を手で打たずに済む。履歴が書き換わるので
  §24.14 の「履歴を書き換える」の下に置く。
- いまの Loomo：部分的にある。逆向き（作業ツリーの変更を過去のコミットへ足す）は実装済み（`src/Loomo.App/ViewModels/Git/GitPanelViewModel.cs:1114`、
  `Loomo.Services/Git/GitRebaseService.cs:28`）。コミットから外す口は Git の右クリックのどこにも無い（`Views/Git` の XAML の Header を全部確認）。
- 作業の置き場：Loomo のみ
- 規模：M（HEAD と過去コミットの 2 経路・ファイル単位から。ハンク単位は Diff ペインの行選択（§24.18）を足場に後から）
- 関連：§24.14・§24.18・§24.38

### 2. 部屋のタブを最近使った順に巡る（元：Zed 1.25.2・2026-10-21／Tabby v1.0.236・2026-09-23）
- 出典：https://github.com/zed-industries/zed/releases （v1.25.2「`tab_switcher.show_file_preview`」——タブスイッチャーで巡っている間、選んでいるタブの中身を見せる）、
  https://github.com/Eugeny/tabby/releases （v1.0.236「basic MRU tab switching」）
- 元の機能：Ctrl を押したまま Tab で、最近使った順にタブを巡り、離したところで確定。巡っている間はそのタブの中身が見える。
- Loomo でやると：エディタ・ターミナル・ブラウザの**タブを区別せず**最近触った順に並べた一覧を Ctrl+Tab で出し、押している間は対象のペインにそのタブを仮に出す
  （離したら確定・Esc で元へ）。部屋の中の「さっきの場所」へ戻る一番短い動線になる。§24.58 の「直前のペイン」はペイン単位、§24.44 は閉じたときだけ、
  `nav.recentFiles` はファイルだけなので、「さっき見ていたターミナルのタブ」「調べていたブラウザのタブ」へはキー 1 つで戻れない。並びの材料は軌跡（§27）が
  既にタブの活性化を記録している。
- いまの Loomo：部分的にある。最近のファイル（`src/Loomo.App/Views/Shell/Navigation/ShellWindow.LocationHistory.cs:117`）はプレビュー付きのパレットだが、
  中身は `RecentFiles` のファイルだけ。Ctrl+Tab の割り当ては Loomo にも Editor／Terminal パッケージにも無い（`Key.Tab` を Ctrl 付きで扱う箇所なし）。
- 作業の置き場：Loomo のみ（ターミナルが Ctrl+Tab を端末へ送る前に取る必要があるので、ペイン横断キーの扱い（`ShellWindow.PaneNavigation.cs`）に足す）
- 規模：M（タブ活性化の MRU を 3 種まとめて持つ・押している間の仮表示と確定／取り消し）
- 関連：§24.2.1・§24.44・§24.58・§27

### 3. ターミナルのタブに色を付ける（元：Fork 2.68（Mac）・2026-06-19／Tabby v1.0.237・2026-09-25）
- 出典：https://fork.dev/releasenotes （2.68「タブの右クリックに名前の変更・色の選択」）、https://github.com/Eugeny/tabby/releases （v1.0.237「custom labels for individual split panes」）
- 元の機能：タブに色を付けて、どれが何かを文字を読まずに見分ける。Tabby は分割した面ごとにも名前を付けられる。
- Loomo でやると：TABS とターミナルペインの見出しのターミナル行に、右クリックの「色」で帯を付ける（名前（§24.53 の `CustomName`）と並べて
  `WorkspaceSnapshot.TerminalTabs` に保存し、常駐セッション（§34）の付け直しでも残す）。「本番につないでいるタブ」「Claude Code を回しているタブ」
  「ビルドを見張るタブ」を周辺視野で分ける。袖のミニチュアや動いているもの面（§24.54）の行にも同じ色を出せば、どこで見ても同じ印になる。
- いまの Loomo：未実装。名前は付けられる（`TabsViewModel.RenameTerminalTab`）が、タブの行に色の持ち物が無い。分割面の名前も無い。
- 作業の置き場：Loomo のみ（タブの色）。分割面の名前まで付けるなら Terminal（分割の見出しにラベルを描く口。NuGet 公開が要る）
- 規模：S（タブの色）／分割面の名前は M
- 関連：§24.53・§24.54・§34

### 4. プルの前に、上流とのずれと衝突の予告を出す（元：GitButler 0.20.1・2026-06-19）
- 出典：https://github.com/gitbutlerapp/gitbutler/releases （release/0.20.1「Upstream integration was redesigned」——ブランチ一覧の更新ボタンから、
  リモートとどう分かれたかを見せ、取り込み方を選ばせ、結果を先に見せる）
- 元の機能：プルする前に「向こうに N 件・こちらに M 件」と、マージ／リベースしたらどうなるかを見せてから取り込む。
- Loomo でやると：Git パネルのプルを押したとき、上流と分かれていれば（ahead と behind が両方 1 以上）、受け取るコミットの一覧・こちらだけのコミット数・
  `merge-tree` での衝突の予告（§24.40 と同じ判定を「分岐元」ではなく上流に向ける）を出し、そこでマージ／リベースを選ぶ。分かれていなければ今まで通り
  黙って fast-forward。戻ってきて「留守中に向こうが進んでいた」ときの取り込みを、壊す前に読めるようにする。
- いまの Loomo：部分的にある。ahead／behind は読んでいて（`src/Loomo.Services/Git/GitBranchService.cs:374`）、プルの方式は選べる（§24.13）。衝突の予告は
  分岐元（既定のブランチ）だけが相手で（§24.40）、上流は相手にしていない。
- 作業の置き場：Loomo のみ
- 規模：S〜M（判定は §24.40 の `GitMergeTreeParser` をそのまま使える。足すのはプルの前の確認面）
- 関連：§24.13・§24.40
